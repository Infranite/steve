# ST-41 厘清事项记录、会话记录、知识与长期记忆

## 1. 四类内容

| 类型 | 回答什么 | 放在哪里 | 怎么产生 |
|---|---|---|---|
| 事项记录 | 要改什么、做到哪、交付了什么、怎么验收 | 事项详情与执行记录；知识库来源「事项记录」 | 事项完成时整篇入库，不经确认 |
| 会话记录 | 某天和 Steve 聊了什么、做了哪些决定 | 主线对话；知识库来源「会话记录」（按天） | 每小时整篇入库，不经确认 |
| 知识条目 | 系统、环境、某人或某类问题**以后还用得上**的确认过的事实与做法 | 知识 → 知识条目（`mems.kind = fact / event`） | 抽取后进「待确认」，你保存才生效 |
| 长期记忆 | 你**明确说过以后都适用**的偏好与规则 | 知识 → 长期记忆（`mems.kind = preference / rule`） | 抽取后进「待确认」，你保存才生效 |

事项记录和会话记录已经可以检索，不再「换个说法」提成知识或记忆。会话记录目前就是当天对话原文，没有另外生成摘要。

## 2. 改了什么

**抽取（`hub-rs/crates/steve-knowledge/src/extract.rs`）**

- 提示词先让模型把原文分成四类，只输出长期记忆和知识条目，并说明「没有就返回空列表，这是常见结果」。每次最多从 5 条降到 3 条。
- 每条必须带 `evidence`（逐字原文）、`basis`、`scope`（适用范围）、`why`（为什么值得长期保留）。
- 服务端兜底规则（`check`），模型说什么都要过一遍：
  1. **原话必须在原文里**（忽略标点空格，允许「…」截断），编造或缺失就丢。
  2. **偏好和规则必须有长期依据**：原话里有「以后、后续、每次、总是、一律、这类、不要再、之前说过……」（`LASTING`），或者 `basis = repeated` 且原文里有两处不同原话。单次的「这里改成那样」「得支持 X」一律丢。
  3. **复述事项目标就丢**：候选文字大部分来自目标，或引用的原话全在目标里（除非原话本身就说了长期适用）。
  4. **和已有的近似就丢**：比较对象包括已确认的和**还在待确认的**（以前只看已确认的，所以同一批里出现了三条「走 GitHub 发布」）。
  5. 事项和对话不再抽「事件」，只有邮件和渠道群会抽。
- 事项抽取输入里，目标标明「属于事项记录」；YOLO 自动发回的返工意见不再当成「你说的验收意见」（ST-33 里「自动验收必须实际运行检查」就是这么来的）。
- `steve_remember` 工具说明同样写清：只存以后还适用的规则、偏好和确认过的知识，不存这件事的要求、进度和结果。

**确认卡与界面**

- 待处理卡片的问题从「记住这条吗？」改成「存为长期记忆吗？」或「存为知识条目吗？」，下面依次是类型、为什么值得保留、适用范围、来源、原话；按钮改为「不保存 / 保存」。旧卡片照常显示。
- 知识页把「记忆」拆成「长期记忆」「知识条目」两个标签页，在哪个页添加就存成哪一类（规则 / 事实）；「待确认」每条带类型和保留理由。
- 检索引用的标签改为「事项记录 · …」「会话记录 · …」「长期记忆 · …」「知识条目 · …」，已有索引在第一次清扫时就地改名（`sync::relabel_once`，标签不参与搜索）。

## 4. 历史误抽取的整理方案

按第 2 节的规则逐条复查已确认的长期记忆：

1. **保留**：原话里明确说了长期适用的（「每次」「之前说过」……）。
2. **合并**：同一条规则从多个事项各抽了一次的，保留表述最完整的一条并改写成合并版，其余删除。
3. **删除**：复述事项目标或功能需求的、把单次反馈泛化成偏好的、来自 YOLO 自动返工而不是你说的话的。这些内容都还在对应的事项记录和会话记录里，能搜到。

执行方式：在「知识 → 长期记忆」逐条删除或改措辞，或调 `DELETE /api/mems/:id`、`PATCH /api/mems/:id {text}`。这是改线上数据，需要你确认后再做。逐条清单（含线上 id）放在本机工作目录 `.steve/ST-41-历史条目整理方案.md`，不进仓库。

目前没有「对历史来源重新抽取」的入口（事项只在完成时抽，对话只在次日 03:40 抽前一天）。新规则下值得补的条目可以手动添加，或另开事项加一个手动重抽入口。
