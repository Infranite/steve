# ST-23 对话页视觉优化

方案：沿用现有中性配色和系统字体，让消息成为视觉中心。使用固定高度的紧凑顶栏，统一正文与输入框的阅读宽度，收敛过程信息，保留 Steve 无底色正文、用户浅灰气泡。

本机可用的两张对话截图呈现出引用、交付、过程和正文挤在同一层级的问题；原需求 11:38 的图片未能直接读取。实施依据为可用截图、当前代码和实际页面渲染。

| 区域 | 调整 | 理由 |
| --- | --- | --- |
| 顶栏 | 64px 固定高度，头像、姓名、状态横排 | 减少空白，避免滚动触发高度跳变 |
| 消息 | 统一 800px 阅读栏，日期细线分组，Steve 名称和时间作为轻量标识 | 区分每轮回复，长内容有稳定阅读起点 |
| 思考 | 次要文字、紧凑触发区，展开后保留过程详情 | 保留可追溯性，降低对正文的干扰 |
| 输入 | 单独留白区、轻微层次、与正文对齐 | 明确下一步操作位置 |
| 操作 | 悬停、键盘聚焦和触屏均可见 | 避免键盘焦点落在透明按钮上 |

消息操作浮在每轮回复下方的留白中，不再占据额外空白行；对话页显式使用主题前景色，避免深色首次渲染时继承到过渡中的黑色文字。

```mermaid
flowchart LR
  A[左侧全局导航] --- B[固定对话顶栏]
  B --- C[日期分组 · 消息阅读栏]
  C --- D[草稿与输入区]
  B --- E[右侧通知与摘要 / 窄屏抽屉]
```

边界：不调整后端、回复生成速度、审批逻辑或全局主题；保持引用、附件、会话切换、草稿、停止生成等既有功能。仅主对话页使用新排版，渠道只读对话沿用相同阅读框架。

验收：类型检查、现有测试和生产构建；实际 ChatView 浏览器 fixture 覆盖浅深色、1440/390px、短对话、长 Markdown、思考展开、键盘操作、草稿引用、输入和侧栏边界。截图自查首尾内容完整、无横向溢出，滚动时顶栏和输入区不跳动。发布另行处理。
