# ST-50 主线对话页与消息历史导航

结论：对话页只呈现一条与 Steve 持续沟通的主线。session 留在底层，不再要求用户切换。顶栏收成一行，只放身份、Steve 当前的回复状态、「历史」和「事项」两个入口。找旧消息走「历史」面板：可以搜索，也可以按话题翻找；点开后跳到原文并高亮，同时给出「返回刚才位置」和「回到最新」。执行进度只显示在一处，同一次执行只用一个计时起点。

## 参考依据

两个项目都只看了公开源码和仓库里的截图，没有安装或运行：

- Cindy：[makecindy/cindy](https://github.com/makecindy/cindy)，开源、开箱即用的 AI Agent，有桌面端和手机端。
- Persona：[Code-MonkeyZhang/persona-agent](https://github.com/Code-MonkeyZhang/persona-agent)，Electron 个人 Agent，每个角色有一条常驻聊天。

用户只给了“cindy、persona”这两个名字，上面两个仓库是按名字和同类产品选定的，属于假设。如果指的是别的项目，下面的取舍需要重新核对。

| 主题 | Cindy 的做法 | Persona 的做法 | Steve 的取舍 |
| --- | --- | --- | --- |
| 会话模型 | 多条独立对话，有「新建任务」、自动标题和置顶，侧栏按项目和最近排列 | 每个角色一条固定的「聊天」（`chat-{agentId}`），不能改名，也不能删除；模型上下文在后台压缩成摘要和记忆，界面始终保留完整记录 | **采用 Persona**：主线固定，不提供「新建会话」。上下文压缩继续在底层进行，界面不提示“开了新会话”。Cindy 的会话列表正是我们要弱化的东西，不采用 |
| 顶栏 | 46px 细线顶栏，放标题、标签、菜单和 git 状态 | 65px，只放标题和「语音 / 形象」；运行状态特意移出顶栏 | 52px 单行：头像、名字、Steve 的回复状态，加「历史」「事项」两个入口。原来那一行「你和 Steve / 会话列表」整行去掉 |
| 历史与搜索 | 全局搜索合并标题模糊匹配和正文全文检索（FTS5），结果带片段；对话内有页内查找 | 没有搜索；侧栏是不分组的任务会话列表 | 新增「历史」面板：搜索主线全部消息和事项编号，结果按日期分组，带命中片段；不搜索时按话题列出。话题按 30 分钟间隔切分（参考 Cindy 的 `HISTORY_GAP_SPLIT_MS`） |
| 定位消息 | 搜索命中后，若该消息未加载，先载入前后各 60 条，再居中滚动、高亮约 1.2 秒；没有「返回刚才位置」 | 没有跳转，只有「滚到底部」按钮 | 先补齐目标到当前窗口之间的消息，再居中、高亮 1.6 秒；同时显示「返回刚才位置」和「回到最新」。Cindy 缺「返回」，这里补上 |
| 滚动跟随 | 解除跟随看用户意图（滚轮上滚、触摸下拉），恢复跟随看是否接近底部；未读按回合计数；从 IM 等渠道来的消息不抢位置 | 距底部 100px 内跟随；发送时直接回到底部 | 沿用现有的“意图解除、接近底部恢复”，与 Cindy 一致。新消息按钮显示条数；载入更早消息时保持阅读锚点不跳 |
| 草稿与阅读位置 | 每个对话一份草稿，只存在内存；滚动位置记“顶部可见条目 + 偏移”，也只在内存 | 草稿不保存；滚动位置在内存里按会话缓存 | 草稿沿用已有的本地存储，刷新后恢复。阅读位置采用 Cindy 的“锚点条目 + 偏移”，但存进本地存储，刷新后仍能恢复 |
| 执行过程 | 整段工作收成一行「正在工作 / 已工作 X」；计时起点只取上一条用户消息；伙伴对话里输入框上方只有一条「正在回复…」 | 消息列表上方一条运行状态条，可展开时间线；不显示计时 | 主线：运行中只保留输入框上方或消息末尾的一条进度，完成后收进「思考」。事项页：同一轮执行只在一个位置展开，所有计时共用起点和时钟 |
| 后台事项 | 任务卡片内嵌在消息里，详情放右栏 | 后台通知不显示，只显示回复 | 相关事项在对应消息下用一张卡片跟进；全部在办事项从顶栏「事项」进入右栏 |

## 页面设计

原型：`docs/ST-50/prototype.html`，是静态示意，不连 Hub。用 `?v=desktop` 打开桌面历史面板，`desktop-latest` 是桌面常态，`mobile` 是手机常态，`mobile-history` 是手机历史抽屉。

```text
桌面
┌ 导航 ┬──────────────────────────────────────────┬──── 历史（340px）────┐
│      │ (St) Steve · 正在回复          历史  事项 8• │ ⌕ 搜索消息或事项编号    │
│      │ ─────────────── 11月4日 ───────────────    │ 今天                  │
│      │                        你的消息 ▢          │  你：……       01:18   │
│      │ Steve 01:30  ← 跳转后高亮                  │ 11月4日               │
│      │ 回复正文 / 事项卡                          │  Steve：……    01:30   │
│      │           [↩ 返回刚才位置 | 回到最新 ↓]     │ 话题（未搜索时）        │
│      │ ● 正在查 · 读取 …                0:42      │ 群聊和私聊 ›           │
│      │ ╭ 和 Steve 说… ╮                           │ 加载更早 ›             │
└──────┴──────────────────────────────────────────┴───────────────────────┘
手机：顶栏 48px；「历史」从右侧抽屉打开，占 88% 宽；「事项」打开同侧抽屉。
```

| 区域 | 设计 |
| --- | --- |
| 顶栏 | 头像 28px、名字，后面只跟 Steve 自己的状态（空闲 / 正在想 / 正在查 / 正在回复）。「在跟 8 件事」改成「事项」入口上的数字；有事等你时加一个橙点，避免被理解成“正在执行 8 件事”。原来的“你和 Steve / 会话列表”整行删掉 |
| 主消息流 | 主线 = 本地已加载的更早消息 + Hub 返回的最近 200 条，按日期分隔。滚到顶部自动载入更早的 100 条，阅读位置不跳 |
| 历史面板 | 桌面在右侧，和「事项」右栏互斥；手机用右侧抽屉。上方是搜索框；不搜索时按日期列出话题，标题取话题第一句话，下面写条数和涉及的事项编号。底部有「加载更早」和「群聊和私聊」（原会话列表，仍可管理关闭和恢复） |
| 定位与返回 | 点击搜索结果或话题，记下当前位置（或“在最新处”），补齐消息后跳到原文并高亮。浮条显示「返回刚才位置」「回到最新」，回到底部后浮条自动消失。引用头和「看最新进展」也走同一套跳转 |
| 输入 | 翻看历史只改变阅读位置。输入框照常给 Steve 发新消息；要接着某句话说，就引用它，输入框上方会显示引用对象 |
| 事项进展 | 在对应消息下显示事项卡片和回流结果；全部事项在顶栏「事项」→ 右栏（等你 / 进行中 / 最近交付 / 通知） |
| 执行详情 | 主线运行时只显示一行进度，完成后收进「思考」。事项页：某轮执行在回答你的补充时，只在那条补充下展开；会话块里改为一行提示「进度显示在那条补充下面」。所有计时共用一个每秒时钟；片段计时从触发它的那条消息算起，与整段会话一致 |
| 边缘滚动 | 消息列表关闭横向滚动和越界回弹，左右滑动不再露出白边 |

不做的：话题由 Steve 命名（需要模型调用，留待以后）；Cindy 的左侧“提问刻度条”（主线很长时刻度过密）；Persona 的“形象 / 语音”模式。

## 后端

- `GET /api/thread/history?before=<ms>[&after=<ms>][&limit=n]`：返回 `before` 之前的主线消息，从旧到新；不带 `after` 时用于往前翻页，带 `after` 时把消息一直补到某条搜索结果。过滤规则与 `/api/state` 的 thread 一致，不返回隐藏的回流消息和已关闭的失败提示。`has_more` 表示是否还能继续往前翻。
- `GET /api/thread/search?q=…`：在正文里查找包含 `q` 的消息，或属于事项 `q` 的消息，从新到旧，默认 50 条。英文不区分大小写；`%`、`_` 按字面匹配。
- 只改了 Rust Hub。TS Hub 没有这两个接口，前端在接口失败时退回到只在已加载消息里搜索。

## 验收方案

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A1 | 搜索并定位 | 搜索框输入词，结果按日期分组并标出命中；点击后跳到原文、居中并高亮，前后上下文都在 |
| A2 | 定位较早的消息 | 目标不在最近 200 条里时，先补齐中间的消息再定位，不出现断档 |
| A3 | 返回 | 跳转前停在中间：「返回刚才位置」回到原来的锚点，误差小于 4px。跳转前在底部：只显示「回到最新」，点击后回到底部 |
| A4 | 翻历史时有新消息 | 不抢阅读位置；显示「N 条新消息 ↓」，点击后回到底部 |
| A5 | 在底部时有新消息 | 自动跟随；Markdown 渲染后变高也保持在底部 |
| A6 | 载入更早消息 | 滚到顶部载入后，原来看到的那条消息位置不变 |
| A7 | 刷新恢复 | 停在中间时刷新，回到同一条消息附近；停在底部时刷新，仍在底部；草稿保留 |
| A8 | 顶栏 | 只有一行；只有一个状态，不出现「在跟 N 件事」；「事项」显示数字；没有“你和 Steve / 会话列表” |
| A9 | 群聊和私聊 | 从历史面板进入原会话列表，打开、关闭、恢复照常；在 IM 对话中，顶栏显示「← 主线」 |
| A10 | 执行状态唯一 | 事项页：一轮执行在回答补充时，正在运行的进度只出现一次 |
| A11 | 计时一致 | 同一轮执行的片段视图和整段视图起点相同；多个计时在同一时刻跳秒 |
| A12 | 布局 | 1440 / 390px × 浅色 / 深色无横向溢出，顶栏高度在滚动时不变 |

自动化：`web/test/chat-history.browser.mjs` 覆盖 A1–A9、A12（模拟 API）；`web/test/chat-layout.browser.mjs` 继续覆盖跟随、草稿、深浅色；`hub-rs/crates/steve-hub/tests/thread_history_api.rs` 覆盖接口的分页、补齐、搜索和隐藏消息过滤。A10–A11 与同期合入 main 的 ST-48 重合，以它的实现和 `web/test/run-progress.browser.mjs` 为准；本项只补了页面上所有计时共用一个时钟。

## 验收记录

- `web/test/chat-history.browser.mjs`：用实际 ChatView 和模拟 API，在 1440 / 390px、深色 / 浅色下全部通过。覆盖 A1–A9 和 A12：单行顶栏；翻历史时新消息不移动正文，并显示「1 条新消息」；搜索结果高亮，跳到窗口外第 50 条时补齐中间消息、目标居中并闪烁；返回刚才位置误差不超过 4px；从底部跳出后只显示「回到最新」；载入更早消息时锚点不动；刷新后恢复阅读位置和草稿；在底部时刷新仍在底部；可从历史打开群聊和私聊；没有横向溢出。
- A10、A11：rebase 到 main 时发现 ST-48 已用同样思路修好（评论触发的回合只在评论下显示，片段从提示时间计时），合并时采用 ST-48 的实现；`run-progress.browser.mjs` 与 `item-feed.browser.mjs` 通过。用改动前的代码复现过同一场景：2 处进度，计时 6:00 和 5:00。
- `web/test/chat-topics.test.mjs`：话题切分、命中片段和阅读位置存取的单元测试通过。
- `hub-rs/crates/steve-hub/tests/thread_history_api.rs`：260 条消息下的分页、补齐、`has_more`、隐藏消息过滤、事项编号搜索、`%` 按字面匹配、空查询返回 400，均通过。
- 实机冒烟：在独立临时目录启动 Rust Hub（端口 8473，不连真实 agent），写入 320 条消息，通过 Vite 代理打开真实页面。最近 200 条之外的消息能搜到，点击后补齐到 299 条并高亮定位，浏览器无错误。
- 截图（本地 QA 目录，不入库）：原型 4 张；fixture 的主线、话题、搜索、跳转在两种宽度和两种主题下各一组；实机 4 组。
