# ST-25 对话页里调整 Steve 自己的功能

在主对话里直接说出要改的设置，Steve 会起草成改动卡片，点「应用」后生效，也可以撤销。只问现状时，Steve 直接列出当前值。

## 调研结论

| 现状 | 问题 |
| --- | --- |
| 路由已有 `config` 类，`changes.rs` 能起草 Bot、项目、设置、模型、标签的改动 | 一句话只能落到一个目标；“免打扰改成 22 点，开发 Bot 思考强度调高”只会改其中一处 |
| 各模块（YOLO、定时任务、流程、事件源、知识来源、邮箱、GitHub 仓库、渠道、对外身份、联系人/团队）都注册了草稿目标 | 对话里挑目标时没有加入这些模块的候选（`steve_modules::changes::candidates` 没接入），所以对话里改不了它们 |
| 标签只能新建、改描述；Bot 不能启停；项目不能归档 | 常见的管理动作缺失 |
| 卡片的「应用/放弃」只存在于页面内存 | 刷新后已应用的卡片又显示「应用」，再点会报“草稿已失效”；「放弃」不通知 Hub |
| 回答和只读研究的提示词写着“不能改设置” | 用户问“你能改自己的设置吗”时，Steve 会说做不到 |

## 实现

- **挑目标**：`Core::pick_targets` 一次最多返回 3 个目标，并判断是否只是询问。已知用户时把模块候选一并给模型；联系人只在请求里点名时才列出，避免候选过多。
- **起草**：`Core::config_request` 对每个目标起草。内核目标走原有草稿；模块目标走 `steve_modules::changes::draft`，存为可撤销 24 小时的变更集。没有改动的模块草稿会立即丢弃。
- **回复**：单处改动用 `meta.proposal`（兼容旧消息），多处改动用 `meta.proposals`。只询问时，或没看出要改什么时，列出“现在是：…”。
- **新增可改项**：Bot「启用状态」（主 Bot 除外）；项目「状态」（使用中/已归档）；标签可以改名、改分类、删除。只删除没有被引用的标签；仍在使用的标签不删，并说明原因。撤销时按原名、原分类重建。
- **卡片状态**：应用、撤销、放弃后写回消息的 `meta.cfg_state`。新增 `POST /api/config/:id/drop`，模块变更集和内核草稿都能放弃。已应用的卡片内直接提供「撤销」。
- **提示词**：路由的 `config` 说明覆盖全部可配置面，并补充多处改动、询问现状的例子。回答和研究提示词说明可以在对话里直接修改设置。

## 边界

- 改 Steve 的代码或界面仍是事项，不属于配置。
- 访客会话（IM 群）仍然不能修改配置。
- 内核草稿和撤销记录仍在内存里，Hub 重启后失效；模块变更集持久化。
- 免打扰等设置仍按设置页的可选值修改，不支持任意时间段。
