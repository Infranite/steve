# ST-38 产出浏览、最终交付筛选与批注回复

入口：事项 → 产出 → 点开一项。

## 产出区只放最终交付

- 一次 `steve_deliver` 写下的产出算一次交付（写入时间相差不到 3 秒）。产出区只列**最新一次交付的结果**；那次只交了过程记录时，沿用上一次有结果的交付。
- 其余内容进入下方折叠的“执行记录”，按交付分组，最新的在前：过程记录（自查截图、日志、中间文件）和早先交付的结果都在这里，标“过程记录”“旧版本”或“早先交付”，仍然可以点开查看。
- 同类型、同位置（没有位置时按标题）的产出再次交付时算新版本，显示 v1、v2；在预览里打开旧版本，会标明“不是最新”。
- `steve_deliver` 的产出新增 `role`：`result` 或 `record`，记在新表 `artifact_roles`。工具说明提醒 Agent：只列仍然有效的交付，自查截图、日志和测试报告标为 `record`。
- Agent 没说明角色的产出（包括旧数据），按标题和类型判断：带“自查、自测、调试记录/日志/截图/输出、debug、运行/调试/测试/构建日志、以“日志”或 log 结尾、中间结果/产物/文件/版本、临时、草稿、过程记录、执行记录”的算过程记录。明确的角色优先，所以“中间件设计”“日志分析报告”这类结果不会被误判。数据不删除，只换位置显示。

## 看图

- 同一组里的多张图片（同一次交付里的图片产出，或者同一个文件夹里的图片）可以连着看：
  - 逐张：支持左右滑动（手机）、←/→ 键、两侧按钮和底部缩略图，显示“第几张 / 共几张”；
  - 连续：所有图片上下排开，滚动浏览。
- 文件夹视图有“连续浏览 N 张图片”入口。
- 双击图片或点“放大”可以放大，放大后拖动用来移动图片，不会切换到别的图片。框选区域时也不会误触切换。

## 文档渲染核对

| 格式 | 结果 |
| --- | --- |
| Markdown（含表格、Mermaid、代码） | 渲染，可切换到源码（ST-30 已有） |
| HTML | 放在沙箱 iframe 里渲染，可切换到源码（ST-30 已有） |
| PDF | 用浏览器自带的 PDF 查看器打开；页批注定位到 `#page=n` |
| 纯文本、代码、JSON、CSV/TSV、diff | 高亮、格式化或表格显示（ST-30 已有）；补了 php、lua、r、scala、dart、vue、svelte、graphql、proto、ini、tex 的语言识别 |
| Word `.docx` | **新增**：标题、加粗/斜体/下划线/删除线、列表、表格、超链接、内嵌图片 |
| Excel `.xlsx` | **新增**：多工作表切换、共享字符串、布尔值、日期格式；最多显示前 1000 行、60 列 |
| PowerPoint `.pptx` | **新增**：逐张显示标题、正文层级、表格和图片，按版面从上到下排序 |
| 图片、音视频 | 原地显示（ST-30 已有），图片支持上面的图集浏览 |
| `.doc/.xls/.ppt`、Pages/Numbers/Keynote、OpenDocument | 不能预览，会说明原因，提示下载，或请 Bot 另存为 PDF 或 docx/xlsx/pptx |

Office 文件由 Hub 按 `office` 类型返回原文件，页面里用浏览器自带的 `DecompressionStream` 解压 zip、解析 XML 后渲染，没有引入第三方库。版式、字体和图表不还原，需要原样查看时可以下载。解析失败时会说明原因，下载入口保留。

## 批注

- 图片可以点“框选区域”后拖出一个区域；文档、表格、幻灯片、diff 和源码可以选中文字后点“批注所选”；PDF 可以“批注某页”；任何产出都可以“整体批注”。选中的文字会记下所在行号（源文件里能唯一找到时），以及所在的工作表或第几张幻灯片。
- 批注先存为 Hub 上的草稿（新表 `annotations`），刷新后仍在，可以修改或删除。产出列表会显示“N 条草稿”。
- “确认发送 N 条”会把这个事项的所有草稿合成**一条“我”的补充**，发到所属事项，并送达它的会话。内容按产出分组，写明标题、类型、第几版、位置，以及每条批注所在的地方，例如“图片区域（左 20%，上 20%，宽 40%，高 30%）”“选中文字「…」（第 12 行）”“第 3 页”。
- 防重复发送：每次发送都带一个 key。同一个 key 再次到达（重复点击，或者回应丢失后重试）时不会再发，上一次还在进行时返回 `pending`；被别的发送拿走的草稿也不会被再次发送。前端发送期间按钮不可点。
- 发送在 Hub 的独立任务里完成，浏览器刷新或断网不会打断。补充失败时，事项里没有这条消息就把草稿退回；如果消息已经写进事项、只是没送达会话，就按已发送处理并提示，避免再发一遍。Hub 在发送中途停止时，草稿 5 分钟后可以重新发送。
- 发出后，事项动态里这条回复显示为批注卡片：区域批注带裁切的缩略图，每条都有“定位”。点“定位”会打开当时那个版本的产出，并在原位置显示：区域高亮显示，文字用高亮标出并滚动到可见位置，PDF 跳到对应页。刷新后仍然可以这样定位。

## 接口

- `POST /api/items/{id}/annotations` `{art, path?, anchor, note}`：`anchor` 是 `{type:"region",x,y,w,h}`（图片宽高的比例）、`{type:"text",quote,prefix?,suffix?,line?}`、`{type:"page",page}` 或 `{type:"file"}`，都可以带 `at`。只保留每种类型认识的字段。
- `PATCH|DELETE /api/items/{id}/annotations/{ann}`：只对草稿生效，已发送的返回 409。
- `POST /api/items/{id}/annotations/send` `{ids, key}`：返回 `{again, sent, timeline_id}`。
- `GET /api/items/{id}` 多返回 `artifactRoles` 和 `annotations`。

数据库迁移 033（schema 33）只新建 `artifact_roles` 和 `annotations` 两张表，不改已有表。
