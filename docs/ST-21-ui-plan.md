# ST-21 界面整改方案与验收

## 方案

统一沿用现有 shadcn 组件与视觉规范，不引入新 UI 框架。

```mermaid
flowchart LR
  A[左侧全局导航] --- B[中间正文与输入框]
  B --- C[右侧辅助信息]
```

| 反馈 | 实施 |
| --- | --- |
| 内容和侧栏方向不一致 | 会话详情辅助栏移到右侧，与主对话和事项详情一致；窄屏用会话信息弹窗 |
| 菜单堆叠 | 工作：对话、待处理、事项、项目、会话；资料与沟通：知识、联系人、邮件；自动化：Bot、自动化、信号；个人和系统保留底部 |
| 输入丢失 | 按对话、事项、会话保存草稿；恢复文字与已上传附件；发送确认成功后清空，失败保留 |
| 缺思考强度 | Bot 配置支持 harness 的思考强度，保存并传递到运行会话；不支持时给出明确反馈 |
| 会话配置不可见 | 输入框上方常驻 harness、模型、思考强度、上下文占用；显示会话实际配置，避免 Bot 后续修改影响历史显示 |
| 缺版本号 | 导航底部与设置关于页同时显示本页前端、后端版本；有新版时提示重载 |

草稿仅保存在当前浏览器。上下文未上报时显示“未上报”，不冒充 0% 用量。
版本继续使用发布系统现有注入和 Hub 状态接口，不另造版本来源。

## 验证方法

执行类型检查、Hub 测试、Rust 测试、前端构建。以独立临时 Hub 和模拟数据实际检查桌面浅深色、窄屏、会话辅助栏、Bot 思考强度、版本与草稿切页/刷新/发送失败恢复。仅在任务分支提交，不推送、不发布。

## 边界

草稿保存在当前浏览器，可恢复文字、提及与已上传的附件；正在上传的附件切页仍会继续上传，但刷新浏览器无法恢复尚未上传完成的原始文件。

Bot 的运行参数用于新执行会话；主页 Steve 的分诊与回复沿用独立模型配置，设置中已说明。实际模型可用档位由 ACP adapter 回报；本次使用模拟 adapter 验证协议链路，未调用付费模型验证各模型的实际推理效果。

没有推送、发布或修改线上数据。
