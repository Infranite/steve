# Steve v0.2.19

Knowledge search can now find things by what they mean, not only by the words they contain. Asking about "the gateway move" finds a note that says "migrated the gateway to the new server".

- **Meaning search runs on OpenViking.** It runs as a separate local service next to the Hub and only listens on this machine. It works out the meaning of text on the CPU and makes no model calls. Install it with `ops/openviking/install.sh`. Then set `STEVE_KB_STORE=openviking` and `STEVE_OPENVIKING_KEY_FILE` in `steve.env` and restart the Hub.
- **What each person may read is still decided by Steve.** Every result OpenViking returns is checked again against what the person asking may see. Content that is never shared is never sent to it.
- **Keyword search stays where it was**, and answers are built the same way as before. Search tries exact keywords first, then meaning, and loosens the keywords only when too little was found.
- **Steve copies its knowledge to OpenViking through its queue of outside actions.** A change or deletion is copied once OpenViking is reachable, so nothing is lost if OpenViking is down for a while. On the first start with OpenViking turned on, Steve copies everything it already has.
- **If OpenViking is down, Steve says knowledge is unavailable**, instead of answering from only part of it. The service is restarted automatically. Setting `STEVE_KB_STORE=sqlite` goes back to keyword search only and stops the copying.

No database migrations.
