# Steve v0.7.0

Hub 收到 Node 事件即应用，不再保存原始事件副本：每批事件在一个事务里按流顺序应用，提交后才向 Node 确认；重发的事件只确认不重复应用，未确认的事件由 Node 重发。一个事件应用失败只停它所在的流（会话会收到说明），其他流照常。升级迁移会删除 Node 事件收件箱和隔离区，并从中保留会话的恢复句柄与修订号；请按常规流程先排空再升级，已确认但尚未应用的事件无法再取回，对应会话会在对账时标记为缺口。

新增指标 `steve_node_ingest_commits_total`、`steve_node_ingest_events`、`steve_node_ingest_seconds`，与已有的 `steve_process_disk_written_bytes` 一起观察写入量。

The Hub now collects metrics from its start, whether or not they are exported; `STEVE_METRICS=prometheus` still serves them on their own listener, and the management socket serves the same text at `/metrics`. New metrics cover live update streams, the event bus, commands and links to each Node, what each Node reports about its journal, backlog, harness processes and own process, plugin calls and restarts, agent turns and model calls (tokens and cost), the Hub process's CPU, memory, descriptors and threads, and the web page's long tasks and interaction latency.

Settings · About has a new Health section for the instance owner: the key figures of the last fifteen minutes beside their limits, with what is past a limit said first (from `GET /api/system/health`).

Needs a minor release: the Node protocol is now 11; upgrade the Hub and all Nodes together.

Agents get Steve's tools again from the first turn: a session lists them as soon as its harness connects, without waiting for a running attempt (calls still need one). An attempt whose harness never listed them is now noted once in the session's timeline and counted in `steve_session_steve_tools_missing_total`.

After an upgrade that changes the Node protocol, the Hub restarts its local Node on the new build by itself; it no longer waits for the old Node to link first.
