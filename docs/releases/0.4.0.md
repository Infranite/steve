# Steve v0.4.0

Needs a minor release: back up the database before upgrading if you may need to restore an older Hub; the untouched, automatically installed “New issue” suggestion rule is disabled on upgrade; re-enable it in Automation if you still want suggestions, or opt into Issue triage for individual repositories.

GitHub repository settings now have independent, off-by-default switches for PR review and new Issue triage. Bot reports appear as Steve items. To share a report on GitHub, prepare its comment and approve that comment separately. The repository's Activity tab connects deliveries and skip reasons to flow steps, failures, result items and comment status.

群聊触发词的只读研究结果现在会交回渠道回复生成器，按当前对外身份、审批和披露规则进入正式回复流程；生成摘要不再因缺失该流程的生成依据而静默留在对话中。未完成的研究和无法核验发送资格的结果仍可阅读，并显示未发送原因，不会自动重发历史结果。

渠道按目标限写和全局只读仍按原有权限执行，未确认发送不会显示为送达。对话保留并展示渠道拒绝原因；清理未添加成功的 reaction 不再抹掉拒绝证据，未获渠道确认的表情也不会显示成已回答。

In New project, keep using an existing folder, or create an empty folder or clone a Git repository on the Hub Node. New destinations are previewed and never overwritten. Cloning shows progress, uses the Node's existing Git credentials, and lets you choose the remote default or a named branch. A project is registered only after the folder is ready; cloning does not set up automatic pulls or pushes.

事项收尾时，列表、详情和动态会显示 Hub 查到的 PR 提交、GitHub 检查结果、上次成功同步时间及下一步责任人，不再把 Agent 空闲说成事项停滞。同步失败时保留并标明上次结果与失败原因；提交更新后不再显示旧提交的检查结果。普通轮询只刷新卡片，检查失败、需要决定或确认合并时才同步到原对话，不改变验收与合并规则。

“群聊和私聊”列表新增“最近回复过的”筛选，显示发过信息或仍有消息草稿等待审批的会话。筛选沿用最近活动排序，不设额外时间范围，可与渠道和搜索条件一起使用；未发送成功且没有待审批草稿的会话不显示。

Needs a minor release: the Hub↔Node protocol goes to 0.8 with `node.remove`, `node.remove_commit` and `node.remove_status`. Nodes of earlier releases keep working with the new Hub, but only Nodes upgraded to this release can remove themselves; for the others Devices shows the command to run on their machine.

- A Node's page in Devices has **Remove from this machine** next to **Unpair** (#325). After its owner confirms, the Hub asks the Node over its own connection to stop taking work, let running sessions end (cancelling them after `STEVE_NODE_REMOVE_GRACE_SECS`, default 10 minutes), stop and uninstall its service and delete its home; once the Node confirms, the Hub unpairs it. This works for Nodes installed remotely over tailcat, whose one-time SSH key is gone.
- When the Node is offline, runs an earlier release, or does not confirm, the dialog shows the exact command to run on that machine instead, and keeps **Unpair** at hand.
- **Unpair** is unchanged and now says so: the Node stays installed on its machine but can no longer connect.
