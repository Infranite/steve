# Steve v0.2.69

对话页的直接回答和研究回复改为通过 ACP 在 Node 上接收实时正文，边生成边显示；长回复无需等整段结束才能阅读，中途停止会保留已生成的内容。

修复事项通知和并发刷新误清除流式草稿的问题，正式回复完成后只替换对应草稿，避免重复或闪退。流式过程保留只读工具限制、取消、用量统计和模型回退。

升级暂停期间，后台模型请求会等待恢复后再执行；已开始的对话及其模型回退可正常收尾，避免后台分类任务在暂停后启动新进程。

- 回答权限请求、批准智能体提出的操作、让失败的事项继续，这几类卡片又能马上生效了。0.2.54 起，事项的工作区在 Node 上时，回答任何“批准”或“失败”卡片前都要先等 Node 读一遍 git，每次要多等 1 到 3 秒。现在只有会决定事项结果的回答才先读 git：验收、批准发布、失败卡片上的“其实已经做完”“核对发布结果”“放弃”。
- 渠道的接入账号移除后，在那个群或私聊里还没发出的回复，会在对应的对话里标为“没有发出去：接入的账号已经移除”，不再只在日志里留一条警告。原消息上的表情状态也会在本地结束，不再去调用已经不存在的连接，日志里也不会反复出现报错。

- 执行者新增只读工具 `steve_lane_status`，用来查看自己这件事项的发布进度：有没有请求过发布，在合并通道的哪一批（例如 MQ-3，批次分支 `steve/merge/main/MQ-3`、自己排第几、同批还有哪些事项），这一批现在是排队、收集中、准备中、等批准、合并中、发布中、发布失败、被退回还是已发布。等批准时会写明是哪张卡片、由谁来批；失败时给出原因和去哪里看详情；已发布时给出合并进的分支、提交和版本号，并说明下一步该等待、修复后重新交付，还是不用再做什么。不走合并通道、用项目自己的发布脚本的项目也一样能查。以前执行者调用 `steve_publish` 只得到“已请求发布”，之后看不到进展，常常停下来问你“我在哪一批”。现在 `steve_publish` 的回复和执行者的工作说明都会提示它用这个工具自己查，不要来问你。管理页的执行者能力列表和会话记录里也会显示这个工具。

设备页现在可以生成限时配对码、查看远程节点连接状态，并在核对设备端指纹后确认接入，替换此前无法配对的占位面板。

配对面板兼容由反向代理提供 HTTPS、Hub 未配置证书指纹的部署，不再显示空的证书指纹栏目。

旧会话迁移的发布检查现在分别核验会话与后台模型：维护期间禁止启动进程，解除维护后允许后台模型恢复，同时确保旧会话只运行一次、空闲会话不会提前启动。
