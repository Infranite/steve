# Steve v0.2.56

- 页面会自己发现新版本：Hub 启动后不久会检查一次，之后每 6 小时检查一次；发现新版本时，侧边栏会出现“新版本 X 可升级 · 查看”，设置 · 关于 前有一个小圆点，实例管理员还会收到一次提示。实例管理员打开 设置 · 关于 时，如果一小时内没有检查过，会自动再查一次。GitHub 接口超出频率限制时，改从 github.com 的发布页读出最新版本。只有实例管理员能发起检查。

- 用 `ops/local-release.py` 在本机签名构建的安装（macOS，保险箱密钥在 Keychain），现在可以在 设置 · 关于 一键升级到新版本，不需要先迁移密钥。点「升级到 X 并重启」后，这台机器会用这个 Release 标签构建（大约 10–20 分钟，期间 Steve 照常服务），然后排空任务、备份数据库、切换并重启，服务会短暂中断。页面会显示每一步的进度，重启后也会接着显示；最后的结果是以下几种之一：
  - 已升级，并核对版本和服务健康；
  - 被拒绝，并说明原因；
  - 失败后已恢复到升级前的版本和数据库；
  - 已经切换到新版本，但新版本没有正常起来。这种情况不会回滚，页面会写明升级前备份的位置。

  每次升级的日志在 `~/.steve/logs/release/upgrade-<版本>-<编号>.log`。
- 升级只认 Release 标签：只能升级到比当前版本新的正式版本。标签在 GitHub 上指向的提交必须与发布清单一致，本机已有的同名标签也必须指向这个提交，否则拒绝构建。构建和部署用的是这个标签自己的脚本，不会动本机源码目录里的文件。同一时间只能有一个升级或发布在进行：`ops/release.sh`、`ops/local-release.py` 和页面发起的升级会互相等待，后来的会被拒绝。只有实例管理员能执行升级。
- 这台机器缺少一键升级所需的东西时（签名身份、签名钥匙串、源码仓库、cargo、npm、git，或 Python 3.12 及以上），设置 · 关于 会列出缺少哪些，并照旧给出手动升级的命令。Python 会依次找 `STEVE_PYTHON`、`python3.13`、`python3.12`、`python3`（也找 Homebrew 的目录），只用 3.12 及以上的那一个；只有系统自带的 Python 3.9 时，页面不会给出一键升级按钮。
