# Steve v0.2.54

- 开启本机 Node（`STEVE_NODE_MODE=local`）后，再设置 `STEVE_NODE_JOBS=think`，Steve 自己的判断调用（路由、回答、草稿、模块和渠道的模型调用）会作为 Node 任务运行，每个模型一次。选模型、按 设置 · 模型 依次回退、统计里的次数、失败和 token 都和原来一样；图片、附件、边写边显示、停止和超时也照旧。Hub 重启时还没结束的判断任务会被取消，不会再跑一次。不设置时一切照旧。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，导入本机 Claude Code / Codex 会话由 Node 列出、读取和转换，导入后的会话记录与原来一致；只能导入 Node 自己列出的会话，其他路径会提示“不是本机能导入的会话”。会话页的“在 harness 里继续”也由 Node 查找记录文件，路径显示为 `~/…`。运行环境里的 Claude Code / Codex 版本和 Codex 的模型列表改由 Node 探测，Hub 不再自己运行 `claude` 或 `codex`；这时 Codex 的模型列表只有模型 ID，没有显示名和推理强度，本机没有 Codex 时不列出 Codex 模型，装了 Codex 但列不出模型时仍用内置列表。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，git 项目里新事项的工作区由 Node 建立和删除，位置和分支都和以前一样（`worktrees/<事项编号>`，分支 `steve/<编号>`）。建工作区和删除工作区不再卡住 Hub 的其他操作；磁盘低于开工下限时，新事项照样提示磁盘空间不足。建不了工作区时，事项会提示“开不了会话”和原因，下一条消息会重新建。事项打开会话期间被暂停的，会话打开后不会自动开始，继续时再开始。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，会话已在 Node 上开工作区的事项，交付时冻结的结果、交付后结果有没有变、有没有需要发布的改动、发布的版本是否包含验收的结果，以及按项目约定核对是否已合并、已推送 tag，都由 Node 的 git 判断；发布前的 rebase 也在 Node 上做。Node 一时连不上时，等待验收的事项保持原样，不会被当成结果变了而作废交付，Node 回来后再核对。
- 批准发布后、rebase 之前分支又有了新提交时，这次不会发布，会把 rebase 失败的原因（核对之后分支又动了）交回给 agent 处理。
- 事项在另一台设备上时，交付结果的核对同样由那台设备的 Node 判断；这类项目不能在 Hub 上发布，发布脚本只在 Hub 所在的设备上运行。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，YOLO 代你验收 Node 上的事项，分支是否干净、有没有新提交，以及判断事项有没有进展用的当前提交，都由 Node 的 git 回答；Node 连不上时按“看不出来”处理，留给你验收。
- YOLO 判断 Node 会话的工具请求时，以 Node 准备工作区时报告的目录为准，不再看会话记录里的目录；工作区已被清理，或所在目录已不在配置的根目录里时，YOLO 留给你决定；Node 会话要结束的进程只认 Node 报告的那些，Hub 不会去查本机的进程表。

- 项目在另一台设备上时，不能用项目的发布脚本发布或回滚：批准发布会直接记为未发布并给出失败卡片，说明发布脚本只能在 Hub 所在的设备上运行；回滚会直接报错。Hub 不会在本机的同名目录里 rebase 分支或运行脚本。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，知识库文件夹改由 Node 扫描和读取，索引、可见范围和 front matter 仍在 Hub 上处理。扫描没有读完（设备离线、超过数量上限、有目录读不出来）时不会删除任何文档；设备离线时来源状态显示“设备离线”，已有文档和索引保持不变。文件在扫描后、读取前被改动的，会重新排队读取。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，新建项目选目录只列出通向已登记目录（项目、知识库文件夹、Hub 自己的临时和工作区目录）的路径，不再浏览主目录下的任意目录；不在其中的目录仍可直接输入路径建成项目，建好后就能在这里浏览。已登记目录里的文件列表和说明文件由 Node 读取，指向已登记目录之外的链接不会被当作目录。
- 项目在另一台设备上时，合并通道暂时只能在本机项目上查看：会直接说明项目在另一台设备上，那台设备的 Node 不在线时提示“设备离线”，不会再去读 Hub 上的同名目录。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，事项的产出（文档、文件、文件夹、图片和视频）由 Node 读取，显示内容与以前相同，视频仍可拖动播放；会话已在 Node 上开工作区的事项，分支和提交也由 Node 的 git 读取。项目里指向项目之外的链接不再打开；临时目录里的产出照常显示。
- 事项在另一台设备上时，产出从那台设备的 Node 读取；那台设备不在线时提示“设备离线”，暂时看不到 git 记录时会直接说明。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，流程里的命令步骤（`cmd`）在项目所在的 Node 上、项目目录里运行，步骤结果与原来一致；项目目录改过后，命令会在新目录里运行。Node 不在线时步骤失败并提示“设备离线”；Hub 在命令运行时重启，这一步记为结果未知，命令不会自动再运行一次，你选择重试时会先确认上次的命令已停下再重新运行。关闭本机 Node 时保持原来的做法。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，机器人使用保险箱机密的命令（`steve_secret_use`）在会话所在的 Node 上、会话的工作区里运行；机密只在命令开始时交给 Node 一次，不写进 Hub 的命令记录或 Node 的日志库，输出里的机密照旧打码。Hub 在命令运行时重启，这次使用记为失败，命令不会再运行一次。会话在其他设备上时，不能以文件方式（`files`）交付机密，请求会在发出审批前直接被拒绝，可以改用 `env` 或 `stdin`。命令本身写着令牌之类的机密时也一样直接拒绝（Node 会原样记下命令），请把机密存进保险箱再注入。关闭本机 Node 时保持原来的做法。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，验收后开 PR 所需的推送改在事项工作区所在的 Node 上进行，规则与原来相同：工作区的 origin 必须是关联的仓库，分支必须还在批准时的提交上，推送从临时仓库发出、不受工作区自身配置影响；GitHub 令牌只在推送开始时交给 Node 一次，不出现在命令行、工作区配置、Hub 的命令记录或 Node 的日志库里。推送超时或 Hub 在推送中重启时，不会再推送一次，而是看 GitHub 上的分支：已经是批准的提交就继续开 PR，否则这次开 PR 记为失败，需要重新确认；Hub 等到时推送还在 Node 上进行（例如 Node 刚重连才接到它），这次开 PR 记为结果未知，稍后再问 Node，不会在推送可能还会完成时就判失败。关闭本机 Node 时保持原来的做法。
