# Steve v0.2.92

- 设置 · 模型、Bot 的模型选择器和"运行环境"列表里的模型、默认模型和思考强度，都来自各 harness 适配器自己报告的（Node 探测时开的临时会话里的 `model` 和 `thought_level` 选项）；还没探测到时用该适配器声明的备用列表。不再读取 `~/.claude/settings.json` 的模型选择器，也不再运行 `codex debug models` 或读取 Codex 的 `config.toml`。自定义适配器和内置的一样出现在这些选择里。
- Steve 的 harness 没有可用的适配器时，判断不再悄悄改用 Claude Code，而是按原 harness 去跑并在设置 · 模型里说明它现在不可用。没有指定模型时用该适配器自己的默认模型；只有声明了 `model_fallback` 的适配器（内置的 Claude Code）才会在 Bot 的模型之后接着试 `STEVE_MODELS_SMART` 的列表。
- 去掉了只对 Codex 的两条提示（逐字输出、研究不能接着追问），这两点在 ACP 下已不成立。
- "运行环境"里每个适配器一行：内置或自定义、是否可用（适配器缺失、`initialize` 失败、开不了会话时会写明原因）、版本，以及它支持的能力（会话、判断、图片、恢复、历史）和权限模式。Bot 设置里的权限模式和思考强度只列出该 harness 支持的。
- 在"运行环境"下可以直接接入自己的 ACP harness：填写 id、名称、启动命令、参数和环境变量，高级里可以用 JSON 写声明的属性（会逐项检查）；保存到 Hub 的 harness 清单（`$STEVE_HOME/harness.json`，只有所有者可写，文件权限 600），重启 Hub 后生效。
- 新建 Bot 的模板和"空白 Bot"默认用第一个可用的 harness。

- 会话和 Steve 自己的调用设置权限模式时，先看适配器在 `session/new` 里报告的模式：Steve 的模式按适配器声明的对应关系（没有声明时按 ACP 常用的 id）找到它提供的那一个；"计划"在适配器没有计划模式时改用"每次询问"；更宽的模式（接受编辑、自动、完全放行）适配器不提供时直接拒绝并说明，不再沿用适配器自己的默认模式。Steve 自己的调用一律用只读的"计划"模式，不再按 `read-only`、`plan` 这两个名字去猜。
- Node 的探测除了 `initialize`，还会开一个临时会话（不发提示词，不调用模型），报告适配器提供的权限模式、模型、默认模型和思考强度；内置的 Claude Code 和 Codex 也一样探测，结果最多缓存半小时。实测 claude-agent-acp 0.99.1 和 codex-acp 0.16.0 都提供 Steve 的全部五种权限模式。

- 就地研究只在本机 Node 上以 ACP 运行，任何声明了的适配器都可以承担；不再调用 `claude -p` 或 `codex exec`。本机 Node 关闭时研究直接提示不可用；项目目录不在本机 Node 能读的范围里时，这次研究会失败并说明原因（以前会改在 Hub 进程里跑）。
- 研究的只读检查只看工具调用是什么（ACP 的种类、位置和搜索范围），不再看 Claude 的工具名；Steve 自己的研究工具按名字（不带 harness 前缀）放行。
- 研究的沙盒只放开这次运行的目录和该 harness 声明的状态目录，不再固定放开 `~/.claude` 和 Codex 的目录。
- 追问接着上一轮研究的会话时，只在同一个适配器上加载那个会话；换了适配器就带着上一轮的回答重新开始。数据库里研究的会话 id 改存在中性的 `session` 列，并记下它属于哪个适配器（升级时旧记录记为 Claude Code）。
- 没有指定研究模型时，任何适配器都用自己的默认模型。

- Steve 自己的模型调用（路由、对话回答、草稿、标题等）一律以 ACP 单次调用跑在所选 harness 的适配器上，Hub 自带的 Node 和不带 Node 的 Hub 走同一条路；不再调用 `claude -p` 或 `codex exec`。任何在清单里声明的适配器都可以承担这些调用。
- 适配器在 `initialize` 里声明支持会话系统提示（`sessionCapabilities.systemPrompt`）时，调用的固定前缀作为会话的系统提示发送；不需要工具的调用会替换 harness 自带的系统提示，Claude Code 还会关掉内置工具。实测一次最短的 Claude Code 调用从约 2.3 万 token 降到约 2 千 token。不支持的适配器把前缀放在消息最前面。
- 没有指定模型时，任何 harness 都用适配器自己的默认模型（以前只有 Codex 如此，Claude Code 会报"没有可用的模型"）。
- 适配器在一轮中途停下（例如 `max_tokens`、`refusal`）时，这次调用按失败处理并带上它给出的原因；适配器回复的错误按其内容判断是否可重试，不再区分 Claude 或 Codex 的报错格式。
- Codex 适配器不报告用量时，从 Codex 的 rollout 文件读取这次调用的 token 数；Codex 的输入 token 不再把缓存部分重复计算（声明为适配器属性 `usage_input_includes_cache`）。
- 统计里 Steve 自己的调用记在实际使用的 harness 适配器下（`claude-code`、`codex` 或自定义适配器的 id），原来的 `claude-cli`、`codex-cli` 记录随升级改名合并。
- 适配器在同一轮里换了 `messageId` 时，草稿从新的一条消息开始显示。

- `steve hub stop` 现在会把 Hub 自己的 Node 进程（`steve-hub --local-node`）一起停掉；以前 Hub 停了它还留着，卸载之后成了没人管的进程。Hub 重启和升级时它照旧继续运行，进行中的会话不会中断。

- 用 `steve setup --vault-dir` 安装的 Hub（vault 密钥放在单独目录），签名钥匙串的密码现在也存进这个目录，不再去登录钥匙串找 `steve-keyhelper` 的条目。同一用户下的另一套安装因此不会碰到这一套的签名密码。
