# Steve v0.2.22

Prompts that no longer matter can now be closed and stay closed, choices in an IM conversation now apply to that conversation, and a session can be resumed in its own harness.

- **IM conversations keep their own decisions.** A reply option in a chat group's conversation used to post into your main conversation. Those options are now shown read-only as "可以回复：…", because they are for the people in the chat. A reply waiting for your approval has "不发出" to close it right there, and "去批准…" to approve it on its 待处理 card. That card shows the text that would actually go out and any disclosure warning. Closing it is sent once, takes the "处理中" mark off the chat message, and stays closed after a reload.
- **Dismissing a drafted reply in 待处理 now discards it.** The conversation no longer shows "等你批准后发出" for it, and undo puts it back. Drafts left waiting by an earlier dismissal read as "你没有发出".
- **A follow-up question in your main conversation is answered once.** Clicking an option twice no longer sends it twice, and the options fold away once you have answered.
- **Item cards recover from failures.** When the Bot carries on, or you continue, hand it to Steve, resume, or add to the item, the card's "卡住了" line goes back to in progress. The failure stays in the item's timeline.
- **Resume a session in its own harness.** Each session in an item's side panel shows its harness, the start of its original session ID, a copy button, and a resume panel. Before the ID is known it says "待获取". The session page has "在 harness 中恢复", where you can copy the full ID, the resume command (`claude --resume` / `codex resume`, run in the session's directory) and the directory. The Hub also checks that the ID and directory still match the harness's own records. New endpoint: `GET /api/sessions/:id/resume`.
- **Your notes on approvals show in the item's conversation.** Notes you give when you approve, reject or decline a release now appear with the decision. They match the text that went to the Agent. Older records show a note only when one was saved with the decision.
- **Release failures follow the latest release.** "发布失败" in item lists, item details and conversations disappears once a later release goes out, the item is finished or dropped, or you close it. Both this notice and a card's failure line have a close button. Closing one is stored in the Hub, so it stays closed on reload and on other devices.

No database migration (schema 30). Hub and Web must come from the same release.
