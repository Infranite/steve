# Steve v0.2.91

- 可以从 Hub 远程安装 Node：在“设备 · 添加设备”里选“通过 tailcat 远程安装”，在目标机器上运行页面给出的一行 `tailcat serve --ssh-authorized-keys='…' ssh`（只接受这次安装生成的密钥），再把它输出的地址贴回来。Hub 随后自己完成：识别平台，下载与 Hub 同版本的安装包并核对 SHA256，经隧道发过去，安装、配对并启动 Node，页面上逐步显示进度。配对码经标准输入传递，不出现在命令行里。这样装的 Node 配对后直接可用，不需要再手动核对指纹。新 Node 经 tailcat（已开启时）或 Hub 的 HTTPS 地址连回来；访问不了 GitHub 的 Hub 可以用 `STEVE_NODE_INSTALLERS` 指向放有发布文件的本地目录。Hub 所在机器需要 tailcat 和 OpenSSH。

- Hub 与 Node 之间的连接加了几道防护，正常使用不受影响：
  - 同时处于握手阶段的连接最多 64 个，超出的直接回 503，Node 稍后会重连；
  - 每台 Node 提交事件的速度有上限（瞬时 64 MiB，之后每秒 1 MiB），超出时 Hub 回答“繁忙”，事件留在 Node 的日志里稍后再发，不会丢；
  - 对端不再读取数据时，写入在心跳超时后放弃并断开，不会一直卡住；
  - Node 读取文件的单次大小限制在一帧能装下的范围内；
  - 大量无效配对码不会再把正在被尝试的配对码的计数一并清空；
  - 对端发来的关闭原因和错误说明在写日志和显示前去掉换行等控制字符，并截断到 500 字；
  - 修正了 Node 事件守卫对 Job 主体的检查：之前查的是回合的 attempt 表，现在核对 job 及其 attempt 都属于这台 Node。

- 运行沙箱分为三级（`STEVE_CONFINE`）：
  - `0`：不隔离。
  - `1`（macOS 默认）：文件系统物理隔离。在工作目录里运行的 agent 和流程命令只能写自己的工作目录（包括 worktree 所属仓库的 `.git`）、harness 与工具链目录、临时目录、常用的工具缓存（npm、cargo、go、pnpm 等）以及 harness 自己的主目录（`~/.claude`、`~/.codex`）。其他位置只读，Steve 自己的密钥和数据照旧不可访问。环境变量保持用户系统原样，不做任何改动。
  - `2`：在 1 的基础上，运行进程从用户全新的登录环境启动（由 `$SHELL -l` 得到），再加上 Steve 为它设置的变量。
  
  某个工具需要写到其他位置时，可以用 `STEVE_CONFINE_WRITABLE` 补充允许写入的目录（多个用 `:` 分隔）。Linux 上的沙箱仍需显式开启（`on`、`1` 或 `2`）。Codex 继续使用它自带的沙箱。

- 默认配置按设计调整到最优：本机 Node 默认在单独进程里运行（`STEVE_NODE_MODE=service`，Hub 重启或升级不会打断正在跑的回合）；运行沙箱默认 1 级（文件系统隔离），Linux 上只要装了 bubblewrap 也默认开启；新会话默认按负载分配（`STEVE_NODE_PLACEMENT=spread`）。需要旧行为时，分别设为 `local`、`0`、`local`。

- 部署文档新增“多台机器”一节，概括 Hub 自己的 Node、其他机器怎样连到 Hub、工作在哪台机器上运行、机器离线时怎么办，以及怎样查看各设备的状态。

- 磁盘提醒提前了：Hub 所在机器的可用空间低于提醒线（`STEVE_DISK_LOW_GB`）时，Steve 先回收已完成和闲置事项的构建缓存，再发一条提醒；低于下限时的提醒和“暂不新建工作区”保持不变。每段紧张期只提醒一次，空间恢复后才会再提醒。
- 远程 Node 的项目磁盘低于提醒线时，也会发出提醒（数据来自设备状态采样）。

- 新增“外部渠道”接入：Steve 可以通过一个独立运行的渠道服务（WebSocket 协议）接入内置适配器之外的即时通讯系统。在 **接入 · 外部渠道** 填写渠道服务地址（`wss://`，明文 `ws://` 只允许本机 127.0.0.1 或 ::1）、渠道服务发给这个 Hub 的访问令牌，自签名证书再填证书指纹即可。Hub 主动连出去，不开放端口；渠道服务崩溃或重启只会让这个渠道暂停，Hub 不受影响，恢复后从上次的位置续接，断开期间可能漏掉的消息会补取回来（只记录，不处理）。
- 外部渠道以你本人的身份工作：收到的消息走和其他渠道一样的规则；接入前的旧消息、补取回来的消息和你自己发的消息只记录；以你的名义回复、表情回应和撤回都经过渠道服务，渠道服务禁止发送时连接变为只读。
- 协议文档、一致性清单和测试向量随代码发布（`steve_channels::adapters::ext_ws::protocol`），测试套件里带一个按协议实现的假渠道服务。
- 空间里的消息多了一种“补取的旧消息”标记，悬停可以看到说明。

- GitHub 新增内置流程「新 issue」：关联仓库里有新 issue 时，Steve 提一个建议事项（建议卡），由你决定要不要开始；issue 的内容会作为不可信数据标注。想让 Steve 直接开始的话，把这个流程里的模式改成 `start` 即可。已关联仓库的工作区在升级后会自动装上这个流程；删掉的模板不会再被装回来。
- 内置流程「PR 检查失败」在新安装时，主干检查失败改为提一个建议事项，不再只是提醒；已有的流程不受影响。

- 可以接入自己的 ACP harness：在 Node 的 `harness.json`（Hub 自带的 Node 读 `$STEVE_HOME/harness.json`，或 `STEVE_HARNESS_MANIFEST` 指定的文件）的 `adapters` 里写 `{"my-agent": {"command": "/path/to/agent", "name": "My Agent"}}`，可选 `args`、`env` 和 `properties`（例如 `modes` 把 Steve 的权限模式对应到它自己的模式 id，`nested_sandbox`、`self_read_only` 说明它的沙箱）。只要它支持 ACP，就能用来跑会话；写在 Hub 清单里的适配器会出现在运行环境列表和 bot 的 harness 选项里（只在远程 Node 上声明的，目前还需要在 Hub 清单里也写一份）。旧的写法（`{"claude-code": "/path"}`）照常可用；清单读不出来时只记一条警告，不会阻止启动。
- Node 会用 ACP 的 `initialize` 询问自己接入的适配器（每五分钟最多一次），报告它的名称、版本、是否支持图片、恢复会话、列出会话以及登录方式；启动不了或没有响应的适配器会标明原因，不影响其他功能。内置的 Claude Code 和 Codex 仍按原来的方式检测，不会为此额外启动适配器。
- Claude Code 和 Codex 之间的差别（权限模式的对应、Codex 的模型目录参数、只给 Claude Code 的 `CLAUDE_CODE_EXECUTABLE` 和会话设置）改为内置适配器的声明数据，行为不变。

- 本机 Node 可以在单独的进程里运行：设置 `STEVE_NODE_MODE=service` 后，Hub 会以 `steve-hub --local-node` 启动本机 Node，并让它脱离 Hub 的进程组（在 systemd 下放在单独的 scope 里）。之后 Hub 重启或升级时，正在跑的回合继续运行，Hub 回来后接上结果，不会重复发送。Node 沿用原来的 id 和数据目录，之前的会话照常继续；Steve 自己的思考和调研任务仍在 Hub 进程里运行。升级的排空阶段不再等待这台 Node 上的回合；Node 空闲时会切换到 Hub 的新版本。默认仍是 `local`（Node 在 Hub 进程内），这个模式需要显式开启。新增 `STEVE_LOCAL_NODE_PORT`（默认 Hub 端口 + 3）。

- 合并队列（试用，`STEVE_MQ=1` 开启，需要 Hub 自己的 Node）：合入和发布分开。
  - 按完成规则（合并或打 tag）结束的项目，验收通过的改动会自动进入目标分支的合并队列，不用 agent 再调用 `steve_publish`，也不再每批弹一张审批卡。验收时选“验收，先不合并”可以暂时留下，之后 agent 调用 `steve_publish` 再放进队列。
  - 每个目标第一次合入前问你一次是否允许；从旧的合并通道迁移过来的目标视为已经允许。读不到目标分支的保护规则时，队列不直接推送，这些事项按项目原来的方式合并。
  - 目标空闲就立即开始合入，忙的时候到达的改动自动攒成下一批，不再等 2 小时窗口。集成、检查和推送都在 Node 上 Steve 自己的镜像里进行，不碰你的仓库目录；构建输出在批次之间保留。
  - 目标分支要求 PR 时（托管方没有合并队列），每一批开一个 PR，托管方的检查通过后用 merge commit 合入，成员提交的祖先关系保留；目标有托管方自己的合并队列时，Steve 把每件改动单独开 PR 交给它，只观察结果，不再自己攒批。这两种方式需要项目关联了 GitHub 仓库。
  - 与同一批前面的改动冲突、或迁移编号已被占用的改动会退回给 agent，并说明原因和下一个空号。只是 rebase、改动本身不变的话，不用重新验收，会自动重新进入队列。
  - 暂存区所在的 Node 连不上时，批次先等它回来，超过设置的时间（默认 30 分钟）才开卡问你继续等还是退回。
  - 推送结果不明时先读远端核对，不会盲目重推；检查没有结果时开卡由你决定重跑、跳过检查还是退回；开了 YOLO 时，它可以替你回答“重跑”（每批次数按目标设置，默认一次），跳过检查和退回留给你。
  - 按 tag 发布的项目，合入后的改动进入发布列车：最早一件合入满 2 小时或攒满 10 件（可按目标调整）时关闭，只出一张发布卡，等你回答期间合入的改动并入同一趟、卡片原地更新。由 Node 在暂存区运行项目自己的 `ops/cut-release.py cut`。发布结果不明时按远端 tag 核对，已经发布的不会重复发布；发布失败的卡可以重试或放弃，放弃后这些改动随下一趟发布。
  - 项目页的“合并通道”在开启后换成合并队列：合入方式和授权（可以在这里允许或不允许）、排队和在途的批次（二分定位时两半挂在原批次下）、发布列车和它的关闭时间（可以“立即发布”）、近 7 天的统计（批次大小、等待时长、二分和退回次数、发布趟数、出卡和回答耗时），以及每个数字的设置，空着用默认。
- 旧的合并通道（031）在开启合并队列后自动转换：排队中和等审批的请求重新排队，等发布的改动进入发布列车，原来的批次审批卡不再使用。

- Hub 现在有自己的身份密钥（`secrets/hub-identity.key`，首次启动时生成，包含在每日备份里），并用它签名每次握手的 welcome。配对时 Node 会拿到 Hub 的公钥；此前配对的 Node 在第一次收到签名的 welcome 时记下公钥。此后，即使 TLS 在代理或隧道上终止，或者走的是本机明文连接，Node 也只认这个 Hub，冒充者会被拒绝。迁移 Hub 时请连同这个文件一起迁移；丢失后需要重新配对 Node，或者在确认 Hub 可信后删除 Node 的 `node.json` 里的 `hub_key` 行，让它重新记下。旧版本的 Node 会忽略签名，照常连接。

- Node 的密钥可以更换：在 Node 上运行 `steve-node rotate`，再重启 Node 服务。新旧两把密钥共同签名，Hub 接受后新密钥才生效，旧密钥保留为 `node/identity.key.previous`，此后 Hub 拒绝旧密钥，并在审计中记录。
- 设备指纹从 16 位加长到 32 位十六进制（128 位）。设备页对之前配对的 Node 也按新长度显示。
- 如果一台 Node 的连接在一分钟内被反复抢占（两方持有同一把密钥的典型表现），Hub 会暂停这台设备接活，在审计中记录 `takeover_suspected`，并发出通知，提醒你更换密钥或撤销设备。
- Hub 的 TLS 证书可以平滑更换：`STEVE_NODE_TLS_PIN` 可以同时写当前和下一张证书的 pin（用逗号分隔），Hub 在签名的 welcome 里公布这些 pin，做了 pin 的 Node 会记下来。所有 Node 都连过一次后，再换证书即可。`steve setup node --pin` 也接受用逗号分隔的多个 pin。

- 远程 Node 的主人在 `policy.json` 里允许执行命令（`"exec": true`）时，这台 Node 也会运行该机器上项目的流程命令、机密使用和推送；否则仍由 Node 自己拒绝。Steve 自己的思考和调研任务仍在 Hub 上运行。
- 新增 `STEVE_NODE_PLACEMENT=spread`：没有项目的事项开新会话时，会交给负载明显更低（按 CPU 数折算后低 0.25 以上）的已连接远程 Node；默认 `local` 不变。远程 Node 仍只接它主人的工作。
- 设备离线超过 `STEVE_NODE_HANDOFF_MIN` 分钟（默认 30，`0` 表示关闭），又有消息在等它的会话时，Steve 会结束这个会话，在新会话里继续事项。新会话带上之前的对话和等待中的消息，并提醒 agent：那台设备上没有推送出去的改动在这里看不到。同时发出通知。离线时长从连接断开时算起，最长不超过 Hub 这次启动以来的时间。
- 修正：本机 Node 以单独进程运行（`STEVE_NODE_MODE=service`）时，流程命令、机密使用和推送也能在它上面运行。

- 设备支持标签：在“设备”页给每台设备（包括 Hub 自己）打上标签，例如 `gpu`、`macos`。事项可以要求某个标签，要求的方式有三种：`PUT /api/items/<id>/node-tag`，流程里 `item.create` 的 `node_tag`，或者 agent 的新工具 `steve_devices`（它也能列出各设备及其标签和在线状态）。之后事项的新会话会安排到带这个标签的设备上：Hub 自己带这个标签就留在本机，否则交给可以接这项工作的已连接远程 Node。没有可用的设备带这个标签时，会在会话里说明，然后按通常的方式安排。

- Node 重启（包括本机 Node 随 Hub 重启或崩溃）打断的回合，不再一直挂着等人点停止：Hub 会自动放弃这次执行，Node 确认原来的进程已经退出后，Steve 提醒 agent 先核对现状、已经完成的推送、合并、打 tag、发布不要重做，然后接着做。这一回合本身不会重发，自动接着做和其他接管共用同一个次数上限。你自己点了停止的回合仍然交给你处理；Node 无法确认放弃时，也保持原来的做法。
- 会话的 Node 事件与已保存记录冲突、被隔离之后，这个会话不会自己恢复。现在会话里如实说明这一点，并直接提供“在新会话里继续”和“关闭这个会话”两个操作。新会话会带上原会话的对话，并提醒最后一回合的结果未知。被隔离的事件仍然保留，用于诊断。

- 设备页显示每台设备的运行状态：负载（按 CPU 数折算）、内存、各项目根目录所在磁盘的剩余空间、正在运行的会话数，远程 Node 还显示往返时间；数据约每分钟采样一次，保留一天，并画出走势。旧版本的 Node 不会被询问，页面上显示为“还没有数据”。之后选择在哪台 Node 上运行工作、以及磁盘紧张时的提醒，都会用到这些数据。
- Hub 与 Node 之间的协议升到 0.3，新增 `node.vitals`。旧版本 Node 照常连接。

- 删除了已停用的 TypeScript 版 Hub（`hub/`）和只为它存在的切换测试脚本。npm 工作区现在只包含网页端，`npm run check` 和 `npm test` 只检查网页。Rust 版 Hub 不受影响。

- `steve setup` 新增 `--label` 和 `--vault-dir`：同一用户下可以再装一套 Steve（自己的服务标签和签名身份，配合独立的 `--home`、`--listen`）。在 macOS 上，`--vault-dir` 把这套 Hub 的保险箱密钥放在单独的目录里，不写入登录钥匙串，因此不会碰到原有安装的密钥。
