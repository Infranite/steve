# Steve v0.13.0

## Before upgrading

- migration 140 rewrites stored reasoning efforts to the five levels. `minimal`/`low` → low, `medium` → medium, `high` → high, `xhigh`/`max`/`ultra` → max, and anything else → default. Update the Hub and all Nodes together (Node protocol 16). ([#576](https://github.com/Infranite/steve/pull/576))
- migration 144 adds `node_id` to usage and daily statistics and backfills history. Update the Hub and all Nodes together (Node protocol 17). ([#590](https://github.com/Infranite/steve/pull/590))
- on macOS Nodes whose harness CLIs are configured in `~/.zshrc`, run `steve node refresh-env` once after upgrading. ([#595](https://github.com/Infranite/steve/pull/595))
- migration 145 adds source roles and write modes, creates the sidecar memory tables (`memory_entries`, `memory_evidence`, `observations`, `rejected_patterns`, `memory_revisions`), extends project proposals to `SKILL.md`, and retires open memory confirmation cards. The pre-upgrade backup is taken automatically; restore it to roll back. ([#588](https://github.com/Infranite/steve/pull/588))

## Features

- **web:** group Node harnesses by availability and structure model lists ([#572](https://github.com/Infranite/steve/pull/572))

  The Node page's Harnesses tab is reorganised so you can see at a glance what works.

  - **Three sections.**
    - **Available** is expanded.
    - **Needs attention** lists harnesses that are installed but not usable. Each card states the typed reason and offers one action: sign in, upgrade, re-probe, or fix PATH.
    - **Not installed** is collapsed and lists each harness with its install command.
  - **Models are structured.**
    - A card shows the default model and the newest model of each family.
    - Every model is still reachable under "All N models", grouped by family, newest first, with dated snapshots folded under their alias and a search box.
    - Families and sources (gateway passthrough, local) are parsed deterministically from model IDs. Unrecognised IDs go to "Other".
  - Probe and component details move into a collapsed "Details" section on each card.
- **workflow:** script-based workflows — sandboxed engine, ledger and item wiring (WF-2 + WF-3) ([#554](https://github.com/Infranite/steve/pull/554))

  - Added deterministic JavaScript script workflows (`steve_workflow_run`) executed in an isolated QuickJS subprocess (`--workflow-step`), backed by a persistent run/call/attempt ledger (migration 139), schema-validated structured `steve_deliver` results, Git tree/commit fingerprint-verified cross-version reuse, cycle attempt budgets, and Hub-enforced independent final review.
  - Unified workflow step placement with Steve's coordinator rules (`placement::select` and the workspace `no_executor` decision card).
  - Moved retirement of non-terminal legacy dynamic workflow child items to one-time migration 140 and removed the per-startup scan.
- **observability:** report per-node/session cost and disk writes and remove read-path write locks ([#590](https://github.com/Infranite/steve/pull/590))

  - **No write lock on reads.** HTTP `GET` handlers no longer take the SQLite write lock. This covers `GET /me/attention` (polled by every open page), `GET /me/feed` and `GET /node-harness-updates/{node}`. The attention and feed windows now live in bounded in-process caches. A static check and a 17-session concurrency test keep it that way.
  - **Cost and load per Node and per session.**
    - Nodes report CPU, memory and bytes written to disk for each session.
    - Statistics can be broken down by `node` and `session`, and the per-group totals add up exactly to the overall total.
    - Stats, the Node page and Sessions show cost, tokens, load and disk writes.
  - New gauges: `steve_node_disk_written_bytes` and `steve_node_adapter_disk_written_bytes`.


  Closes #578. Refs #426.
- **knowledge:** keep personal memory in plain files and write it silently ([#588](https://github.com/Infranite/steve/pull/588))

  Personal memory now lives in plain files and is written silently. Steve no longer asks you to confirm each memory.

  - **Files are the only source of truth.** Personal context is plain Markdown with YAML front matter, in `$STEVE_HOME/context/` by default, so any other agent can read and edit it even when Steve is down. Steve's database keeps only sidecar data next to each block: anchors, provenance, a confidence tier and disclosure level. It never keeps a second copy of the text.
  - **Write modes per source.** Each source is `read_only`, `propose` or `direct_write`. Steve writes only where you allowed it to.
  - **One ingestion path.** Everything goes through the same deterministic filters: `steve_remember`, contact memories, digest, item and chat extraction, mail threads, and your edits to drafts.
    - The single test for keeping something is whether it would change how an agent acts on a different task; the default is not to keep it.
    - Content from external sources can never become one of your rules.
    - Confidence is computed from rules: source type, independent occurrences, corrections and age. Your corrections take effect immediately.
  - **Removed:** the `LASTING` keyword table, `SAY_KEEP`, the 03:40 "kept" morning message, and memory confirmation cards in Decisions.


  Closes part of #584 (memory card 2 of 6).

## Fixes

- **harness:** map one Steve reasoning-effort setting onto each harness ([#576](https://github.com/Infranite/steve/pull/576))

  Reasoning effort is now one Steve setting with five levels: `default`, `low`, `medium`, `high` and `max`. Each harness's adapter maps it to that harness's own control.

  - **Native option.** The level becomes the harness's own setting, for example Codex `reasoning_effort` and Claude Code `effort`. Levels are matched by position in the option list the Node reports for the current model.
  - **Model variant.** For harnesses where effort is part of the model, Steve switches to the sibling model at that level. For example, Antigravity `gemini-4-neon` accepts `thought_level` values `low` through `xhigh`.
  - **Not supported.** Some models expose no effort control, for example Antigravity `gemini-pro-orchestrator-neon`. These run at the model's default, and the session says so. Before, every turn failed with "harness did not report a settable reasoning effort".
  - Switching harness or model keeps your level. The picker shows what each level maps to on the selected model and greys out levels it cannot honour. The session view and transcript show the mapping that was applied, for example `high → codex xhigh`.
  - The session-open errors in `steve-acp` that were hard-coded in Chinese are now typed and localised in English and Chinese.
- clean closed item worktrees deterministically and reap test child process groups ([#589](https://github.com/Infranite/steve/pull/589))

  - **Closed items clean up after themselves.** When an item closes (finished, ended, failed or auto-completed), its sessions stop and its worktree is removed, along with its `steve/<id>` branch once that branch is merged. Unmerged branches are kept and the item says so. If cleanup fails, the failure shows on the item.
  - **One-time cleanup of earlier leftovers.** Worktrees of items closed before this release are cleaned once, by an idempotent maintenance task.
  - **Tests clean up their processes.** Test child processes are now reaped with their whole process group on exit, drop and panic. Before, leftover fake harnesses and `steve-hub --local-node` processes could pile up on developer machines.

  Tracking: #449.
- avoid macOS harness SIGKILL race and web DeviceMap/effort-mapping races ([#598](https://github.com/Infranite/steve/pull/598))

  Fix a macOS harness shutdown race where releasing or reconfiguring an idle Node session could fail with "the harness did not stop", and update the Devices connection map narrow layout immediately on viewport resize.
- remove three intermittent races in workflow locks, usage settlement and job tests ([#594](https://github.com/Infranite/steve/pull/594))

  Fixes three intermittent failures at their root cause, without retries or looser assertions.

  - **Workflow run locks.** Cleaning up `workflow_run_locks` could race with a new holder or a cancelled wait and leak entries. Entries are now removed in the same critical section that releases the lock.
  - **Usage tail settlement.** The settlement polling interval is now an explicit named constant, and the test drives settlement with an injected clock instead of wall-clock sleeps.
  - **Test synchronisation.** `workflow_run_e2e` and `review_jobs` now wait for the FakeNode acknowledgements (for example `AttemptStarted`) before emitting the next event, so async workflow failure steps settle deterministically.
- **install:** guide macOS file access in setup and capture the interactive shell PATH ([#595](https://github.com/Infranite/steve/pull/595))

  - **macOS file access during setup.** `steve setup` now walks you through granting folder and Full Disk Access once, for both the Hub and its Nodes. In SSH or headless sessions it prints the exact command to run instead (exit code 2).
  - **Every macOS Node reports file access, including the Hub's own.** Each one reports Full Disk Access, its protected folders and its canonical executable path. The Devices page shows one status for local and remote Macs, with the repair command (`steve hub file-access` / `steve node file-access`) and a one-click recheck.
  - **The service PATH includes tools set up in `~/.zshrc`.** `steve setup`, `steve node enable-boot` and `steve node|hub refresh-env` now read PATH from an interactive login shell, falling back to a plain login shell. That picks up tools added only in `~/.zshrc`, such as `~/.local/bin/agy`. The source used is recorded as `path_source`.
  - **Clearer `enable-boot` on old installs.** `steve node enable-boot` now detects a leftover LaunchAgent before asking for `sudo` and prints the commands to migrate it.


  Closes #519.
- **web:** unify the Node harness view, replace the raw JSON form and remove duplicated chrome ([#596](https://github.com/Infranite/steve/pull/596))

  - **One harness list per Node.** The Node's Harnesses tab shows a single list; the second, contradictory runtime panel is gone. Adding a custom harness is a typed form with permission mode, sandbox and resume controls instead of raw JSON.
  - **Less duplication on item and session pages.**
    - Item detail and session detail no longer repeat the same identity and approval cards.
    - Refusal reasons are shown inline instead of in hover-only tooltips.
    - Automation shows branch and rule conflicts.
  - **Settings and contacts split into tabs.** Bot settings and contact detail are organised as task-oriented tabs.
  - **Copy fixes.** No more "Bot Bot"; untranslated English in the Chinese UI is fixed.
  - **One component library.** Command menus, model pickers and inline diffs use affectUI. `cmdk`, `@shadcn/react` and unused UI modules are removed.
  - **Two unstable browser tests fixed at the root cause:** `markdown-highlight` and `effort-mapping`.

  Closes #580.

## Other changes

- **refactor(ux):** remove onboarding friction, the legacy handoff threshold, the allow_tool engine and low-risk decision noise ([#591](https://github.com/Infranite/steve/pull/591))

  - **No forced model choice on first start.** When a harness is ready, Steve pre-fills its default model and you can go straight to the chat. If no harness is ready, the first start shows one card that tells you to install or sign in to a harness.
  - **The old context-percentage handoff setting is gone.** The 0/70/80/90% auto-rollover setting is removed; context compaction belongs to the harness. Manual handoff, handoff when quota is exhausted, and handoff on provider errors remain.
  - **One permission boundary.** Steve's second rule engine (`allow_tool`) for one-shot and research runs is removed. Those runs rely on the OS read-only sandbox and the harness's own plan mode, and any permission request is refused and recorded.
  - **Quieter decisions.**
    - Workflow `notify` steps go to the Feed instead of Decisions.
    - High-confidence contact merges and steward assignments are applied directly, each with a 24-hour undo.
    - The blocking two-choice suggestion card is replaced by inline answers with one-click offers.
    - Decisions only holds things that really need you.
    - The main chat shows one waiting count, the sidebar badge, instead of four.

  Closes #579.
- **ci:** split macOS Rust tests across three runners ([#599](https://github.com/Infranite/steve/pull/599))

  CI splits the macOS Rust tests across three runners instead of two. The first macOS shard also runs the script checks, and on main it had reached its 45-minute limit after 1,921 of 2,440 tests (run on 741198023), cancelling the main build.
