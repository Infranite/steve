# Steve v0.2.62

- 就地研究现在作为本机 Node 任务运行（`STEVE_NODE_JOBS` 不设置时包含 `research`），每个模型一次。按 设置 · 模型 选模型和依次回退、跟进时接着上一轮的会话、边写边显示的草稿和工具行、停止按钮、附件和图片、预算、越界即停和审计记录、统计里的研究用量都和原来一样；一个工作空间同时只跑一个研究、同时最多几个研究的限制和提示也照旧。研究里 Steve 的只读工具（知识库、事项、会话列表）经由 Node 调用，只对这次研究、只在研究进行中可用。设置里没有限定研究时长时，在 Node 上也不限时，和原来一样不会中途被截断。研究的目录不在本机 Node 管理的目录下（或读不到这些目录）时，这次研究仍在 Hub 里运行，并记入 `/healthz` 的 `research_fallbacks`。

- 在本机 Node 上运行的会话，附件由 Node 从 Hub 按哈希取回，再放进会话工作目录的 `.steve/attachments`（目录里自带 `.gitignore`，不会被提交），图片照常直接附在消息里；Hub 不再往工作目录里复制文件。附件在 Hub 上已经不存在时（例如很早之前排队的消息），这条消息照常发出，Agent 会看到“有附件没能取到”的说明，会话不会卡在队列里。工作目录里的 `.steve` 是指向别处的链接时，附件不会写过去。

- 会话现在都在本机 Node 上运行：本机 Node 成为默认（不设置 `STEVE_NODE_MODE` 时就是 `local`），Hub 自己的旧运行器已删除，Hub 不再自己拉起 agent 进程。
- 升级后第一次启动时，旧运行器留下的会话会自动转到 Node 上，不需要手动操作，Hub 也总会正常启动：
  - 能转过去的会话会用原来的 harness 会话 id 接着原来的对话继续。启动时不会一下子拉起所有会话的 agent：有排队消息或被打断的一回合的会话，等升级排空解除后才打开；其余空闲会话等下一条消息到来时再打开。
  - 旧运行器已经领取、还没发出的消息会重新排队，转过去后照常发出。已经发出的消息会带上“先核对再继续”的说明重新排队，不会被当成新请求重做。
  - 升级时被打断的那一回合会在 Node 上接着做一次，规则和以前重启后自动继续一样：事项已结束、已暂停、在等你处理、中断超过一天，或者半小时内已经自动继续过一次，就不会自动继续，会在会话里说明，需要时出一张卡片。
  - 旧运行器留下的未答复工具授权会失效，并在会话里说明；继续时 agent 会重新请求授权。
  - 不能在 Node 上运行的会话（工作目录已不存在、项目已归档、Bot 已停用或删除、Node 不支持的权限模式等）会结束，并在会话里写明原因。它排队的消息再也发不出去，会一起撤下并列出（包括旧运行器已经发出、重新排队待核对的消息）。如果它的一回合正被升级打断，事项上会出一张卡片说明原因，不会一直显示“正在做”。这样结束的会话不会再恢复：直接给它发消息会被拒绝，在事项里发消息会开始新会话。导入的只读会话不受影响。
  - 启动时暂时没能转过去的会话（例如当时本机 Node 没起来），之后每隔几分钟会再试一次；转过去后，它排队的消息会马上发出，不用等你再发一条。
- Node 不能接的新会话（例如工作目录不在 Node 可用的目录里）会立刻结束，并在会话里和事项上写明原因，不会一直等着。
- Steve 自己的判断调用和就地研究也默认作为 Node 任务运行：不设置 `STEVE_NODE_JOBS` 时等于 `think,research`；设为空或 `off` 则仍在 Hub 里运行。
- 需要回退时设置 `STEVE_NODE_MODE=off`：已经在 Node 上的会话只排队，重新开启后接着发；这时不能新开会话，也不能给没在 Node 上的会话发消息，会直接提示“本机 Node 已关闭”。重新开启本机 Node 后，启动时会再把留下的旧会话转过去。`STEVE_NODE_MODE` 只接受 `local` 和 `off`，写错时 Hub 不启动并提示原因，不会悄悄当成关闭。0.2.50 的写法 `STEVE_NODE=local` 仍然有效。
- 用 `STEVE_NO_RESUME` 启动的数据库副本默认不开本机 Node，照常启动；在这样的副本上明确设置 `STEVE_NODE_MODE=local` 仍会拒绝启动。
- `/healthz` 的 `node` 一栏新增 `adopted` 和 `retired`：本次启动以来转到 Node 的旧会话数和因无法转而结束的旧会话数；本机 Node 开启时，`node.legacy.sessions` 在启动后应为 0。
- 升级排空不再等待或停止 Hub 自己的 agent 进程（已经没有了）；返回里的 `acp` 固定为 0，`adapters_stopped` 固定为 true。
