# Steve v0.2.74

- 新增“每个人在每台 Node 上自己的环境变量”：用 `PUT /api/node-env/{node}/{key}`（`{"value": …, "note": …}`）保存，`GET /api/node-env/{node}` 查看，`DELETE` 删除。本机 Node 的编号是 `local`。`PATH_PREPEND` 会把目录加到 `PATH` 前面。
  - 只能改自己的，且只能用在本机 Node 或自己配对的 Node 上；工作区所有者还可以为工作区本身（`principal: "svc:<工作区>"`）保存。值以明文保存在 Hub 数据库和 Node 的运行记录里，其他用户不能通过 Steve 读取，但能读取数据库的人能看到。
  - 目前只在一种情况下注入：运行的发起人就是这台 Node 的主人，是这个工作区唯一的成员，而且这台 Node 上不会有别人的运行（本机 Node 要求 Hub 只有这一个用户；远程 Node 本来就只接主人自己的工作）。其他情况先保存、暂不注入。原因是：现在的运行还在用 Node 主人的登录；Hub 还不记录每条消息是谁发的；同一个系统用户下的进程能互相读到环境变量。
  - 会话每次重新打开时按当时的值注入，删掉或改掉的值不会再带上。正在运行的 harness 要等下次重新打开才会更新。
  - 这些键不能设置：Steve 自己设置的（`HOME`、`TMPDIR`、`PATH`、`XDG_*`、git 全局配置、`STEVE_*`、`*_FILE`）；会把代码注入其他进程的（`DYLD_*`、`LD_*`、`NODE_*`、`BASH_ENV`、`ENV` 等）；控制 harness 本身的（`CLAUDE_*`、`CODEX_*`、`ANTHROPIC_*`、`OPENAI_*`），这类设置以后随每个人自己的 harness 凭据提供。
  - 保存在保险箱里的值（引用）还不支持，网页上的编辑界面也还没做。

- 新增可选的“每个人自己的 harness 目录”：在 `steve.env` 里设 `STEVE_PRINCIPAL_STATE=on` 后，新开的会话按“工作区 × 发起人 × Bot × harness”各用一个独立目录，存放 harness 的配置、登录和历史（Claude Code 通过 `CLAUDE_CONFIG_DIR`，Codex 通过 `CODEX_HOME`），不再和 Node 主人自己的目录混用。
  - 发起人就是这台 Node 的主人时，第一次会从主人自己的目录复制 Claude Code 的 `settings.json` 和 Codex 的 `config.toml`，之后就是独立的一份，原目录不会被改动。写在设置里的登录方式（例如 Claude Code 的 `apiKeyHelper`）会一起带过来；用 `/login` 的订阅登录和 Codex 的登录不复制，需要在新目录里重新登录。不复制 Codex 登录，是为了避免多份副本各自刷新令牌、把主人自己的登录挤掉。
  - 其他人的目录开始是空的，暂时没有登录，所以这个开关默认关闭；等每个人自己的 harness 凭据做好之后再默认打开。
  - 已有的会话，以及从旧运行器迁过来的会话，照旧使用原来的目录，续接不受影响。关掉开关后，已经用了独立目录的会话继续用它。
  - 启用 Steve 系统沙箱的运行只放行自己的主体目录；仍使用自身沙箱的 harness（当前 Codex）没有这层目录隔离。该阶段不隔离同一系统用户下的进程，也不改变真实 HOME。

macOS 系统沙箱里的运行不能启动 setuid 程序，例如 `ps`、`top`、`sudo`。查看进程可以使用 `pgrep` 等非 setuid 工具；该限制不适用于仍使用自身沙箱的 harness。

本阶段未改变执行权限，也不开放多 Bot 协作执行。主体凭据、独立 HOME 和完整的进程隔离仍待完成；现有工作流执行门槛保持不变。

- 工具链改为数据定义：Steve 内置 23 种常见构建工具的定义，包括 Rust、Node（npm / pnpm / yarn / bun）、Python（pip / uv / poetry / conda）、Go、JVM（Gradle / Maven）、Swift / Xcode / CocoaPods、C/C++、.NET、Ruby、Dart / Flutter、Elixir，以及常见前端框架和 Python 工具的缓存目录。每份定义写明怎么识别、哪些目录只是缓存，代码里不再写具体工具的名字。磁盘不够时释放哪些缓存、合并时哪些锁文件可以重新生成，也改为读这份数据，行为和以前完全一样。
  - 新增可选开关：在 Node 的环境里设 `STEVE_TOOLCHAINS=on`，并且同时开启 `STEVE_PRINCIPAL_STATE=on`（需要知道运行属于谁）后，会话里检测到的工具会这样放：
    - cargo 的构建输出 `target/` 放进事项自己的 `.steve/build/cargo`，不会进 git；为 agent 默认打开轻量调试构建（`CARGO_INCREMENTAL=0`、只保留行号信息）。
    - 只是缓存的下载和构建缓存（npm、bun、pip、uv、poetry、conda、Go、NuGet、Bundler）放进这个人在这台 Node 上自己的缓存目录，启用 Steve 系统沙箱的其他主体读写不了这些缓存；仍使用自身沙箱的 harness（当前 Codex）没有这层隔离。
  - 工具自己的 home、配置和凭据不会被移走，例如 `CARGO_HOME`、`GRADLE_USER_HOME`、`GOPATH` 和 Maven 的设置。其他项目或用户设置保持原样；启用此开关后，工具链的缓存重定向与瘦构建变量会覆盖同名环境变量。其他工具的输出照旧留在项目目录里。
  - 默认关闭，因为换位置以后第一次构建要从头开始。用前估算磁盘、种子缓存和定期清理会在后续加入。

同时启动多个首次会话时，主体状态目录和工具缓存目录会复用已创建的真实目录，不再因抢先创建而启动失败或丢失缓存重定向。首次导入配置会完整写入后一次性发布，并保留已有配置，避免另一个会话读到未写完的文件。

Items and sessions now offer a Debug panel with current blockers, limited-duration capture, filtered event pages and stable evidence references. Agents can read the same facts through `steve_debug`, subject to their current workspace and conversation access; only the instance owner can change capture.

Shared observation boundaries record bounded tool, decision, dependency and adapter-exit metadata without copying arguments or output. Capture expires automatically and reports retention, pending work and known loss; diagnostics remain best effort and do not drive task execution or perform repairs.

Replace copied date-formatting, tool-catalog and fixed schema-number expectations with public behavior, real-interface and release-lock checks. Store tests declare the runtime features they need to run independently. Keep distinct authorization, retry and lifecycle regressions, and make standalone open-source operation an explicit contributor requirement.

升级回归测试的模拟 Hub 在查询构建信息时立即退出，避免从正在运行的 Node 继承端口并误启动监听，也避免无谓等待探测超时。

修复主对话查询事项进度时，合法的只读工具调用因 ACP 工具身份格式不同而被误拦截的问题。保留工具的只读声明和原有授权检查，不依据显示标题放行；停止提示改为准确的工具检查说明，避免把未完成的查询误报成已经读取了越界内容。

- 日常升级直接下载并校验已发布的安装包，不再要求源码目录、Git、Cargo 或 npm。macOS 已有签名安装保留原钥匙串身份和凭据辅助程序，只对下载的 Hub 应用原签名。
- 升级回执记录实际下载字节、校验和解包阶段；等待安全切换时显示真正占用运行时的事项和会话。页面重连后继续读取同一回执，失败前的版本切换和数据库保护规则保持有效。

升级页显示实际下载字节、当前处理步骤与最近进展；切换前列出阻塞运行并提供事项入口，断线后保留最后状态并继续核对。普通本机签名安装改用预编译发行包说明，提供服务状态和诊断的终端入口。多 Bot 协作缺少执行隔离能力时明确说明版本限制并禁用恢复和重试，避免操作成功却没有工作启动。

协作所需的 Node 执行隔离尚未就绪时，恢复和重试会明确说明阻塞原因，保留暂停状态、工作单元和修订版本，不再显示成功却没有执行。仍可保存计划、暂停或取消工作。

官方发行包现包含 Hub、Node、Web、keyhelper 和运行脚本。macOS 自动升级下载并校验官方二进制，用原签名重新签名 Hub，保留已安装的 keyhelper 和钥匙串；旧版首次升级也无需重新编译，源码构建改为显式开发选项。

新增统一 Hub/Node 用户服务安装、启动、停止、重启、状态和诊断入口。Node 可在服务停止后切换到新发行包，保留身份、配对、目录和权限配置；运行中拒绝替换，不把已配对当作在线。升级记录提供真实排空状态和阶段耗时，健康部署后安全保留当前与前一版本。

- 独立 Node 在服务停止或 Ctrl-C 时先关闭连接并等待运行资源清理；无法确认的执行结果留在日志中供恢复，不会伪报完成。

Node 为按卷核算增加磁盘采样基础，分别记录逻辑大小和文件系统报告的已分配空间，避免重复计算重叠目录和硬链接。遇到路径变化、无法读取或采样超时时保留不完整状态，不当作零占用；本阶段尚未启用新的容量限制或自动清理。

启用工具链缓存隔离时，修正工作目录含等号或花括号导致的路径解析错误。无法安全解析的目录设置会跳过该工具链的环境注入，避免写错位置。

- Node 新增绑定执行记录与视图的产物读取接口：逐段拒绝符号链接，拒绝硬链接和特殊文件，按块限制读取量，文件在读取期间变化时拒绝返回内容。
- 这是产物读取迁移的底层准备；现有预览与知识库仍沿用原有路径，尚未完成全部迁移，也不代表运行隔离已经完成。

修正自动化发布回归测试的进程回收，正常结束测试时会同时终止模拟锁的等待进程并释放锁。

修复 Node 新事件与 Hub 消费队列恰好交错时，已收到的消息或回合结果可能长期不更新的问题。队列判空和清理待处理标记现在在同一提交锁内完成，后续事件无需等待下一条消息或重启即可继续处理。

Node 重新对账期间，任务只会在所等待的事件实际处理完成后继续，避免旧的队列判空结果提前解除新一轮等待。

服务检查与维护命令现在兼容旧版 macOS Hub 的启动配置：只有既有签名身份、账户默认数据目录和准确的启动脚本同时匹配时，才确认服务归属。其他目录、未知启动命令或环境覆盖仍须通过原有归属检查，检查过程不重写服务配置。

Node 可选择记录每轮开始和结束附近的磁盘占用，后台采样并保留预算、耗时和不完整原因，重启后不会补测并冒充过去的结果。记录数量和保留时间可配置，默认关闭；可恢复的统计写入失败不阻断回合状态提交，整个日志事务失败仍如实报错。它不改变现有磁盘准入、执行权限或清理行为，也不把异步观测当作独占增量。

事项页现在可以直接保存前置完成后的续跑方式和等待原因，无需先唤醒正在被前置阻塞的 Agent。页面区分工作区默认策略、单独登记的持久等待和当前调度暂停；旧的等待文案不再一律承诺“自动开始”。登记不会放开协作执行的隔离和权限门禁，重复保存不会重复启动工作，事项进入新一轮后会要求刷新再操作。

修正 macOS 升级回归测试对旧提示文案的依赖，继续验证错误或缺失授权安装目录时拒绝升级、不下发签名密码、不生成候选版本，避免正确拒绝被误报为发行检查失败。

补齐 Node 侧缓存种子与清理的基础校验：写时复制只使用系统 CoW 接口，不覆盖已有目标，不改用硬链接；清理预览遇到在用状态、保存证据或回收所有权不明时保留目录。此次不启用自动种子或业务目录删除。

修复普通事项暂停后，Node 在当前回合结束时仍可能自动执行排队消息的问题。暂停期间保留排队内容，恢复后再执行；取消请求已接收仍不代表当前回合已经停止。

已签名的 macOS Hub 新增随发行包提供的 `ops/upgrade.py`：本机安装账户可以检查版本、提交幂等升级请求、查看进度和终态，无需浏览器会话。它沿用升级日志和 launchd 执行器，由原签名 Hub 读取钥匙串；终端环境变量不能更换安装账户或升级仓库。新 Hub 直接安装二进制包，旧签名执行器通过一次兼容桥接获取官方标签脚本，不在本地编译。

修正日志磁盘阻塞回归测试的时序竞态：用明确的阻塞与断管回执同步，继续严格验证输出入口超时会中断任务并保留原因，避免繁忙测试机器把正常结束误判为未执行保护。
