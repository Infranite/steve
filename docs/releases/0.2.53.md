# Steve v0.2.53

- 网络断开或手机把页面切到后台再回来时，网页从断开的位置接着收更新，只重新加载这段时间里变过的事项和会话记录，不再整页重新加载；回到页面或网络恢复时立即重连，不用等重试间隔。Hub 重启后或离开太久（超出 Hub 保留的变更窗口）时，会完整刷新一次。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，Hub 启动后新建或修改的项目不用重启就能在 Node 上开会话；项目归档后，它的目录（包括其中任务和会话用过的目录）不再登记给 Node，这个项目的新会话不再交给 Node 运行。知识库文件夹作为只读目录登记给 Node，不会在里面建工作区。

- Node 会话交接到新会话时（上下文用量超过交接阈值、目标改动较大、事项关联到项目、或换了 Bot），如果旧会话的回合还在运行，新会话会等这一回合结束、旧会话在 Node 上释放完成后再打开，不再出现两个会话同时在一个工作区里运行。等待期间新会话显示为正在打开，发给它的消息会排队，打开后再发出。如果 Node 拒绝释放旧会话，会自动重试释放，新会话里会提示正在等待。旧运行器上的会话保持原来的做法。
- 事项结束后清理工作区时，如果它的 Node 会话还在释放中，会等释放完成后再清理，不会在会话可能还在工作区里运行时删掉工作区。

- 开启 Node（本机 `STEVE_NODE_MODE=local` 或远程 Node）时，新会话在 Node 上的初始权限与旧的运行方式一致：机器人自己不能带来完全访问，只有 YOLO 的完全访问会；YOLO 开启时，有独立目录的事项同样放宽为“可以改项目目录里的文件”。
- 本机 Node 停止运行，或会话的目录不在 Node 允许的范围内（例如已归档项目的目录）时，新会话留在旧的运行方式里正常运行，不再卡在一个无法运行的 Node 会话上。

- `/healthz` 新增 `node`，不用查数据库就能判断 Node 路径的状态：本机 Node 是否启用（`STEVE_NODE_MODE=local`）、是否已和 Hub 对账、是否因启动失败而停用；绑定在 Node 上的会话数、未释放的会话数、进行中的轮次、结果未知需要人处理的尝试（`unknown`），以及因所在 Node 未启用而排队等待的会话（`parked`，Node 关闭时同样显示）。`legacy.sessions` 是仍会由旧运行器执行的会话数，`legacy.busy` 是其中还有排队消息、未完成派发或待恢复的会话数；`fallbacks` 是本次启动以来 Node 已开启、但新会话仍留在旧运行器上的次数。只有状态和计数，不含会话 ID、路径或错误原文。

- Node（`STEVE_NODE_MODE=local` 或远程 Node）的日志库会给磁盘留出余量：所在磁盘剩余空间不足 512 MiB，或日志库达到 256 MiB 上限时，Node 不再接新会话和新回合（Hub 会稍后自动重发），正在运行的回合会被取消并照常记下结束；停止、释放和权限回复仍然可用。空间回来、日志库降到上限的 80% 以下后自动恢复接活。Hub 收下事件后，Node 会删掉已结束命令的完整内容（包括提示词），日志库不再一直变大。

- Node 模式（`STEVE_NODE_MODE=local`）下，Node 发来的某条事件与 Hub 已保存的记录冲突时，不再卡住这台 Node 上所有会话的事件投递：冲突的事件被单独隔离保存，只有它所在的会话暂停应用 Node 事件并等待对账（会话里会出现一条说明，期间不会重新运行，新消息留在队列里等待），其他会话照常进行。
- Node 模式（`STEVE_NODE_MODE=local`）下，Hub 重启后会先向 Node 补齐此前没收到的事件并处理完，再开始新的一轮，会话里不再缺少重启前最后的回复。若 Hub 的数据回到了较早的状态（例如从备份恢复）或 Node 的记录回退，导致事件对不上，或者 Node 上有 Hub 没有记录的未结束工作，相关会话会出现一条说明并暂停，不会重新运行或发出新的指令，其他会话照常进行。某个会话的事件若迟迟处理不完，只有这个会话会出现说明并暂停，处理完后自动继续，不会让同一 Node 上的其他会话一直等待。

- Node 模式（`STEVE_NODE_MODE=local`）下，打开、释放、切换配置、准备工作区、放弃执行或回复授权这类操作在 Node 上结果无法确定时，会话不再只能一直等待：点停止会向 Node 发出一次撤回请求。撤回成功后会话被释放（准备工作区会重新准备再打开），排队的消息照常运行一次；被撤回的操作本身不会重发，它的实际效果仍按“无法确定”对待，不算成功。会话交接时如果撤回的是旧会话的释放，旧会话会重新请求释放一次，新会话等释放完成后再打开，不会一直卡在打开中。撤回不成功时会话保持暂停并提示需要人工核验 Node 状态，可以再点一次停止重试。

- 启用本机 Node（`STEVE_NODE_MODE=local`）时，升级前的维护排空会等 Node 会话的回合结束再停止服务，不再在 Node 回合运行时切换版本、让回合变成结果未知。等待审批的 Node 回合同样会让排空等待，直到你回复审批卡片或卡片到期；排空期间仍可回复这些卡片。结果未知（等待对账）的 Node 执行在点停止放弃前也会让排空等待；本机 Node 启动失败、已停止时不计入，不会挡住用来修复它的升级。等待超过升级的排空时限时，升级照旧放弃，当前版本保留。排空状态里新增 `node`，表示还在进行的 Node 工作数。旧运行器上的会话保持原来的排空行为；远程 Node 上的回合不受 Hub 升级影响，不计入排空。
- 取消、放弃或标记完成一个事项时，停止只作用于当时正在运行的那一回合：如果那一回合恰好刚结束、排队的下一条消息已经开始执行，新的回合不再被误停，事项等它结束后再关闭。旧运行器和 Node 会话都是如此。会话里点停止时，如果 Hub 无法确认停止（例如本机 Node 已停止），现在会提示出错，而不是静默显示没有可停止的回合。
- 一回合的结束消息晚到（下一回合已经开始）时，不再按它来判断事项：新回合里提出的批准或问题会保留到新回合自己结束，事项不会因此被误判为“停下来了，没有交付也没有提问”。同一回合的结束重复送达时只处理一次。旧运行器和 Node 会话都是如此。
- Node 会话里，回复或忽略工具权限卡片如果因 Hub 内部错误没能交给 Node，现在会提示出错并保留卡片，可以再回复一次；之前卡片会被静默标为失效，而 Node 那边的回合还在等回答。YOLO 开关变化时，如果没能切换运行中会话的权限模式，下一次同步会再试，不再丢掉这次变更。

- 开启本机 Node（`STEVE_NODE_MODE=local`）后，会话空闲超过 `STEVE_IDLE_RELEASE_MS`（默认 10 分钟）时会释放它的 agent 进程，和原来的运行方式一样；下一条消息会重新打开会话，接着原来的对话继续。还在跑、有消息排队或有待批准卡片的会话不会被释放；因等待对账而暂停的会话也不会被释放。

- 开启本机 Node（`STEVE_NODE_MODE=local`）时，权限模式为“自动”的机器人（包括内置的“Steve 开发”）的新会话也会在 Node 上运行，不再留在旧的运行方式里；YOLO 开关切换权限后，这类会话会回到“自动”模式。
- 远程 Node 需要升级到本版本，才会接收权限模式为“自动”的机器人的新会话；未升级的远程 Node 照常运行其他会话，“自动”机器人的会话留在 Hub 上运行。Hub 重启后远程 Node 还没连上时，YOLO 切回“自动”的操作会保留，等 Node 连上后再发出，不会被丢掉。
