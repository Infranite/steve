- Collaboration is planned to finish sooner. Steve splits work into parts that can run at the same time instead of a chain of phases, keeps resource keys per module or path, and does single-sequence work in its own session. A failed review goes back into the unit it found problems in, and that unit is retried instead of fix units being added to the end. When a plan leaves out `max_parallel`, every ready unit whose resources are free runs. A plan that cannot run anything at once, independent units that share a resource key, or a limit below what the graph allows come back as notes in the plan reply. They are hints and never refuse the plan.
- When a model's quota runs out and its error says when it is back (a 429 with "available again at 00:40 UTC"), the item waits until then and continues the agent once the quota is back. Before, Steve continued at once, failed again within a second and used up the continues.
- A Steve tool result too large for one Node message (over about 256 KB) reaches the agent cut, with a note of how much was cut and how to ask for the rest, instead of failing the call. A message that is still too large names the call it belonged to.
- A Node that reaches the Hub but cannot link now tells the Hub why. Devices shows the reason while that Node is disconnected (for remote Nodes and the Hub's own), and work waiting for the Node says why it waits. A Node that cannot reach the Hub at all records the reason in its own log and `link-status.json`.
- With remote Nodes off (`STEVE_NODE_LISTEN=0`, or a read-only copy), the Devices page says so instead of failing, and the Node API answers in JSON.
- A web client on another origin that the Hub does not let in yet shows how to sign in by token, instead of "Can't reach Steve". Signing in by token lets that origin in, and the browser sign-in, which could not return there, is no longer offered on that screen.
- Smaller fixes: YOLO's answers to tool calls read "allow this once" instead of an option id; the locked vault no longer suggests creating an item it can't create; GitHub shows a connection that needs reauthorisation as "Needs reauthorization"; modules that are not built yet say they are planned for a later release; the mail page's connect button opens the mailbox setup under Connections; a session's header keeps its way back visible on narrow windows.
- For contributors: `python3 ops/dev.py` runs a checkout as a development Hub next to the installed one, with the web dev server in front, so a change can be tried in seconds without CI or a release. `up --fresh` starts from an empty database. `up --snapshot` starts from a copy of the installed Hub's data that shows it without acting on it (nothing resumes, no Node, vault locked). `restart` rebuilds the Hub incrementally. The installed Hub's pages, the web dev servers and the origins in `STEVE_DEV_CLIENT_ORIGINS` may call the development Hub directly. See CONTRIBUTING.md.
