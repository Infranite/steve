- 主事项新增多 Bot 协作工作图：按目标拆分工作单元，声明依赖和协同范围，配置并发与尝试预算；独立单元使用各自的事项与工作区，共享交付物和检查记录。
- 支持独立评审、集成验收、暂停、恢复、取消、重试和带版本校验的重规划。旧尝试与调整原因保留；目标或周期变化后必须重新验证成果。事项详情展示协作进度、依赖、产物、调整记录及不能关闭的原因，Bot 可通过 `steve_workflow` 操作。
- 必需工作、独立评审、集成实际操作验证或子会话停止尚未完成时，主事项不能交付或关闭；取消工作不会被算作完成。子单元不能自行发布，旧会话不能继续交付或获得新工具许可。
- Bot 可查询其获授权范围内的事项，并为当前事项登记前置、回读真实等待状态。等待支持本事项单独选择自动续跑或提醒，重启后保留；等待前置是合法停点，不再被反复提醒“没有交付也没有提问”，前置未完成不能提前验收。
- 升级迁移和迟到的完成判断也遵守前置等待；缺少隔离能力的协作会话不会因重启被启动或提前结束。已加入当前工作空间的 Bot 可正常使用管理工具，撤销成员资格后立即停止获得新授权。
- 修复 Node 推送排队或响应较慢时凭据被提前撤销的问题：查询超时仍可继续等待，重复查询不会重复授权，操作结束后自动清理；提交失败可以安全重试。
- Node 的 Git 命令结束后会短暂等待进程组完全退出，避免系统尚未完成回收时误报失败；仍无法确认退出时保留记录并阻止继续操作。
- 本次先提供编排与验收基础。当前 Node 版本尚不支持通用 OS 沙箱和按运行主体隔离凭据，因此协作图可以创建和查看，但实际调度会明确阻止启动，且不会回退到 Hub 执行。真实多 Bot 执行需在这些 Node 能力接入并验证后启用。
