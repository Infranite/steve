- 实验性的本机 Node（`STEVE_NODE_MODE=local`）：Hub 重启不再误判 Node 会话被中断：空闲的 Node 会话不再收到“Hub 刚重启，请从中断处继续”的提示，也不再出现“Hub 重启，这一回合被中断”的消息或中断失败卡片；Node 会话的审批卡片在 Hub 重启后保持打开，仍可回复，到期由 Node 关闭。关闭 `STEVE_NODE_MODE` 后只排队的会话同样不受 Hub 重启影响。之前版本为这些会话留下的“重启后继续”记录在首次启动时清除。旧运行器上的会话保持原来的重启后自动继续行为。
- 实验性的本机 Node（`STEVE_NODE_MODE=local`）：Node 会话的运行状态和旧运行器一致：消息发出、回合排上后就显示“运行中”（harness 还没开出自己的会话时显示“启动中”，开始执行后转为“运行中”），回合结束后显示空闲，出错结束时显示出错，不再一直停在“启动中”；已结束的会话保持结束。结果不确定（等待对账）的执行，包括 Hub 或 Node 在 harness 还没开始执行时重启的情况，在点停止放弃前一直显示运行中。会话开始运行时，事项上的“它停下了”卡片同样会自动失效。Node 会话现在也记录 harness 自己的会话 ID，会话里能看到并复制这个 ID 和在 harness 里接着用的恢复命令。
- 实验性的本机 Node（`STEVE_NODE_MODE=local`）的统计：Hub 重启不再把 Node 上的回合记为“中断”。这些回合按实际结果（完成、取消、放弃）计入；Hub 自行结束的执行（停止时放弃、发送前取消）也会结束对应的统计记录，发送前就取消的执行不产生记录。
- 实验性的本机 Node（`STEVE_NODE_MODE=local`）：删除或重建 Node 的数据目录后，新的 Node 事件不再和 Hub 已收到的旧事件冲突，消息投递不会因此卡住；原来正在运行的执行标记为“等待对账”，不会自动重跑；迟到的旧“已释放”状态也不会把重新打开的会话关掉。旧版本 Node 打不开升级后的 Node 数据，不会误用。
- 实验性的本机 Node（`STEVE_NODE_MODE=local`）：Node 重发 Hub 早已处理并清理掉的旧事件时，Hub 只确认收到，不会再把这些消息或状态应用第二次；一条发送结果不明、随后又被 Node 以忙碌拒绝的消息，点“停止”时会真正向 Node 发出取消，而不是只在 Hub 上标记为已停止。
- 实验性的本机 Node（`STEVE_NODE_MODE=local`）：Node 存储或容量已满时，会话里会出现一条提示“Node 存储/容量已满，暂停接新工作，恢复后自动继续”（只提示一次）。Hub 不再每秒重发，而是从 2 秒起逐次加倍、最长 60 秒再试。若在约 10 分钟内恢复，原来的那条消息照常执行一次，不会重复执行，也不会交给旧运行器；超过约 10 分钟仍未恢复，这一轮会以失败结束，需要重新发送。
