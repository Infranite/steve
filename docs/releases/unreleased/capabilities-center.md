- **Capabilities** (能力) is a new sidebar entry next to Bots: the workspace's library of MCP servers, skills and remote agents, each defined once and chosen per bot. Its tabs are MCP servers, Skills and A2A; every entry shows which bots use it, and its bots can be chosen right there.
- A bot's **Capabilities** tab now shows what that bot uses: Steve · built-in first, then the MCP servers, skills and remote agents it is given, each with a switch for that bot alone. **Add** picks one from the library or makes a new one, which goes into the library and to that bot at once. Editing an entry changes it for every bot that uses it; taking it off a bot leaves it in the library.
- MCP servers are a local command (stdio) or an HTTP or SSE endpoint, with environment variables or headers. Every session of a bot gets the servers it has switched on through ACP, next to Steve's own tools, the same way for every harness and on every Node; a change applies the next time a session's harness opens. A variable or header marked secret goes into the vault: it is never shown again, never stored with the server, logged, put in the command to the Node or kept in the Node's journal, and the Node takes it from the Hub only when the harness opens.
- Skills are `SKILL.md` instructions (a name, when to use them, the steps), written where the bot's harness reads skills before a session opens. Whether a harness reads skills, and where, is part of its adapter's declaration (`skills`); Claude Code and Codex do. A new skill can be filled from a pasted `SKILL.md`.
- Remote agents (A2A): add an agent by its Agent Card address (a host alone is looked up at `/.well-known/agent-card.json`); its name, description and skills are shown before it is kept, and a key it needs goes into the vault. A bot that uses one gets a Steve tool, `steve_a2a_<name>`, that sends the agent a task and brings back its answer and artifacts (asking again while it is still working, for up to 100 seconds, then handing back the task id to ask later). It is the same for every harness.
- Steve · built-in: Steve's own tools are shown as one MCP server, always on, with its tools folded inside and what each is for (and, on a bot's tab, how often that bot called it in 30 days), instead of the grid of tool cards. The new memory tools are listed too.
- Steve from outside: Claude Desktop, Cursor or another agent can connect to the Hub's `/mcp` with one of your access tokens (`Authorization: Bearer stt_…`), also from another machine. It gets the tools that need no Steve session: find and read items, hand Steve new work (`steve_item_create`), add to an item (`steve_item_supplement`), the knowledge base, your memories (to read) and the session list. **Capabilities · MCP servers** shows the address as the Hub is configured to be reached, makes a token (shown once) and gives a copyable configuration for a generic MCP client, Claude Desktop, Cursor and Claude Code.
- Steve as an A2A agent: its Agent Card is at `/.well-known/agent-card.json`, and `POST /a2a` with an access token takes `message/send` (a new task becomes an item; a task id adds to that item), `tasks/get` and `tasks/cancel`.
- API: `/api/capabilities/{mcp-servers,skills,a2a-agents}` (with `POST …/a2a-agents/preview`), `GET /api/bots/{id}/capabilities`, `PUT|DELETE /api/bots/{id}/capabilities/{mcp|skill|a2a}/{entry}`, `GET /api/capabilities/steve`. Migration 65 adds the library (`mcp_servers`, `skills`, `a2a_agents`, `bot_capabilities`) and moves the per-bot servers and skills of migrations 62 and 63 into it, assigned to the bots that had them. See "Capabilities" in `docs/deployment.md`.
