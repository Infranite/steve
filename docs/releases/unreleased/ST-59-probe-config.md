- 升级前先用新版本自己的启动检查核对 `steve.env`，不合格就在动手之前停下。新增 `steve-hub --check-config`：按真实环境做一遍正式启动时的所有配置检查，包括监听地址、`STEVE_ALLOW_ANY_HOST`、本机 Node 模式、保险箱密钥存储，以及 `STEVE_HOST` 里的每个地址是否属于这台机器。它不打开数据库，也不占用 Hub 的端口。`ops/local-release.py deploy`（一键升级也走这一步）和托管模式的升级都会在排空之前先跑这个检查。检查不通过时，部署直接拒绝，不排空、不停服务、不切换，当前版本照常运行，并写明要改哪个设置。以前的试启动用的是临时地址和端口，看不出新版本会拒绝的监听地址，结果是切换之后新版本起不来，也不会自动回滚。
  - 0.2.66 起，`STEVE_HOST=0.0.0.0` 或 `::` 必须同时设置 `STEVE_ALLOW_ANY_HOST=1`，Hub 启动时仍然会拒绝，这一点不变。如果现有安装的 `steve.env` 里还是 `0.0.0.0`，现在部署会在开始前停下，提示你二选一：加上 `STEVE_ALLOW_ANY_HOST=1`，继续监听所有网络；或者把 `STEVE_HOST` 改成 `127.0.0.1` 加上需要访问 Hub 的地址，例如 `127.0.0.1,100.64.0.2`。改好后重新部署即可。0.2.66 的说明里写的“升级会失败回滚”不准确：那时新版本切换后直接起不来，需要手动修改。
  - 比这一版更早的版本没有 `--check-config`，部署到这些版本时不做这项检查，仍然只靠试启动。
