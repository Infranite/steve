Design confirmation is now a switch on the item, **Design confirmation** in the item's properties, off by default. Steve no longer guesses it from words in the goal such as "先出设计" or "设计通过后再实现", so an item whose goal only mentions a design is delivered for acceptance like any other. Only the instance's owner can turn it on or off, on the item page or with `PUT /api/items/<id>/design-gate {"on": true}`. Bots, MCP tools and YOLO have no way to change it. When it is on, a delivery stops at the design card (implement the design, keep the design only, or revise it), and YOLO still never answers that card. The delivery text is always saved as a design file Steve can verify, so an external link or a file that doesn't open in the browser next to it no longer gets the delivery refused.

When Steve refuses a delivery, the reason now shows in the item's activity, and the next time Steve continues the agent it passes the reason on. If a delivery is refused twice in a row for the same reason, the item comes to you instead of the agent being asked to deliver again. `STEVE_TAKEOVER_SAME_REFUSALS` sets the number of refusals (default 2, 0 turns it off).
