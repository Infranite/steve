The macOS client now has a native toolbar showing the current Hub, page and confirmed selected workspace, with Hub controls, connection details and an Attention entry point. Its menu-bar panel emphasizes context and navigation instead of operational counters. Native Settings and a Navigate menu accompany a single restorable main window: closing it keeps the menu-bar client running, and quitting the client does not stop the Hub. Pairing links still require native confirmation.

An additive bridge v2 carries page metadata and acknowledged, Hub/workspace-scoped navigation. Only an explicitly opted-in macOS shell hides the duplicate web Hub switcher; browser, older-native and iOS navigation remain available. Navigation errors are visible, and unsupported deep targets fail rather than claiming success. Native Hub switching waits for the current page to approve leaving; unsaved edits and in-flight writes also block workspace-scoped navigation before any workspace change. Missing or stale page approvals never switch the Hub.

This is the shell foundation, not background reminder delivery. Attention separately labels Steve replies, pending work, completions/deliveries and connected-channel messages as unavailable until their personal reminder data is connected. It shows no invented unread counts, requests no notification permission and delivers no background notifications.
