Task worktrees no longer pile up on disk.

- When an item closes, Steve frees its build and dependency caches (`target/`, `node_modules`, and anything else git ignores that is marked as a cache). It removes the worktree once that loses nothing: the worktree is clean, and its branch has landed in main or the item is archived. Branches stay, and a removed worktree is rebuilt from its branch when the item continues. Branches landed by rebase or squash now count as merged. Before, those worktrees were kept forever. (ST-45)
- Nothing is touched while one of the item's sessions is busy, a process runs inside the worktree, or there are uncommitted changes. Caches are first moved into `worktrees/.trash` and deleted outside the Hub's lock. An interrupted pass is finished by the next one, and each item's timeline records the space freed.
- A check every ten minutes also frees idle items' caches when free space drops below `STEVE_DISK_LOW_GB` (default 40). Below `STEVE_DISK_FLOOR_GB` (default 10), no new worktree is made: the item fails with a clear reason, and you are notified once.
- Settings → 数据与隐私 → 工作区与磁盘 shows each worktree's size and caches, the free space against these thresholds, and folders no item points at. It also has a reclaim-now button. Only the instance owner sees this section.
- `STEVE_GIT` selects the git binary Steve runs. Debug builds of the Hub keep line tables only, which makes a test build about 19% smaller.
