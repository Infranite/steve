- A project's page has two tabs, Overview and Settings, and the description sits under the project's name. The overview leads with:
  - **Items**: the open ones, waiting on you first, then failed or stuck, then running, filled up to six with the latest finished. A merge batch in progress sits under them with "Merge and release now".
  - **Last 7 days**: items done, changes merged and versions released (for a git project), failures by kind, estimated cost, agent time and the time items waited on you. "Open in statistics" opens the stats page for this project. This replaces the "last 30 days" line in the header.
  - **Repository and delivery**: one line each for the folder and machine, the repository and branch, the linked GitHub repository, how changes merge and how they are released. Under it, folded, **Repository conventions** lists what Steve found in the repository: the checks before merging, and what needs coordinating when merging (version tags, release notes, migrations, lock files).
- Settings holds the "tell Steve" field, the name and description, the default Bot, branch-per-item, YOLO and done-when options, the merge lane's batch window (or the merge queue's settings) and the GitHub link. The merge section loads in about a third of the time, because the Hub reads the GitHub branch rules while it fetches the project.
- People can have a photo. On your own page (我) or a contact's page, click the avatar to upload a PNG, JPEG or WebP image up to 10 MB. Steve crops it to a 256-pixel square and stores it with the Hub's other files. Your photo also shows on the account button in the sidebar, and contacts' photos show in the contacts list.
- The 我 page and contact pages have a new layout: avatar, name and one line with the organisation and title, and a description cut to three lines. "Steve 记得的你" lists everything Steve knows about you in one list, each value editable in place with its disclosure level, and 补充 to fill in an empty one. The 资料完整性 section is gone. Sections with nothing in them are hidden.
- API: `PUT /api/contacts/:id/avatar` takes the image as the raw request body or as the multipart field `file`, and `DELETE` removes it. Both return the contact, whose `avatar` is now `{"file": "<id>"}`, served by `GET /api/files/:id`. Other image types get 415 and images that are too large get 413.
