Settings · 关于 now says plainly when this installation can't be upgraded from the page, why, and what to do instead, rather than leaving out the upgrade button without a word. (ST-55)

- A box headed "不能在这里一键升级 · <installation>" replaces the one-line note. It shows the Hub's reason for that installation: a locally signed build (`ops/local-release.py`) reads its keys from the Keychain with its own signing identity, which the generic GitHub Release bundle doesn't have; a `ops/release.sh` install, a source build and an external deployment have no managed upgrader to switch and restart them. Below it: follow the steps further down when a new version is out, or press 检查更新 first, and, for a locally signed build or a release-script install, what it would take to get one-click upgrades (`STEVE_VAULT_KEYSTORE=dir` and `ops/run-managed.sh`, see `ops/UPGRADES.md`).
- The reason used to be "当前安装未使用 managed supervisor" for every unmanaged install. `GET /api/updates` and `steve_upgrade status` now give the reason for the detected installation, and `steve_upgrade status` also names it (`install.kind`). A refused `steve_upgrade request` returns the same reason.
