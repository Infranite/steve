- Bot sessions now load eight core tools plus their Bot's pinned tools instead of every capability schema. A short catalog in the brief and deterministic `steve_tools_search` discover enabled tools by keywords, source, read/write kind and resource; `steve_tool_call` validates arguments against the tool's JSON Schema before dispatch. MCP definitions preserve annotations and include Steve source/resource/as-you metadata.
- The Hub is the sole MCP tool entry point and shares plugin connections across sessions. Plugin configurations and credentials are no longer forwarded to session Nodes or harnesses. Local stdio servers now run on the Hub host through the Node sandbox API: install their commands/dependencies there and configure explicit resource paths. HTTP and legacy SSE servers are also reached from the Hub; unavailable sources report diagnostics without removing other tools.
- Workspace APIs can pin individual tools, whole MCP servers or A2A agents per Bot (up to 32 pins), and report 30-day per-tool discovery/call counts. Pins do not grant capability access. Outside MCP clients get the same search/call pattern within their existing restricted allowlist, without access to Bot plugins. Rich plugin results currently cross the bridge as text; timed-out writes are not automatically retried.
