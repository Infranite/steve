An opt-in Digest Bot now organizes stored conversation windows through ordinary Bot schedules, harness sessions and discoverable tools. It batches conversations, confirms matter/memory associations, records personal todos with source evidence, and writes validated chunks with durable progress, one complete-window summary, persisted change reports and guarded undo. New and replacement memories keep the existing confirmation flow; deterministic alert counts stay intact. It does not automatically fetch history or attachment bodies, deliver notifications, or add a dedicated messages page.

Schedules can explicitly authorize a member's own requester identity for ordinary item-mode execution. Existing schedules without requester keep service access; personal schedules require the requester's edits and live membership, and deleting their Bot revokes that authorization. Digest tools use the data owner's real caller identity, including in multi-member workspaces, rather than treating a service run as the owner. Setup and recovery are documented in the deployment guide.

Ordinary module tools now preserve the authenticated session principal across Digest, Knowledge and Contacts instead of aliasing callers to a workspace owner. Connector tools follow the same recorded session identity and recheck live membership, so editing an item's requester cannot lend another session personal account access. Item knowledge context uses the explicit requester and live membership; service runs and departed members cannot borrow private knowledge, even in a one-person workspace.
