The macOS client now monitors personal attention for the confirmed account and selected workspace independently of its web window. The toolbar and menu bar keep Steve replies (messages), pending work (cards), completions/deliveries (entries) and channel messages (conversations) separate; unavailable, stale and sign-in-required states are not shown as zero. A Dock dot indicates attention without adding incompatible counts together.

System notifications are off by default. Enable them in native Settings and use the explicit permission button to ask macOS for access. Category toggles, category-only privacy previews, sound and per-conversation local overrides are available; channel notifications otherwise follow the Hub's notification setting, and quiet is not mute. These local controls do not change server read or mute state. The app respects system notification settings and does not request critical or time-sensitive delivery.

The first successful snapshot silently establishes a baseline. Native-scoped persistent event checkpoints prevent reconnect/relaunch replay; invalid or full deduplication storage pauses banners instead of forgetting history. Logout, profile removal and account changes remove the affected local records and delivered notifications. Closing the main window keeps monitoring the last confirmed workspace; quitting the client stops monitoring without stopping the Hub.

Notifications contain only scoped identifiers and generic/category text, not message bodies or credentials. Opening one restores the main window, verifies the native account, selects the Hub/workspace and opens the actual reply, decision, expanded delivery entry or channel conversation. Foreground suppression applies only to matching entities actually visible in the focused current document, not to an entire page. Older Hubs without the personal-attention API remain explicitly unsupported.
