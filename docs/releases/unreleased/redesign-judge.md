Items gain a completion judge, in shadow. When an item's turn has ended and the Hub sees nothing more coming for it, the judge decides whether the work is done and records what it would do next. Nothing acts on that yet: it never closes, reviews, wakes or merges an item, and who can send, merge or close is unchanged.

- A turn is judged only when it has settled: no turn running or retrying, no dispatch whose receipt is missing, no queued input, card, wait, pause, Stop of yours or busy collaboration, and the Node not away. Otherwise it is looked at again later. Each turn is judged once, per cycle, session and goal version. A verdict for a turn that is no longer the current one, or whose inputs changed while the judge ran, is thrown away.
- Verified facts come first. A merged pull request, a passed build or a live deploy settles its criterion without a model. What the agent only reported never counts as a fact. A model is asked only about what facts can't settle. It must answer with one of five verdicts (done, not done, waiting, needs you, can't tell), giving a status for every criterion. Anything else counts as a failure. After three failures in a row, the judge gives up and the item stays as it is.
- The judge's model is a new setting, "Completion judge", in Settings · Models. By default it avoids the working Bot's own model. Each verdict records the harness and model that actually answered, and whether that model was a different one. Each finished task turn now costs one short model call, unless facts or rules settle it. To record only what facts and rules decide, set the work policy entry `judge_model` to 0.
- The judge runs on its own timer, one pass at a time, 30 seconds after the last one ended (work policy entry `judge_every`). A slow or hanging judge call never delays the stall cards, the Release build checks or the pull request checks.
- The item API (`shadow.judge`) and the item's Debug view show the latest verdict and what it would trigger. The derived state gains the row "Stopped; being judged".
- A migration adds an empty table for judge candidates and new columns to the judge results. It runs by itself and is fast on a large database.
