- Hub 与 Node 之间的连接加了几道防护，正常使用不受影响：
  - 同时处于握手阶段的连接最多 64 个，超出的直接回 503，Node 稍后会重连；
  - 每台 Node 提交事件的速度有上限（瞬时 64 MiB，之后每秒 1 MiB），超出时 Hub 回答“繁忙”，事件留在 Node 的日志里稍后再发，不会丢；
  - 对端不再读取数据时，写入在心跳超时后放弃并断开，不会一直卡住；
  - Node 读取文件的单次大小限制在一帧能装下的范围内；
  - 大量无效配对码不会再把正在被尝试的配对码的计数一并清空；
  - 对端发来的关闭原因和错误说明在写日志和显示前去掉换行等控制字符，并截断到 500 字；
  - 修正了 Node 事件守卫对 Job 主体的检查：之前查的是回合的 attempt 表，现在核对 job 及其 attempt 都属于这台 Node。
