Source replies now use a durable output-intent ledger and the existing channel outbox, with deterministic same-channel routing, explicit reachable channel switches, per-person manual preferences and reply-based preference learning. Repeated requests with the same key report the original delivery instead of resending it; uncertain outcomes retain the existing adapter deduplication/reconciliation rules. Requester membership, personal account ownership and the pinned route are rechecked before queued sends.

Authenticated clients can submit and inspect deliveries through `/api/deliveries`; `steve_reply_source` also accepts a stable key and an explicit destination. Structured content has a lossless Markdown/text fallback, while platform rendering remains in adapters. This is the initial source-reply/explicit-send path, not the full notification system: notification tiers and routing, digest subscriptions, activity feeds, read synchronization and unification of arbitrary connector writes remain to be connected.

Explicit channel cleanup now includes output-intent content and foreign keys: text purge retains only routing/idempotency/receipt metadata, while full cleanup removes owned deliveries and detaches deleted reply/preference references atomically. Retrying the same source reply after a conversation voice change returns its original delivery instead of reinterpreting its identity.
