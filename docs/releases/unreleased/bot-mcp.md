- A bot can have MCP servers of its own. On the bot's **Capabilities** tab, the new **MCP servers** section lists them. Each one is a local command (stdio) or an HTTP or SSE endpoint, with environment variables or headers, and has its own switch, edit dialog and delete. Every session of the bot gets the enabled servers through ACP (`mcpServers` of `session/new` / `session/load`), next to Steve's own tools, the same way for every harness, on the Hub's own Node and on remote Nodes. A change applies the next time a session's harness opens.
- A variable or header marked secret goes into the vault. It is never shown again, and it is not stored with the server, written to the audit log, put in the command sent to the Node or kept in the Node's journal. The Node takes the value from the Hub when the harness opens, and each use is in the vault's use log. Saving a server without a secret's value keeps the stored one. See "Bot MCP servers" in `docs/deployment.md`.
- The Capabilities tab also names A2A as planned. It is not available yet.
- API: `GET|POST /api/bots/{id}/mcp-servers`, `PATCH|DELETE /api/bots/{id}/mcp-servers/{server}`. A bot's view (`/api/state`, bot answers) lists its servers as `mcp_servers: [{id, name, transport, enabled}]`. Migration 62 adds `bot_mcp_servers`.
