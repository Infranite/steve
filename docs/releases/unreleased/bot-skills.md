- A bot can have skills. On the bot's **Capabilities** tab, the new **Skills** section next to MCP servers lists them, each with its own switch, an edit dialog (name, description, and Markdown content with a preview) and delete. A new skill can be filled from a pasted `SKILL.md`. A skill is written as `<name>/SKILL.md` where the bot's harness reads skills, in the session's own harness directory, before the session opens; a change applies the next time a session's harness opens. Skills Steve wrote and that were since removed or switched off are taken away again; skills the harness or a person put there are left alone.
- Whether a harness reads skills, and where, is part of its adapter's declaration (`skills`, a directory under its state directory). Claude Code (`$CLAUDE_CONFIG_DIR/skills`) and Codex (`$CODEX_HOME/skills`) both read them. A harness adapter in the manifest can declare its own; for a harness without one, the page says it does not use skills. A session without a harness directory of its own (`STEVE_PRINCIPAL_STATE=off`) gets no skills. See "Bot skills" in `docs/deployment.md`.
- Steve's own tools on the Capabilities tab now each say what they do (items, sessions, work graphs, diagnostics, upgrades, devices, replies, knowledge, contacts, vault, GitHub, mail and the first meeting), instead of a generic "a tool Steve provides".
- API: `GET|POST /api/bots/{id}/skills`, `PATCH|DELETE /api/bots/{id}/skills/{skill}`. The harness list (`runtimes` in `/api/state`) says `skills: true|false` for each adapter. Migration 63 adds `bot_skills`.
