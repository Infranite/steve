Needs a minor release: the incoming-reaction migration advances the database reader floor; take a consistent database backup before upgrading if you need to return to the previous release, and restore that backup when downgrading.

Incoming reactions now retain their actor, emoji, time and provenance, appear in conversation records and reach the reply composer. An identified owner's explicitly manual reaction handles only the reacted-to message in a group, or that message and the same sender's earlier unanswered DM burst. Later messages remain eligible for drafts, including when their timestamps equal the reacted-to message's.

Waiting drafts and handoffs close as “你已用表情回应”; YOLO approval, retry and queued sends recheck the handling state. Other people's, automated and unknown reactions are context only. Removal is durable and cannot revive expired cards or resend an answer already sent; explicit human approval and existing sending/disclosure rules retain their precedence.

The Hub accepts native Feishu created/deleted events and optional ext_ws reaction feed items. Native Feishu user events cannot prove manual provenance and remain context only; the separate bridge must establish and forward manual provenance before reactions can suppress drafts. See the deployment guide's “Incoming reactions” section for the supported scope.

Channel producers can supply durable action revisions and distinguish provider times from observation times. Revisions preserve same-millisecond deletion/re-addition and stale replay ordering; observation times are labelled in the record. Automated actions on personal accounts retain the account's human identity. Gateway-specific decoding, write receipts and attribution remain outside the public Hub.
