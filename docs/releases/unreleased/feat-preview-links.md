- Preview links for any file or folder. `steve login` then `steve publish <file|folder> [--title] [--entry] [--interactive]` uploads a file (a folder is packed as a ZIP) and prints its delivery page, which opens from a phone through the Hub's public address. Publications without an item are listed, newest first, in **我的发布** (More, the command menu, `#/publications`), with sharing and revoking.
- Bots can call `steve_deliver_file` in any session with a working directory — chats, conversations and scheduled runs, not only items — within the same directory and Node read rules.
- Interactive HTML prototypes, opt in per delivery: the owner switches it on the delivery page (or the publisher with `--interactive` / `interactive: true`). The page then runs the package's scripts in an isolated sandbox (an opaque origin with no access to Steve, its cookies or storage, and no network beyond the package's own files). Static stays the default, and public shares follow the same switch.
- The delivery page is fully in your language, says plainly when a link only opens on the Hub's computer, and explains when a static HTML page needs scripts instead of showing an empty frame. It now also plays audio and video, renders Markdown with the package's own images (`.md` files are recognised by extension), opens a package at its README when it has no HTML, and highlights code by file type.
- A design delivered as an openable file with `steve_deliver_file` and listed in `steve_deliver` outputs now satisfies the design-confirmation step, whatever kind it was listed as.
