- Releases no longer push to `main`. `ops/cut-release.py cut` now brings the release notes in through a release pull request (`release/vX.Y.Z`): it waits for that pull request's CI, rebase-merges it, and pushes only the tag. This lets `main` require pull requests and the `CI gate` check. A release whose pull request merged but whose tag never landed is finished by the next `cut`.
- CI skips the Rust and Apple jobs for a pull request that changes only `docs/releases/` and stands on a commit whose CI passed, as it already did for such a push. The CI workflow also runs for GitHub's merge queue (`merge_group`).
- CONTRIBUTING.md and AGENTS.md describe the flow: branch from the latest `main`, open an issue first, then a pull request that closes it. Nothing is pushed to `main` directly.
