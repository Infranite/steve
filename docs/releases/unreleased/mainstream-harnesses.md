- Steve now has 16 built-in ACP coding CLIs instead of two. Besides Claude Code and Codex: Gemini CLI (`gemini`), GitHub Copilot CLI (`github-copilot-cli`), OpenCode (`opencode`), Qwen Code (`qwen-code`), goose (`goose`), Kimi Code (`kimi-code`), Grok Build (`grok-build`), Kilo Code (`kilo`), Factory Droid (`factory-droid`), CodeBuddy Code (`codebuddy-code`), Cursor (`cursor`), Kiro CLI (`kiro`), Mistral Vibe (`mistral-vibe`) and Qoder CLI (`qoder`). Each is described as data on its adapter: its permission modes, thinking efforts (now including `off` and `ultra`), quick models, its own state directory for each principal, how a terminal resumes or forks its sessions, and how it reports tokens. A cost a harness reports in another currency than US dollars is left out of the dollar figures.
- `steve setup` lists the 12 adapters that come from npm and ticks the CLIs it finds on `PATH` (Claude Code and Codex when it finds none); `steve adapters status`, `install` and `upgrade` manage all 12. Cursor, Kiro CLI, Mistral Vibe and Qoder CLI come from their own installers and are found on `PATH`. Every built-in entry can be pointed elsewhere with its `STEVE_ADAPTER_*` variable, given a default model with `STEVE_DEFAULT_MODEL_*`, or overridden in `harness.json`, which can now also declare `resume_cli`, `fork_cli` and `outer_sandbox_args`.
- A session's resume card gives the harness's own fork command where it has one. The Bot page, Settings → Models, the model picker and Devices → runtimes list every harness the Hub reports, and Devices → runtimes shows an install hint and the sign-in methods. Harnesses and models from GitHub, Cursor, Moonshot, Mistral, OpenCode, Qwen and CodeBuddy show their marks; the others show the terminal mark. A model list follows the interface language.
- When a principal's harness state is set up for the Node's owner, the declared settings files are copied as they are, never through a symbolic link. A session of anyone else no longer sees the owner's harness homes (logins, tokens, history) inside the Node's sandbox. On Linux, read-only research and Steve's own read-only calls now run in bubblewrap, as they run in `sandbox-exec` on macOS.
