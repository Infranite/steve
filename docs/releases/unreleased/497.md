Needs a minor release: backup receipts and restore commands now use restic snapshot IDs. If the installed macOS updater still expects a backup directory, deploy from the verified, prepared bundle with its native maintenance command (see “First upgrade through an older runner” in the deployment guide).

Steve now uses one encrypted, deduplicated backup repository under `backups/restic` for daily, manual, upgrade, destructive-operation and diagnostic copies. The Data and privacy page shows total repository use, and Health warns when its destination is low on space. Automatic backups retain the latest copy of each purpose and use time and count limits. Manual snapshots stay until you remove them.

Keep the repository password and Vault recovery keys separately from off-machine backups. Existing backup directories stay in place. To recover an earlier copy, stage the database named in its `manifest.json` and the contents of its `files/` or `files.tar` in a private directory. Check the recorded database SHA-256 and run SQLite `quick_check` before restoring. The Backups section of `docs/deployment.md` covers offline recovery. Retire earlier copies manually after verifying the new repository.
