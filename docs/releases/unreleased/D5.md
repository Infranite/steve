- 队列里的消息点“立即发送”时，如果实际没有发出，会显示“等待”和原因，不再显示“已发送”：升级维护期间（包括维护中途 Hub 重启后）提示“Hub 正在维护，维护结束后发送”；会话暂时接不了消息（比如还在打开）时提示“会话正在准备，就绪后发送”或“暂时发不出去，稍后自动发送”。消息留在队首，能发时自动发出。
- 新增实验性的本机 Node 运行方式：由 Hub 决定做什么，Node 负责执行 harness。默认关闭，只有设置 `STEVE_NODE=local` 后才启用；启用后也只有新建的会话绑定到本机 Node，以前的会话继续用旧运行器。关掉 `STEVE_NODE` 后，已绑定 Node 的会话的消息只排队，不会交给旧运行器，重新开启后接着发。开启后运维能得到：
  - 结果不确定的执行（比如 Hub 或 Node 中途重启）标记为“等待对账”，绝不自动重跑；点停止可以放弃它，之后排队的消息在重新打开的会话里发出。Hub 启动时先与 Node 对账，对完才派发。
  - 停止只作用于当时正在运行的那次执行，旧的停止不会打到新的执行上；回合还没被 Node 接收时点停止，也不会因为取消先到而丢失或误发。停止或取消被拒后可以再次停止。
  - 审批卡片按请求的有效期自动关闭，到期仍在等待的请求由 Node 拒绝；一张卡只有一条回复，迟到的回复不会落到后面的回合上；Node 拒绝的回复记为已过期，不算已答。
  - 模型、推理强度和 YOLO 模式的变更通过 Node 在会话空闲时生效，不改动正在运行的回合，Hub 重启后也不会丢；结果未知时会话保持占用、不会自动重发。
  - YOLO 按 Node 实际绑定的目录和它上报的 harness 进程判断审批；不知道这些信息时（比如远程 Node）把卡片留给人处理。
  - Steve 工具调用的编号跨 Node 重启也不重复，不会把旧调用的结果当成新调用的结果；开始前被取消的调用记为已拒绝、未执行。
  - 升级维护的暂停对 Node 会话同样有效，重启后也一样，队列不会在暂停时被发空。
  - 会话结束后由 Node 释放；回合进行中结束的会话在回合结束后释放。Node 拒绝释放或打开会话时，会话不会卡在“释放中/打开中”，用户能看到原因。
  - Hub 关闭时一并停掉本机 Node 和它的 harness 进程。
- 数据库迁移 036（Node 事件收件箱的索引，已应用的旧事件定期清理）和 037（Node 会话的审批请求和待生效配置）。
