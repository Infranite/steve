- 多 Hub 切换与设备配对现在是网页端自己的功能，任何浏览器里都有：侧边栏顶部的 Hub 切换器（手机上在「我的」页），登录页与「无法连接」页的 Hub 列表，「设置 · 访问与客户端」里的完整列表，以及命令面板（`⌘K`）。
- 添加 Hub 时填地址或粘贴配对链接都可以。同一主机不同端口、或 HTTPS 的 Hub 在当前页面内直接切换；其他主机上的 HTTP Hub 会跳转到那个 Hub 自己的页面，已保存的 Hub 列表随地址一起带过去，经你确认后才加入。
- 配对二维码现在是一个任何浏览器都能打开的链接：手机用系统相机扫码即可在浏览器里完成登录，不需要安装 App，链接还能复制到另一台设备的「添加 Hub」里。二维码 5 分钟内有效、只能用一次；Hub 有多个地址时可以选择设备够得着的那个。
- 同一台主机上的多个 Hub 现在可以同时保持登录：Hub 的 Cookie 名带上了自己的端口。升级后，已登录的浏览器需要重新登录一次。
- 开启了独立网页端口（`STEVE_WEB_PORT`）时，用浏览器打开 Hub 的 API 端口会自动转到网页端口。
- 未设置 `STEVE_PUBLIC_URL` 时，默认地址跟随 `STEVE_PORT`，不再固定为 8440。
- 浏览器重新登录同一个 Hub 时，被替换掉的旧登录会随之失效，不再在客户端列表里越积越多。
- 页面开着时与 Hub 的连接断开，页面顶部会说明并继续重连，旁边可直接换到其他 Hub；连不上的地址与「不是 Steve Hub」的地址现在是两句不同的提示。
- 添加 Hub 时填的是它的网页地址（地址栏里看到的那个，网页端口与 API 端口分开时两者不同）也可以，页面会找到背后的 Hub。
- 页面只为自己所在主机上的 Hub、或当前正在使用的 Hub 领取配对码；指向其他 Hub 的配对链接会先提示，再转到那个 Hub 自己的页面完成。用 `#/hub/pair` 链接打开配对窗口时，点一下才会生成二维码。
- 浏览器不保留其他站点上 Hub 的登录状态时（Safari、隐私窗口），登录页会直接说明并提供前往那个 Hub 自己页面的入口，不再悄悄回到登录页。
- macOS / iOS 客户端（`apple/`，需自行从源码构建）尚未跟进这次调整：客户端里原有的 Hub 列表与配对窗口还是旧实现，扫码只认 `steve://pair` 码，客户端自己的配对窗口与本版本的 Hub 不兼容。客户端改用网页端同一套界面的改动随后发布。
