- Every memory on the Knowledge page says what it is about and where it came from, and both are links. The subject opens its view. The source opens the day of the main conversation, the item, the agent session, the mail thread or the event it was learned from, and hovering over it shows who noted it and the words it was based on. Each memory also says how many times Steve has used it. Memories in To confirm link to their sources the same way.
- The Long-term memory and Knowledge entry tabs are memory panels. They group memories by kind with filter chips. You can reword a memory in place, mark it stale (kept but no longer used) or use it again, and delete it with a few seconds to undo. Closing or reloading the page during those seconds still deletes it. A new memory picks its kind (rule or preference, fact, event or summary) in the panel. Memories show in English too, and memories you wrote say "Written by you" in your language.
- A new Subjects tab lists the people, projects and Bots Steve knows something about, with how many memories, documents and unconfirmed memories each has. Opening one shows what Steve knows and where it learned it, and the sessions, answers and searches that used it lately. A project also gathers its item records and the memories its deliveries left.
- The Sources tab shows each document source's state (OK, syncing, error or paused). A new section, Where memories come from, counts who writes memories (you, the main conversation, item deliveries, agent sessions, a Bot, mail, plugins) and how many still wait for you. It also says whether search finds things by meaning with OpenViking or uses the built-in keyword index.
- A new Tidy-up tab runs a knowledge steward on a schedule (daily, weekly or monthly), or at once. The steward merges memories that say the same thing, settles contradictions (the newest explicit correction wins), marks outdated ones stale, and fills in who a memory is about or which item it came from. It is an ordinary Bot made from the new Knowledge steward template, on an ordinary schedule, so its rules are on its Bot page and its time under Automation › Schedules.
- Each tidy-up run lists every change with its reason. A merge waits for you in To confirm. A conflict the steward could not settle asks which memory to keep. Every other change has Undo, and an answered conflict can be reopened.
- Agents on every harness have two new tools: `steve_memory_list` lists memories with their sources and use counts, and `steve_memory_tidy` makes the changes above. Changes any agent makes show up in the Tidy-up tab under the item they came from. Migration 64 records these changes and the merges.
