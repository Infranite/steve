- 扩展 API 升到第 2 版（`EXTENSION_API = 2`），按第 1 版编译的扩展需要重新编译。外部扩展现在可以为自己注册的渠道侧适配器挂上“每个连接运行什么”（`Mounted::lifecycle`），例如一条长连接或一个轮询：Hub 在连接接入、恢复、换凭据、暂停、断开时自动启动、重启或停止它，每个连接各管各的，一个停得慢不会拖住别的；运行失败按 5 秒到 5 分钟逐步退避重试，并记到连接的健康状况里（授权失效时转为“需要重新授权”）。扩展只能读写自己这个连接的数据（是否已被别的连接覆盖、消息是否已收到、自己的游标、某人在另一个系统里的账号）。
- 「飞书你本人」不再必须和飞书机器人一起装配：只装你本人时，Hub 照常启动，你的消息照常按原来的节奏读取。
- 内置飞书机器人的长连接启动失败时，现在会自动重试，并记到这个连接的健康状况里，不再只写日志；重试连上后，连接自动恢复为正常，不会一直显示出错。
- 以你本人身份发出的飞书消息又能撤回了：之前点“撤回”会提示“这个渠道不支持撤回”，或者转去用机器人撤回而被飞书拒绝；现在 Hub 记住每条消息是从哪个连接发出的，以你本人发出的消息用你本人的授权撤回，之后群里改由机器人发言也不受影响。
- 外部扩展可以为自己的渠道侧注册“以你本人身份”的发送、表情回复和撤回（`ActAsUser`），以及消息里图片和文件的下载（`MediaFetch`）；内置的飞书机器人和飞书你本人也走同样的接口，行为不变。
- 外部扩展注册渠道侧时要声明它的人用哪个账号体系、能做什么（撤回、表情回复等）、消息有没有平台 id、时间精度和接入方式；声明和实际提供的能力对不上时（例如声明能撤回却没有实现），Hub 启动时直接报错，不会等到用的时候才失败。
- 授权「飞书你本人」时，机器人之前为你建的“未确认”联系人会并入“我”：现在从任何入口授权都会这样（包括通用的“新建连接”和设备码），不再只限于“授权你本人”按钮。别人亲手确认过的联系人仍然不会被自动合并。
- 需要配对的连接（例如「飞书你本人」和同一个应用的飞书机器人）在接入、换凭据、重新授权时都会检查配对：配对的必须是你看得到、没有断开、类型对得上的连接；只有一个可选时自动选上它。授权进行到一半时机器人连接被断开，这次授权会被拒绝，不会留下一个配对到已断开连接的“你本人”。配对可以用 `PATCH /connections/:id {app_connection}` 改；不需要配对的连接带上配对字段会被拒绝。
- 外部扩展可以声明自己的连接和哪种连接配对（`ConnectionProvider::pairing`），每条接入路径都按这个声明检查；能证明登录者是谁的连接会在接入时把其他渠道为这个人建的未确认联系人并入“我”（`claims_self`：用 OAuth 或设备码授权的“你本人”默认开启，凭据式的连接要自己声明，表示它为这个账号担保）；`AccountInfo` 还可以带上这个人在其他系统里的账号（`alias`），接入后一并记到“我”名下。
- 外部扩展的渠道侧报告发消息的人时，可以只给它自己系统里的 id，再附上邮箱等其他账号（`Sender::new(…).alias(…)`）：Hub 先按其中任何一个找已有的联系人，找到了就把没见过的账号也记到这个联系人名下，都找不到才新建一个未确认联系人。
- 授权进行到一半时改了配对（`PATCH /connections/:id {app_connection}` 换成另一个机器人，或去掉配对），授权完成后会保留你刚改的配对，不再被换回授权开始时的那个。
- 外部扩展可以在每条接入路径上先检查连接配置（`ConnectionProvider::check_config`，例如只允许 https 和 Hub 允许的主机）；检查不通过时直接拒绝，什么都不会保存。扩展还可以声明自己保存的配置版本（`config_version`）：同一个 id 的连接改由新的实现接管、或保存的格式变了时，旧版本保存的连接在 Hub 启动时转为“需要重新授权”，重新授权后按新版本保存。内置连接不受影响。
- 外部扩展的渠道侧即使拿不到平台消息 id，也能把消息交给 Hub（`InboundMessage::without_id`），并带上对方系统自己的投递 id（`source_id`）：同一次投递重复送来只记一次（不带投递 id 时，重复送来的会记成新的一条，扩展要自己按游标避免重复送）；同一条消息从这个渠道和机器人两边都收到时只记一条，不管哪边先到，也不管这个渠道先用哪个系统的账号报告发消息的人，机器人那边带来平台 id 后这条消息就改用它；同一个人连发两条一模一样的消息仍然是两条。各方的时间都精确到毫秒时，消息在一边被编辑过也不会多出一条。
- 以你本人身份发出、对方没给消息 id 的消息，读回来时会认出是自己发的，不会再记成一条新消息；机器人随后看到它时补上平台 id。扩展可以按投递 id 找回这条消息（`message_ref_by_source`），用来撤回、回表情或下载附件。Hub 为这类消息自编的 id 只在 Hub 内部使用，不会出现在界面和接口里，也不能由扩展冒用。
- 外部扩展可以注册自己的渠道侧，Hub 按它的声明对待它：渠道账号的来源和能力、联系人能不能被查到、`POST /channels` 新建渠道连接（表单式的直接接入，OAuth 式的返回授权链接，配对照常检查）都看声明，不再只认内置飞书的两个适配器。没有机器人时用 `POST /channels` 授权飞书你本人，现在和通用的“新建连接”给出同样的提示。
- 消息里的图片和文件只交给收到它的那个渠道侧去下载；那个渠道侧的连接都断开后显示“已断开”，不会再拿着别的渠道侧的文件标识去试。
