- 新增插件商店，在「设置 · 插件」：页面先列出需要处理的事（插件没在运行、插件库读取失败），然后是已安装的插件、插件库里可以安装的插件，最后是插件库本身。实例管理员在这里添加插件库（GitHub 仓库地址、索引文件的 `https://` 地址，或 Hub 所在机器上的一个目录），Steve 读取库里的 `steve-store.json`，列出其中的插件，可安装、升级和卸载。官方插件库 [Infranite/steve-extensions](https://github.com/Infranite/steve-extensions) 在新安装里默认列出，但在管理员点“读取插件库”之前不会联网；`STEVE_PLUGIN_LIBRARY` 可换成别的库，或设为 `off` 不带任何库。旧的 `#/plugins` 地址会转到这里。
- 插件是预先构建好的压缩包，安装时按库里写的 sha256 校验，不链接进 Hub，也不需要编译器；插件崩溃或被卸载不影响 Hub。安装渠道插件等于以 Hub 的用户身份运行它的程序，所以只有实例管理员能添加库和安装，请只添加你信任的库。
- 渠道插件：把 Steve 没有内置适配器的消息系统以你的身份接进来。任何已登录的成员都可以在已安装的插件上填自己的设置并接入，Steve 为这个人启动一个进程并建立一条外部渠道连接，之后它和其他连接一样出现在「账号」里；在那里断开连接会停掉进程并删除它的设置和数据。连接的 token 存在保险箱里，所以要先启用保险箱。
- 主题插件：插件包里是一份主题清单（和「外观」里内置主题同样的格式），只是数据，Hub 和浏览器都不运行其中任何代码。安装后，这个 Hub 上的每个人都能在「设置 · 外观」里选用它；客户端校验不通过的主题会在插件页标出原因，不会出现在选项里。卸载后，正在用它的设备回到默认主题。外观页也加了一条去插件页找更多主题的链接。
- 插件库的索引格式、两种插件要实现的约定（渠道插件的环境变量、`/ws` 地址、如何退出；主题插件的清单和 `any` 架构的压缩包）和磁盘上的位置（`<目录>/plugins`，日志在 `instances/<id>/plugin.log`）见 `docs/deployment.md` 的 Plugins 一节。
