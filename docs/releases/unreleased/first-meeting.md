- 实例管理员第一次打开一个空的 Hub 时，首次引导的最后一步改为“互相认识”：同意后 Steve 在主对话里先打招呼，问怎么称呼你、平时用它做什么，然后逐项征求同意再动手：从这台机器上已有的信息（编码助手留在主目录下的会话记录和全局指令文件、git 全局配置、主目录下的项目）整理你的资料并写进“我”；按各 harness 实际提供的模型，为分诊、起标题挑快的，为研究、起草、编排挑最强的；按你做的事建两到四个 Bot（已有的 Bot 能承担的不再另建）。每一项都先问你，每次写入都进审计日志，可以在 我、设置 · 模型、Bot 页查看和改回。
- 认识期间，你在主对话里说的话直接由 Steve 带着工具处理，不再先过分诊（点名 Bot 或事项的消息除外），所以全新安装后的第一句话不用再等分诊超时。
- 不想认识可以在引导里选“以后再说”、对 Steve 说“跳过”，或点欢迎语下面的“跳过认识”；这个选择记在 Hub 上，换浏览器不会再问。超过十二条消息没有结束，认识会自己结束。之后想重来，到 设置 · 通用 重新开始首次引导。
- 其他成员只看到原来的引导，没有“互相认识”。
- 没有做“互相认识”也不再让分诊等最强的模型：Steve 所在的 harness 报出自己的模型后，Hub 会把分诊、起标题、披露检查、流程 Bot 节点这四个高频小判断一次性放到该 harness 的快模型上（例如 Claude Code 提供的最新一款 haiku），只在这些用途还没有单独设置时写入。它就是 设置 · 模型 里的普通单独设置，改掉或改回“跟随 Steve”后不会再被写回。harness 没有报出快模型时一切照旧。设置了 `STEVE_MODELS_FAST` 的安装不受影响。
