Needs a minor release: existing macOS Nodes need a one-time administrator-approved service migration; the Hub cannot manage macOS Node deployment or removal remotely.

- After finishing the Node's sessions, run `steve node enable-boot` as its existing macOS user. This retires the login LaunchAgent and registers one system LaunchDaemon that runs as that user before desktop login. The pairing, identity and data stay in place. New macOS Nodes use the same command after setup and pairing. See the deployment guide for credentials, local upgrades and removal.
- Devices now shows why the Hub considers a Node offline and for how long, including when it has no evidence beyond the missing connection.
- After registration, select a new verified release with `steve node update --release <bundle>` without sudo. Devices distinguishes harness authentication failures from an offline Node.
