Needs a minor release: existing macOS Nodes need a one-time administrator-approved service migration; the Hub cannot manage macOS Node deployment or removal remotely.

- After finishing the Node's sessions, run `steve node enable-boot` as its existing macOS user and approve the one-time sudo prompt. This retires the login LaunchAgent and registers one system LaunchDaemon that runs as that user before desktop login. Migration corrects stale receipts from the running release or the newest verified installed bundle. The pairing, identity and data stay in place.
- Devices now shows why the Hub considers a Node offline and for how long, including when it has no evidence beyond the missing connection.
- Once the Node is running a signed boot release, upgrade it from **Devices** even when nobody is signed in. The supervisor switches release directories without sudo and the helper rolls back if the replacement fails to link. `steve node update --release <bundle>` also remains available locally. Devices distinguishes harness authentication failures from an offline Node.
