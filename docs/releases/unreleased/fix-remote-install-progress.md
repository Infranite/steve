- Installing a Node remotely over tailcat (Devices → Install remotely) now pairs. `steve setup node` passes the pairing code it was given in `STEVE_PAIR_CODE` on to the pairing. Before, the code was lost, and the install ended with "no pairing code".
- The install dialog now shows real progress: bytes downloaded and the speed, then the check of the installer; bytes sent to the target; and on the target, the install, pairing, adapters and service start. Each step shows how long it took, and a running step shows a live clock. The progress is kept by the Hub, so a page opened later shows the same install.
- An installer the Hub downloaded before is reused for the next install of the same version and platform. It is checked against the release's manifest again, and the Hub keeps the two most recently used. The cache is under `<STEVE_HOME>/tailcat/installs/cache`.
- A step that gets no data fails with a reason instead of hanging: 60 s with nothing downloaded, sent or answered, or 10 minutes with no output from the setup on the target.
- A failed install shows the step it failed at, after how long, and why, with a retry button. The address stays filled in. Starting a second install to an address that is already being installed shows the running one instead of starting it again.
- `GET /api/nodes/installs` lists your remote installs, newest first. Each step now has `kind`, `ended`, `elapsed_ms` and `progress`, and the install has `failed_step` and `address`.
- A Node home left by a setup whose pairing never made the Node's key, as a failed remote install leaves one, no longer blocks the next setup. Before, a newer release refused it as another version's installation, and another Hub refused it as a pairing sent elsewhere. Setup now continues it and drops the old Hub's pin. A home with a Node key or a registered service is still protected.
