- Hub 不再自己运行会话：旧运行器已删除，所有会话都在 Node 上运行。
- 升级后第一次启动时，旧运行器留下的会话会自动处理，不需要手动操作，Hub 也总会正常启动：
  - 能转到本机 Node 的会话，会用原来的 harness 会话 id 接着原来的对话继续。启动时不会一下子拉起所有会话的 agent：有排队消息或被打断的一回合的会话，等升级排空解除后才打开；其余空闲会话等下一条消息到来时再打开。
  - 旧运行器已经领取、还没发出的消息会重新排队，转过去后照常发出。已经发出的消息会带上“先核对再继续”的说明重新排队，不会被当成新请求重做。
  - 升级时被打断的那一回合会在 Node 上接着做一次，规则和以前重启后自动继续一样：事项已结束、已暂停、在等你处理、中断超过一天，或者半小时内已经自动继续过一次，就不会自动继续，会在会话里说明，需要时出一张卡片。
  - 旧运行器留下的未答复工具授权会失效，并在会话里说明；继续时 agent 会重新请求授权。
  - 不能在 Node 上运行的会话（工作目录已不存在、项目已归档、Bot 已停用或删除、Node 不支持的权限模式等）会结束，并在会话里写明原因。它排队的消息再也发不出去，会一起撤下并列出（包括旧运行器已经发出、重新排队待核对的消息）。如果它的一回合正被升级打断，事项上会出一张卡片说明原因，不会一直显示“正在做”。导入的只读会话不受影响。
  - 启动时暂时没能转过去的会话（例如当时本机 Node 没起来），之后每隔几分钟会再试一次；转过去后，它排队的消息会马上发出，不用等你再发一条。
- Node 不能接的新会话（例如工作目录不在 Node 可用的目录里）会立刻结束，并在会话里和事项上写明原因，不会一直等着。
- `STEVE_NODE_MODE=off` 仍然可以用来回退：已经在 Node 上的会话只排队，等重新开启后接着发；这时不能新开会话，也不能给没在 Node 上的会话发消息，会直接提示“本机 Node 已关闭”，Hub 不会自己去跑 agent。重新开启本机 Node 后，启动时会再把留下的旧会话转过去。
- `/healthz` 的 `node.legacy.sessions` 在本机 Node 开启时，启动后应为 0。
- 升级排空不再等待或停止 Hub 自己的 agent 进程（已经没有了）；返回里的 `acp` 固定为 0，`adapters_stopped` 固定为 true。
