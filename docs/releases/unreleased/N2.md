- 新增独立的 `steve-node` 程序，可以把另一台机器配对为 Steve 的节点：在 Hub 上生成一次性配对码（10 分钟有效，只保存其哈希），在节点上运行 `steve-node pair`（配对码从环境变量或标准输入读取，不出现在命令行），确认节点指纹后 `steve-node run` 即可连上 Hub。节点可以暂停、恢复、改名和吊销；吊销后连接立即断开，之后的连接一律被拒绝。
- 节点与 Hub 之间用一条 WebSocket 连接（默认要求 wss，可固定 Hub 证书；只有本机回环地址且明确开启时才允许明文）。断线后节点自动重连（Hub 一时繁忙或出错时节点不会退出，只有被拒绝时才停止），期间的事件由节点保存，重连后补交且只记一次；结果不确定的命令不会被重发。旧连接被新连接取代后不能再做任何事，一个节点也不能替别的节点的会话报告事件、调用工具或读取文件。
- 默认关闭：只有设置 `STEVE_NODE_LISTEN=1` 才会开放配对和节点连接。
- 会话可以交给远程节点执行，但只在明确指定时：同时设置 `STEVE_NODE_BIND=<节点 id>`（一个已确认、未暂停、由该工作区所有者配对的节点；普通成员配对的节点不会接到工作区的会话）后，新建的、不属于项目的事项的会话在该节点上用它自己的 harness 运行，工作区建在节点上；属于项目的事项、以前在 Hub 上跑过的事项和已有的会话都不变。审批卡片、停止、排队和 YOLO 与本机 Node 会话相同（YOLO 不知道远程节点的目录，卡片留给人处理）。
  - Hub 重启时远程节点上的回合继续运行，重启后补齐结果，不会重发。
  - 节点进程中途重启时，结果不确定的执行标记为“等待对账”，绝不自动重跑；对账完成前不给它派新活。
  - 节点被暂停时不再派新活，恢复后排队的消息接着发；暂停不会解除 Hub 的升级维护暂停，反之亦然。
- 数据库迁移 038（已配对的节点、配对码的哈希和节点审计记录）。旧版本会忽略这些新表。
- 本机 Node 的开关改名为 `STEVE_NODE_MODE=local`，`STEVE_NODE` 只表示运行 `.js` 适配器用的 Node.js 程序。0.2.50 的写法 `STEVE_NODE=local` 仍然有效（启动时提示改用新名字），不会被当成 Node.js 程序；同时设置两者时以 `STEVE_NODE_MODE` 为准。
