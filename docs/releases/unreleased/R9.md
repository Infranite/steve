Needs a minor release: removed STEVE_* variables are now rejected by --check-config and startup

Remove `STEVE_ITEM_PREFIX` from the Hub environment before upgrading, including empty assignments.
Set item prefixes in workspace settings instead. The Hub now rejects invalid flags, takeover
counters, idle-release values, disk-policy values and HTTP(S) URLs instead of silently keeping
defaults. Boolean flags use `0`/`1`; backups use `on`/`off`.

The Hub and authentication share one secret-file reader. Set either a direct variable or its
`_FILE` source; setting both is an error. Files must be regular UTF-8 files with Unix permissions
no broader than `0600`. Correct existing OIDC/OpenViking file permissions before upgrading.
Only final CR/LF are removed; spaces now remain part of file-based secrets. Configured sources
are validated even when an optional backend is off.

New file sources are `STEVE_PUBLIC_URL_FILE`, `STEVE_PUBLIC_URLS_FILE`, `STEVE_CLIENT_ORIGINS_FILE`,
`STEVE_OIDC_ISSUER_FILE` and `STEVE_OPENVIKING_URL_FILE`. `STEVE_OIDC_CLIENT_SECRET_FILE` and
`STEVE_OPENVIKING_KEY_FILE` use the same rules; OpenViking also accepts `STEVE_OPENVIKING_KEY`
directly. Credentials loaded by the CLI, vault and connectors keep their existing contracts.
