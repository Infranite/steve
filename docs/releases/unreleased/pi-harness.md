Pi is now a built-in harness through the open-source @openma/pi-acp bridge, including managed installation, model and thinking-level discovery, MCP tools, skills and isolated per-principal configuration. The built-in catalog now has 17 entries. Pi executes native tools without harness approval modes and therefore offers only FullAccess; thinking levels are never presented as permissions. The runtime list keeps these declared limits even before sign-in or when a scratch-session probe fails. Provider sign-in is still required in the executing principal’s own Pi directory.

Development mode now isolates Pi’s configuration and uses its own adapter package directory rather than linking the installed Hub’s packages. An existing shared development adapter symlink is reported explicitly so a live development Node cannot upgrade production packages through it. Read-only snapshots still keep their Node disabled; runnable acceptance uses a fresh, separate data set.
