- 事项的 PR 在 GitHub 上合并（包括 squash 合并并删除分支）后，即使事项的工作区随后被清理，事项也会直接完成，不再判定“工作区不见了”而作废验收、叫 Bot 重新交付。Steve 按跟踪的 PR 编号向 GitHub 核对合并状态和合并提交；工作区变了而 PR 还开着时，先问一次 GitHub 是否已合并，再按原来的规则作废。
- 只有人的消息（和补充信息）会作废待收尾的结果；Steve 自己排队给 Bot 的接手、跟进消息不再作废。你点“标记完成”时，Steve 排队的消息会被撤下，不再挡住完成。
- 会话出错、或读不到工作区和远端时，Steve 不再往会话里排消息，而是给你一张卡片：读不到远端时可以直接选“已经上线”（已合并）或“不需要发布”。
- Steve 合并 PR 时先读 GitHub 能否 rebase：不能 rebase（包括 GitHub 回复 “This branch can't be rebased”）就改用仓库允许的下一种方式（squash，再是 merge commit），仍然锁定验收的提交。只有所有允许的方式都合并不了时才给你卡片，并写明原因。
