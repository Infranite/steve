# Steve 0.2.4

This release adds readable Feishu/Lark cards and authenticated image and attachment access in channel messages.

- Read card schema 1.0 and 2.0, including the provider's original, flattened and wrapped message representations. Recent messages and IM conversations share structured rendering for text, tables, columns, notes, links and controls. Unknown or truncated content has an explicit fallback.
- Preview, enlarge and download message images; download files and rich-text post resources through the message's receiving connection. Resource keys are not exposed to clients. Permission changes, recall and retention expiry are checked again after downloads.
- Give the channel reply model actual supported image inputs and extracted UTF-8, PDF and DOCX attachment text, under bounded resource access. Unsupported or unreadable content is identified explicitly.
- Recover older card and post representations on read when the matching original event is still retained, without replaying messages or replies.

See [message content and limitations](https://github.com/Infranite/steve/blob/v0.2.4/ops/MESSAGE-MEDIA.md) and [managed upgrades](https://github.com/Infranite/steve/blob/v0.2.4/ops/UPGRADES.md).

Card callbacks and forms remain read-only. Feishu's resource API does not expose card-embedded images/media, folders or stickers; Steve displays descriptions and directs users back to the provider. Audio/video transcription, OCR, merged-forward expansion and outbound attachment sending are outside this release. Separate research, item and ACP sessions do not inherit the reply composer's attachment access.

Downloads are limited to 25 MiB and 30 seconds; the reply composer applies smaller aggregate limits. Tests use official-shaped fixtures, an isolated provider emulator and browser checks; real tenant permissions and a model's image interpretation have not been certified. This release preserves the previous managed installation and credential-backend requirements and does not migrate credentials.
