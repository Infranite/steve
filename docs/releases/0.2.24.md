# Steve v0.2.24

A project's "finished" rule can now actually be set, and deploys are more patient.

- `PATCH /api/projects/{id}` takes `done_when`, which says when an accepted result counts as finished. It takes `merge` (its commits are on the remote default branch), `tag` (merged, and a pushed version tag contains them), or `null` (a release by the project's own command on this machine, as before). The rule came in v0.2.22, but nothing could set it, so items of a project released through GitHub waited to close forever. Only this part of a project's release settings can be changed this way; the release command stays as it was set up.
- The local deploy script keeps trying to lift the maintenance drain for up to two minutes. A Hub that just started can be too busy to answer within 10 seconds, for example while it copies the knowledge index into OpenViking. Before this, that showed up as a false "degraded" result.

No database migration (schema 30). Hub and Web must come from the same release.
