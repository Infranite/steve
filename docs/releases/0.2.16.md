# Steve v0.2.16

What Steve sends or does outside, and what comes in, now survives a restart and never claims more than it knows. When the result of an outside action is uncertain, Steve says "may have happened" and checks before doing it again, rather than reporting a failure and retrying.

- **Connections are checked when something goes out, not when you approved it.** If the connection is paused or needs signing in again, the mail, GitHub write or chat message waits and goes out once it's back. If the connection was removed, or the capability was switched off (sending mail, writing to repositories, sending as you), it isn't sent and you're told why. Mail archiving and marking as read, recalls and reactions are checked the same way.
- **GitHub actions you approved (opening a PR, merging, an agent's comment) are kept until they're done.** A restart no longer drops them. If GitHub doesn't answer, the action is marked as possibly done, and the next try first checks GitHub:
  - **Opening a PR:** a PR from the approved commit counts as done. If the branch has new commits since you approved, nothing is pushed.
  - **Merging:** only a merge of the approved commit counts. The branch is deleted only if it is still at that commit.
  - **Comments:** a comment that can't be found is not posted again, because someone may have deleted it. You're told instead.
  - GitHub requests have time limits, so one stuck request can't hold up the rest.
- **GitHub events are processed after a restart.** A webhook is accepted only once it has been saved. Anything a restart interrupted is processed again, and a failure is retried. A delivery processed late can't overwrite newer PR state. The signals sent to automations, and items finished by a merge, survive a crash.
- **Mail events are saved together with the mail**, so a crash between the two loses nothing. Repeat deliveries change nothing, including after the source was paused. A polled source that fails to store an event doesn't skip past it.
- **Chat messages:**
  - **No answer from Feishu:** the message shows "may have been sent, checking" instead of "not sent". Within Feishu's one-hour duplicate window it is sent again with the same ID, so it can't appear twice. After the hour, you're asked whether it went out.
  - **Interrupted replies:** a reply interrupted before it was sent is sent once Steve is back. If it's more than an hour old, you're asked instead.
  - **Paused connections:** a message on a paused connection waits instead of failing.
- The daily backup checks the database copy before keeping it, and adds what the database alone can't restore: attachments, the signing identity, secret files and the configuration (one file readable by the owner only, kept 14 days, same disk).

Database migrations 028–030: `gh_delivery_inputs`, `gh_effects` and `chan_send_state`. Messages that were mid-send when the Hub stopped are marked "may have been sent" so you can check them. A Steve older than 0.2.16 can't open the database afterwards, and the release gate refuses it. Hub and Web must come from the same release.
