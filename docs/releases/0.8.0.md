# Steve v0.8.0

Needs a minor release: `STEVE_NODE_BIND` and `STEVE_NODE_PLACEMENT` are removed and new sessions are placed differently; move any Node you named there into a Bot's execution Nodes after upgrading.

事项的新会话只按一种方式安排：交给执行它的 Bot 的执行节点（按顺序，首个合格的优先，其余备用），有 Team 时再按 Team 收窄。Steve 主 Bot 使用 Hub 本机节点。其他 Bot 的执行节点默认也是 Hub 本机，显式留空则不再接新任务。“原有派发”选项去掉了：设置页的执行节点直接显示当前列表，Team 选择里的“原有派发”改为“不使用 Team”。

`STEVE_NODE_BIND`（把新会话交给指定 Node）和 `STEVE_NODE_PLACEMENT=spread`（按负载把新会话分给更空闲的 Node）不再生效，请改在 Bot 的“执行节点”里绑定远程 Node。事项要求的 Node 标签只在 Bot 的执行节点里挑选；没有带该标签的节点时，会话会说明原因而不再按别的方式安排。升级迁移会删除升级前配对节点的自动分流名单，以及与实际绑定对不上的旧放置记录。

Needs a minor release: Hub 与 Node 必须一起升级（Node 协议去掉了对旧版本的兼容），请同时换用随 Hub 提供的 Web 客户端。

不再兼容旧版本与旧数据：

- Hub 与 Node 只按当前业务协议 v12 交互：不再为旧 Node 退回旧的快照分页、会话容量与 harness 能力判断，`artifact-read-v1`、`harness-updates-v1` 两个能力声明删除；harness 组件只报告 `status`（`installed` 字段删除）。请先升级 Hub，再升级各 Node。
- 本机 Node 未开启时，流程里的 `cmd` 步骤不再改在 Hub 上直接执行，而是失败并说明"本机 Node 未开启"。
- 本地升级与发布脚本不再兼容旧 Hub 的升级 runner（`local-release.py build` 的下载桥、`--operation`、`--keychain-pass-stdin`）；`build` 只做源码构建，正式发布包用 `prepare-bundle` 或 `steve upgrade`。没有 `STEVE_HOME` 的签名服务定义、没有 `schema_compat` 标记的数据库会被拒绝。
- 升级迁移一次性清理旧数据：没有出站记录却标为"已发送"的回复改为"未确认"；把失败构建写成发布版本的事项卡片改为构建行；没有记录时点的旧"停止"请求和已结束会话里残留的排队输入删除；未写 harness 的模型选择补为默认适配器；模型种子标记合并为一个；仍未处理的接手卡片、新群卡片换成当前选项。没有周期或修订号的旧完成事件清除，事项本身保留。
- 调试面板显示当前推算状态及拟执行的动作。历史费用只在能通过 turn 或 call 确定归属时计入同一用量。
- macOS 首次安装直接把签名口令写入安装的 key store。启动时不再迁移平面口令文件，备份只复制签名身份和钥匙串。旧版 Python 签名初始化入口由 `steve setup` 取代。
- 网页与 macOS 客户端去掉了对旧 Hub、旧路由（`#/settings/hub`、`#/personas`、`#/plugins` 等）和旧卡片选项的兼容。请使用会话范围的排队输入接口 `/api/sessions/{id}/queued/{qid}`。

Device cards show CPU, memory, received and sent network rates, and session tokens per minute and today for each Node. Round-trip latency and session capacity remain on the Node detail page.

Hub integration tests use the address assigned by the operating system, avoiding collisions when they start in parallel.

Research tests use the virtual clock and ACP round trips to check that thoughts reset the idle timeout and silence expires it.

Diagnostic copies started with STEVE_NO_RESUME reject model calls immediately and keep all Nodes disabled. Model execution on runnable Hubs goes through Node jobs. The offline reply evaluation example now runs from the steve-hub crate.

Needs a minor release: update daily file-restore scripts to read the backup's files/ directory.

Daily backups write a complete, verified SQLite snapshot and reuse unchanged files through hard links. Each daily directory can be restored on its own, and retention releases shared file data after the last backup using it expires.

Needs a minor release: Remove STEVE_NODE_MODE=off from existing configurations.

Set STEVE_NO_RESUME=1 when opening a diagnostic copy. The diagnostic Hub never accepts Nodes or executes models. Model calls return a stable forbidden error that clients can display in their own language.

The Hub writes its actual startup addresses to run/hub-ready.json under the installation home. Development tooling uses the file to find the running Hub, including when the operating system assigns its port.

Needs a minor release: The migration discards the old Node vitals table. Reinstalling the previous Hub requires restoring a pre-upgrade database backup.

Device CPU, memory and network charts now use the Hub's metrics recorder. Minute samples stay in memory for up to 24 hours and start over when the Hub restarts. Workspace token totals continue to come from the usage ledger.

The Hub's local Node shuts down when its installation directory or executable disappears. Hub tests also clean up the local Node services they start, including when a test fails or times out.

Needs a minor release: this database migration requires restoring the pre-upgrade backup to roll back.

The Hub records session permission modes as commands and receipts arrive. YOLO and the item view can read those modes without scanning command history or taking the database write lock.

The Node runtime tests wait for committed turn starts, avoiding intermittent timeouts when a session reopens. Nextest now fails local and CI runs when a test leaves its output pipes open.

The macOS upgrade preparation test uses its temporary installation’s signing store, so clean test environments no longer need a preconfigured vault backend. Production signing requirements are unchanged.
