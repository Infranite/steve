# Steve v0.2.101

Multi-Bot work graphs now execute through ordinary Node sessions when the parent and child share a confirmed request principal. Bot permissions, workspace and worktree checks, Node routing and ceiling, and approvals remain in force. Unknown or mismatched identities and unavailable Bots or Nodes block execution with a visible reason; cross-principal OS isolation is not implemented.

Recovery binds a session interrupted before its first Node binding and reuses durable children and turn records. Dependencies, independent review, integration acceptance, pause and retry remain enforced. The item page now explains the current admission failure instead of saying every workflow needs a future isolation-capable Node.

Linux CI and release builds no longer fetch Zsh through Ubuntu package mirrors. They verify a pinned, self-contained Zsh archive before running the existing release compatibility checks.

修复 YOLO 选择弹窗在窄屏或长命令下横向溢出、右侧边框和说明被截断的问题。选项、命令和路径会在弹窗内换行；长内容纵向滚动，取消和应用按钮保持可见。同样修复事项和项目的 YOLO 选择及完全放开确认框。不改变 YOLO 权限、确认要求或已有设置。

修复取消协作后主事项仍被已取消的评审和集成单元永久阻挡的问题。用户可在事项页暂停协作后，明确确认改为本轮单会话验收；系统保留原成果、取消状态、确认人和历史，不把取消记为通过，也不会自动接受交付。Bot 不能自行批准这一切换，仍未确认结束的执行继续阻止切换和关闭；普通暂停或取消不会解除必需验收门禁，恢复协作须重新规划。

- 事项会话还在启动时，页面不再把 Steve 交给它的任务说明当成一条“排队消息”：队列条写“任务说明 · 会话启动后开始”，不再给它“撤回”“立即发送”；你在这期间补充的话写“会话启动后发送”，可以编辑、撤回，没有“立即发送”（没有回合可打断）。此前这里写的是“本回合结束后发送”。
- 会话启动卡住时看得见了：“正在开始…”后面显示已经等了多久，超过两分钟提示比平时久、去哪里找原因；会话页顶部的状态条写“正在开始”并从创建时计时，不再是“运行中 0:00”。

When a collaboration work unit reports a failed review or blocker, its child item now finishes as failed after its turn ends. The result and reason remain in the work graph for the coordinator to retry or replan, without leaving an idle child item that later raises a separate stall alert.

- 主控会话在协作工作图执行、排队、等你处理或已暂停时结束回合或空闲超过两分钟，不再被当成“停下了”：不弹“它停下了”卡片，Steve 也不再替它续跑、消耗续跑次数。必需的工作单元真实失败、被取消、尝试次数用完、目标已变化或协作无法开始时，主控会收到带具体原因的提醒，次数用完后卡片写明是哪个单元因何未通过，不再因为“存在工作图”就被忽略。
- 工作单元自己的事项不再被普通的停滞检测续跑或弹卡，由工作图负责续跑和上报；单元重新开始执行时，主事项上关于停下的旧卡片自动失效。已登记的前置等待也不会被当成停滞。
- “它停下了”卡片的原因改为来自当前状态（你中断了这一回合、上一回合出错、会话空闲、哪个单元未通过），不再引用会话里最后一条系统消息，例如很早以前的发布通知。你自己中断的回合仍只给你卡片，Steve 不会替你接着做。
- 续跑前会再核对一次状态：已经在执行、排队、等你处理或暂停的事项不会被重复续跑。事项诊断新增当前工作状态和原因，与上面的判定一致。
- YOLO 新增硬限制：需要你本人操作的事（登录、扫码、验证码、在手机或设备上确认、插上设备等），或声称你已经操作过的回答，不会被代答；Agent 停下来等你本人操作时，Steve 和 YOLO 都不会自动让它继续，卡片留给你。

After a restart, Steve now clears an old parent stop alert when its collaboration graph is already running or waiting for a known reason. The item returns to its current work status, while real questions and uncertain external effects continue to wait for the user.

Steve now closes a failed work unit's child item after a restart when the graph already recorded the failure and the turn has ended. Older failed attempts no longer remain falsely active.
