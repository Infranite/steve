# Steve v0.2.15

One lifecycle for every item. Finishing, cancelling, failing and reopening now go through a single path, so an item can no longer be marked done while its work is still running, and it is never "done" twice.

- Marking an item done while its agent is mid-turn no longer cuts the turn off or leaves it half-closed. The item shows as closing, and closes once the turn has stopped, nothing is queued for it, and every required step (such as its release) has succeeded or been waived.
- If the work changes after you accepted it (new commits or edited files), the accepted result no longer counts and the item stays open.
- A closed item stays closed. New messages, supplements and goal changes to it are refused. Reopening it starts a new round, and the earlier rounds keep their outcome in the item's history.
- A successful release no longer finishes an item on its own: the release has to contain the accepted work. When there is nothing to release, Steve asks whether it is already live. A release whose outcome is unknown holds the item open until you check it.
- A module hook that crashes no longer stops the hooks that come after it, and an acceptance check that dies is asked again rather than taken as a yes.

Database migration 027: new item columns (phase, cycle, revision, outcome, acceptance, closing) and the tables `item_cycles` and `item_operations`. Existing items keep the state they were in, and nothing is sent when the migration runs. A Steve older than 0.2.15 can't open the database afterwards; the release gate from 0.2.14 refuses it. Hub and Web must come from the same release.
