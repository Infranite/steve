# Steve v0.3.3

远程安装配对失败或尚未开始时，现在可以选择“取消此次配对”，再添加下一台设备；下一次配对会使用新的安装命令和临时密钥，不再恢复已取消的失败记录。原机仍可直接重试，关闭弹窗仍会保留进度。取消后请在原目标机器上按 Ctrl-C 关闭 tailcat serve。

取消会清理 Hub 上此次安装的临时 SSH 密钥；安装阶段失败后，尚未使用的自动确认配对码也会失效。正在进行或已经完成的安装不会被取消，也不会卸载目标机器或撤销已经配对的 Node。

手动配对设备时，界面会先显示 Homebrew 安装命令和安装说明，再显示 steve setup node；已安装 Steve 的机器可以跳过安装步骤。直连和经 tailcat 的手动配对均提供此指引。

Steve 自带工具现在按用途显示图标：更新计划、搜索工具、调用工具、交付等不再共用同一个图标。会话步骤及时间线、主对话研究步骤和能力设置中的内置工具列表使用一致的线条图标，兼容历史工具名称和 MCP 前缀。

Channel send failures now retain the full proposed message, identify the verified restriction and offer explicit retry, edit for review, or discard. Local send-as-user permission can be reviewed, applied and undone from the failure card; external service restrictions explain where to restore access. Applying permission never sends a message.

Edited recovery drafts require your explicit approval even with YOLO on, including after rewrite failures and restarts. Explicit mentions, trigger words and manual retries are no longer swallowed by the 24-hour automatic-refusal suppression. Discarded messages stay discarded; retry preserves the existing claim, UUID and unknown-result safeguards.

Personal ext_ws sends now expose the protocol’s existing 24-hour deduplication guarantee to recovery, so a lost response can be reconciled with the original key and payload after a restart.

Recovery rechecks use the current conversation and writing samples. Your replacement text is reviewed as written; model rewrites retain the same delete-only rules as other replies, and an unfinished check remains unchecked rather than being reported as a leak.

Items gain a completion judge, in shadow. When an item's turn has ended and the Hub sees nothing more coming for it, the judge decides whether the work is done and records what it would do next. Nothing acts on that yet: it never closes, reviews, wakes or merges an item, and who can send, merge or close is unchanged.

- A turn is judged only when it has settled: no turn running or retrying, no dispatch whose receipt is missing, no queued input, card, wait, pause, Stop of yours or busy collaboration, and the Node not away. Otherwise it is looked at again later. Each turn is judged once, per cycle, session and goal version. The judge reads the final words and the end of that turn's last attempt only: words its Node confirms that attempt said, so a retry never mixes in an earlier attempt's output. When some of the words can't be attributed, it records them as unknown. A verdict for a turn that is no longer the current one, or whose inputs changed while the judge ran, is thrown away. The session, the turn, the goal version, the session's input and the evidence (including the item's operations) are checked again in the same write that stores the verdict.
- Verified facts come first, criterion by criterion. A merged pull request, a passed build or a live deploy settles its criterion without a model. What the agent only reported never counts as a fact: such a criterion stays unknown, and the model can't mark it met. The goal in words is always judged by the model, also when every other criterion is met. It must answer with one of five verdicts (done, not done, waiting, needs you, can't tell), giving a status for every criterion. Anything else counts as a failure. After three failures in a row, the judge gives up and the item stays as it is.
- The judge's model is a new setting, "Completion judge", in Settings · Models. By default it avoids the working Bot's own model. Each verdict records the harness and model that actually reported back ("unknown" when they didn't say), and whether that model was a different one. Each finished task turn now costs one short model call, unless facts or rules settle it. To record only what facts and rules decide, set the work policy entry `judge_model` to 0.
- The judge runs on its own timer, one pass at a time, 30 seconds after the last one ended (work policy entry `judge_every`). A slow or hanging judge call never delays the stall cards, the Release build checks or the pull request checks.
- The item API (`shadow.judge`) and the item's Debug view show the latest verdict and what it would trigger. The derived state gains the row "Stopped; being judged".
- A migration adds an empty table for judge candidates and new columns to the judge results. It runs by itself and is fast on a large database.
