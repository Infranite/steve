# Steve v0.2.36

- An item branch that shares no history with the main branch (an old line) is reported as not merged, instead of "can't tell", and no longer clutters other items' overlap checks.

Tables in the conversation open to their full height, and Steve can answer with charts, choices and small forms (A2UI) that you use right in the reply.

- A Markdown table is no longer boxed into a 300px window with its own scrollbar and copy/download/fullscreen buttons. It sits in the text and scrolls with the page; only a table too wide for the screen scrolls sideways. A table longer than 30 rows shows its first 20 and a "展开其余 N 行" button. (ST-46)
- In the main conversation, a reply can carry an A2UI v0.9.1 interface in a ```a2ui block: the basic catalog (text, cards, rows and columns, lists, tabs, dialogs, buttons, text fields, check boxes, choices, sliders, dates) plus Steve's `Chart` (line, bars, stacked bars, horizontal bars), drawn in the app's own style. A chart can filter on the page (近 7 天 / 近 30 天) and switch to a table.
- Pressing a button sends the interface's answer back to the same conversation as your message, and Steve answers it. Each interface is submitted once: a double click or a second tab sends nothing more, and after a reload it shows as submitted with the values you sent. What you typed before sending survives a reload. A failed send says so and can be tried again. Interfaces only hand your choices to Steve; they never run anything.
- Older messages look as before. While an interface is being written you see "正在生成界面…"; a description that can't be drawn shows a short note with the original text, and an unknown component is marked without hiding the rest. Interfaces in IM conversations and elsewhere are shown read-only.
- `POST /api/thread/:id/a2ui` takes the A2UI action of a reply's interface; see docs/ST-46-a2ui.md.
