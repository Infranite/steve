# Steve v0.2.97

- 发布不再为同一份代码等第二遍 CI：一个已经跟上 `main` 的 PR 以 rebase 方式合并后，`main` 末尾的提交和 PR 的提交逐个内容相同，`ops/cut-release.py cut` 会核对这一点（GitHub 记录的合并提交、逐个提交的 tree），核对通过就直接认 PR 那一遍通过的 CI，不再等 `main` 上重复的那一遍。PR 落后于 `main`、被 squash、它的 CI 没通过，或者 `main` 上那一遍已经失败时，仍按原来的规则处理。

- CI 的 Rust 测试改为每个平台一个任务：在同一台机器上编译并跑完全部测试。以前是先编译、把几个 GB 的测试包传给四台机器、再分片跑，传包和解包的时间比跑测试本身还长。测试范围不变，仍然不自动重试，仍然逐项核对每个测试都跑了一次且一次通过。

- 开发和测试构建里的 SQLite 现在按优化级别编译。几乎每个测试都会新建一个数据库并跑完全部迁移，这一步原先占了普通测试的大半时间；优化后这类测试的耗时大约减半，CI 的测试阶段随之变短。正式发布的程序本来就是优化构建，不受影响。

修复使用私有 CA 证书的 OIDC 登录：之前 Hub 只信任内置的公共根证书，登录时 `/auth/login` 返回 500，日志只有 `discovery: Request failed`。现在 Hub、Node 和 `steve` 命令的 HTTPS 请求也信任系统证书库（macOS 钥匙串、Linux `/etc/ssl`）里的 CA；Node 连接这类 Hub 时也不再必须 `--pin`。OIDC 发现和密钥获取失败时，日志会写出完整原因，例如证书不受信任。
