# Steve 0.2.0

This release brings native Feishu/Lark application registration, clearer consent choices, and managed upgrades for paired Hub and Web builds.

- Create or connect a bot application through the official registration flow implemented in Rust. No additional provider CLI is required. Saved credentials survive interrupted verification and can be retried without creating another application.
- Personal authorization is optional. Read/draft access and sending as yourself are separate choices. Device authorization works without a public callback URL; deployment-specific callback URLs remain optional advanced configuration.
- Check GitHub Releases in Settings -> About -> Versions. Managed installations can download, verify, drain active work, back up, restart and recover eligible work. Instance owners approve or reject Agent upgrade requests.
- Interrupted session inputs have durable dispatch receipts. Recovery preserves paused work, requires fresh tool approval where needed, and does not automatically replay uncertain external delivery.
- Upgrade progress reconnects after a restart without repeating the request. The browser refreshes only when you choose, retaining saved drafts.

## Installation and compatibility

See [README](https://github.com/Infranite/steve/blob/v0.2.0/README.md) and [managed upgrades](https://github.com/Infranite/steve/blob/v0.2.0/ops/UPGRADES.md). The bundles target Apple Silicon macOS 14+ and Linux x86_64 with glibc 2.35+. Source installations and externally managed containers support release checks; their existing deployment process still manages installation and restart.

macOS installations using Keychain helper signatures cannot automatically switch to generic precompiled binaries. Managed bundles require a compatible credential backend configured by the deployment owner; upgrading does not migrate keys.

Lark personal authorization uses device codes; Lark browser callback authorization is not enabled. Registration and authorization tests use an isolated provider emulator, not a real tenant. Linux service-manager deployment remains separate from the local process tests.

Failures before the upgrade commit restore the previous bundle and database. Failures after commit preserve the new database so resumed work and external effects are not discarded. Retain upgrade journals, backups and prior bundles until the deployment has been accepted.
