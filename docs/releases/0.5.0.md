# Steve v0.5.0

Needs a minor release: the Hub API error body changed; upgrade the web client (served by the Hub) together with the Hub

Hub JSON error responses now include `code`, `retry`, `reason`, and `params`, while preserving the HTTP status, `error` message, and existing extra fields. Session and module 401 responses retain the existing `error`/`login` distinction for sign-in; domain `reason` values will distinguish them in wave 4.

The daily backup job of a source-based installation (`ops/backup.sh`) now also copies `deliveries`, the delivered files, as the Hub's own daily copy already did. Before, restoring from such a backup lost them.

Optional in-memory Prometheus metrics can be enabled with `STEVE_METRICS=prometheus`; the default remains off. The independent `GET /metrics` listener defaults to `127.0.0.1:9464`; `STEVE_METRICS_LISTEN` accepts loopback IP addresses or an absolute `unix:` socket path with mode 0600. Scrapes require an owner's Bearer client credential, using the existing access-token sign-in flow. Lock timing, transaction counts and process disk-write bytes never enter the database. HTTP metrics use route templates, separate SSE connections, and report observed store connection acquisitions per request; work crossing the ordinary API blocking boundary retains that request context.

Needs a minor release: SSE frames now carry ws and rev, the synthetic workspace resync frame is replaced by stream.reset, and steve.thinking always carries ws; upgrade the web client (served by the Hub) together with the Hub

Events now carry their declared workspace scope and transaction revision throughout producers and internal subscriptions. SSE cursors and replay keep their existing format; clients outside an event's workspace no longer receive its invalidation notice.

Nodes no longer record working-directory disk observations in their execution journals. The `STEVE_DISK_OBSERVE*` environment variables no longer have any effect. Existing disk-observation records are removed when the Node opens its journal.

Needs a minor release: the new migration cannot be undone by reinstalling the previous release.

External WebSocket channels retry transient inbound failures and retain permanently rejected messages with an audit diagnostic instead of silently losing them.

Feishu personal-message polling now follows every page, including bursts of more than 50 messages in one second.

Chat memory extraction commits results together with its completion receipt and catches up on the last seven completed local days after downtime.

Needs a minor release: the `GET /digest/conversations/{conv}` API response no longer includes `cursor.since`; clients that read this field must stop using it.

Digest intake now reads only new or pending messages instead of scanning all message history every minute, while still processing late arrivals and newly sent outbound messages exactly once.

Mail sync retries messages whose IMAP body or header is temporarily unavailable and reports messages still unavailable after three attempts before continuing with newer mail.
GitHub pull request polling now follows all changed pages, resuming unfinished scans on later polls so bursts of updates are no longer missed.

Approved channel messages that are due now go out even when more than 50 other approved messages are still waiting for their send delay. Before, those could hold the due ones back.

Needs a minor release: the default time zone now follows the system, and daylight-saving gaps use RFC 5545 semantics.

Schedules, todo reminders and calendar imports use the same DST rule: a missing wall time keeps the offset before the jump, and a repeated time uses its first occurrence. For example, New York's 2026-03-08 02:15 runs at 03:15, rather than 03:00.

The workspace time zone defaults to “跟随系统”; existing explicit choices remain available.

The “每天汇报” setting is removed: it was never read. A morning brief's time is its own plan, set on the Automations page (weekdays 08:30 when it is first created).

Calendar imports resolve unknown TZIDs using `X-WR-TIMEZONE`, then the connection's time zone, then the system zone, with a diagnostic instead of silently treating the wall time as UTC.

The Node retry checks now complete adapter discovery before creating work and use a scripted adapter that satisfies Pi's HTTP MCP contract, avoiding intermittent test failures before a session opens.
