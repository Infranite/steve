# Steve v0.2.17

Tighter reading in conversations where someone besides you reads Steve's answer. This is the first step of the read-permission work (phase 2); it narrows what Steve can see there until it can tell each listener's rights apart.

- When Steve answers in a group chat or any conversation where you are not the only reader, its item tools see only the items that conversation itself produced, and only their title, status and goal. Other items, plans, timelines and delivery notes are not there. Your own private chat with Steve and the main conversation are unchanged.
- In those conversations, knowledge search uses only what the whole workspace may see. It no longer falls back to your personal view of the knowledge base, and Steve's research there no longer has your project directories open: whatever it may say there, it finds through its tools, which check every call.
- Work only starts on your say-so. When someone else in a group chat asks Steve to do something, Steve makes it an item that waits for your "yes" (a 方案 card) instead of starting an agent. YOLO doesn't answer that card for you; it only does so for items you asked for yourself. A `/bot` command counts the same way: it starts work only when you sent it. When you say yes, the work starts with the conversation it came from and its attachments, as if it had started right away. What you ask for, in any chat, starts as before, and rules or flows you set up to create items keep doing what you configured.
- A tool token of an agent session that has ended no longer works. Whatever still holds it gets nothing.

No database migration (schema 27). Hub and Web must come from the same release.
