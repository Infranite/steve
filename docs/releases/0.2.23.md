# Steve v0.2.23

Items no longer get stuck waiting to close, and work Steve's agents left unfinished is finished.

- When you decline a release with a note ("merge the PR, no release needed"), that answer now holds for the whole round of the item. Before, every later delivery or "mark done" asked for a release again, so the item waited for a release forever.
- When an accepted item only needs its release and the agent ends its turn without asking for one, Steve now asks you whether it still needs releasing, instead of waiting in silence. The card's buttons read 不需要发布 / 需要发布 / 已经上线.
- A question or approval that comes up while an item is closing now holds the close until you answer it.
- Two test races are fixed. Your Feishu authorization also still merges the contact the bot made for you when the name lookup has already filled it in (it used to refuse).

- Every item now has exactly one category tag (bug / feat / doc / refactor / ops / chore), and an empty tag is refused. The local release script reads this machine's build identity from signing/identity.json.
- This machine switches its knowledge store to OpenViking (STEVE_KB_STORE=openviking, from v0.2.19). On first start the existing index is copied into it in the background.

Coming from v0.2.17, this deploy also brings v0.2.18–v0.2.22: the conversation card, the OpenViking knowledge store, and what Steve's agents shipped. That covers decisions belonging to their conversation, the harness session id with resume, notes on approvals in the item conversation, output previews and the upgrade flow.

No database migration (schema 30). Hub and Web must come from the same release.
