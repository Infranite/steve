# Steve v0.2.79

Homebrew 安装时，如果 GitHub 资产 API 下载失败，会自动尝试同一版本的官方 Release 下载地址。两条路径使用相同的 SHA256 校验，不需要提供 GitHub 凭据或在本机编译。

安装说明补充了 Linuxbrew 自身可能安装的编译器和 libc 基础依赖；Steve 仍从已发布的二进制包安装，原生 CLI 无需 Python 或 OpenSSL。

首次配置 Hub 时，安装向导会保留 OIDC issuer 的完整路径和末尾斜杠，避免认证服务返回的 issuer 与保存值不一致而导致登录页报错。浏览器访问地址仍独立处理，HTTPS 与认证校验规则保持不变。

Service commands show a readable terminal summary, with the original JSON available through `--json` or a pipe. Process state, configured build and unverified runtime identity are presented separately, with local diagnostic scope and next steps made explicit.

Interactive setup lets you correct an invalid field without restarting the wizard. Cancellation, ownership checks and existing-file protection remain in force. Completion output includes the full listening address and the remaining startup, login or Node confirmation steps.

Installation documentation now distinguishes the base service from the selected harness's required ACP adapter.

`steve setup --reconfigure` lets an existing managed Hub edit its listening addresses, browser URL and current OIDC issuer/client ID using the actual configuration as defaults. It preserves other environment lines and comments, the secret file, installation identity, service registration, databases and Node pairing.

Changes are previewed with confirmation defaulting to No, checked against the installed Hub, backed up privately, and read back after saving. Interrupted writes can be recovered by rerunning the command and confirming recovery; external edits are not overwritten. Saving does not restart the service, and Node reconfiguration is refused.

工作区回收测试使用的临时 Git 仓库现在同步完成自动维护，避免后台维护进程干扰进程占用判断。保留未提交文件与活动进程的原有检查，并补充失败时的目录、Git 状态和回收结果诊断。
