# Steve v0.14.0

## Before upgrading

- migration 146 adds reaction records, reply sources, burst grouping and the `[AI]` mark setting. Bot groups that join after the upgrade start in silent recording; switch them to replies on the space page. ([#592](https://github.com/Infranite/steve/pull/592))
- Linux needs no manual steps; upgrade from Settings → About. ([#593](https://github.com/Infranite/steve/pull/593))
  On macOS, upgrading from v0.13.0 or earlier needs one terminal command from the new release; do not start it from Settings → About. Those releases start the Hub through a script that this release removes, and their upgrader insists on that script, so the in-app upgrade cannot do this step.
  - Homebrew: `brew upgrade steve && "$(brew --prefix steve)/libexec/bin/steve-hub" --local-release upgrade-macos --home ~/.steve`
  - Release tarball: unpack `steve-X.Y.Z-aarch64-apple-darwin.tar.gz` into an empty directory and run `<dir>/bin/steve-hub --local-release upgrade-macos --home ~/.steve`.
  - Roll back to the previous version: `~/.steve/current/bin/steve-hub --local-release rollback-macos --home ~/.steve`
    - Once the upgraded Hub works, confirm it: `~/.steve/current/bin/steve-hub --local-release confirm-macos --home ~/.steve`
- `STEVE_NODE_MODE=local` and `steve-hub --local-node` have been removed. Unset `STEVE_NODE_MODE`, or use `STEVE_NODE_MODE=service` (the default), and make sure `bin/steve-node` is installed alongside `bin/steve-hub`. ([#606](https://github.com/Infranite/steve/pull/606))
- **Breaking:** replace the YOLO switch with Ask, Auto and Full access levels ([#624](https://github.com/Infranite/steve/pull/624))

## Features

- **channels:** read group conversations correctly, reply per burst and finish the calm inbox ([#592](https://github.com/Infranite/steve/pull/592))

  Channel replies now read conversations the way a person would.

  - **Group conversations (#258).** Owner identity, threads, quotes and media are read from the channel's event structure, not guessed. Context is assembled thread first. Steve no longer asks you about things you already said.
  - **One reply per burst (#268).** Messages that arrive together are answered together. A reply is split by question or topic only when one answer doesn't fit, and each part quotes the message it answers. Late messages are folded into the unsent draft.
  - **Replies in your voice look things up (#275).** Before drafting, Steve runs bounded read-only searches: the same person's other chats, related threads, items, your memory, linked documents, mail and calendar. It skips them for small talk, and each source is shown on the draft card and passes the disclosure check.
  - **Your emoji reaction counts as handling (#277).** If you react first, no draft is made; if you react later, the unsent draft is withdrawn. Removing the reaction restores it only if nothing else handled the message.
  - **Images and files are understood (#278).** Images go to multimodal models, with cached descriptions. PDF, docx, xlsx, Markdown and text are extracted within limits. When something can't be read, the draft says so and links the original instead of guessing.
  - **Calm inbox, remaining parts (#213):**
    - Unhandled mention and direct-message drafts are escalated after 4 working hours.
    - After you ignore the same kind of message 3 times in 7 days, Steve offers a "just record these" rule.
    - New groups are recorded silently by default, with one-click switching to replies.
    - Drafts open in their conversation, approval cards look different from other cards, rich text renders, and the source app opens directly.

  Feishu-specific logic stays inside the Feishu adapter. Outbound sends still require who, what and why to be clear, and keep the switchable `[AI]` mark.


  Closes #258, #268, #275, #277, #278, #213.

- **thread:** show live turn timing and research progress in the main conversation ([#616](https://github.com/Infranite/steve/pull/616))

  - **The main conversation shows the whole turn's elapsed time** from the moment you send a message. It no longer resets when tools run or when the page is refreshed. After more than 15 seconds of silence it shows when the last activity happened.
  - **Deep research and long analysis show their progress live**: the current stage, the thinking stream, the plan, each tool with its result summary, and parallel subtask progress. When the turn finishes, the total time and the key steps stay visible. Credentials are redacted.

- **permissions:** replace the YOLO switch with Ask, Auto and Full access levels ([#624](https://github.com/Infranite/steve/pull/624))

  The workspace switch **Native approval (YOLO)** is replaced by **Permissions**. It has three levels; only the owner sets it, and it starts at Ask.

  | Level | What a session's harness runs in |
  | --- | --- |
  | Ask | Its asking mode. Permission requests that reach Steve open a decision card for you. |
  | Auto | The harness's native auto mode, where it declares one. A harness without one, or one that refuses it, is shown as unsupported or refused; Steve does not simulate it. |
  | Full access | The harness's declared full-access mode. Switching to it first asks you to confirm the risks. The harness no longer asks before any command, and it can change or delete what it can write and use the network. Steve's sandbox still keeps Steve's own files out of reach, except for harnesses that run their own sandbox instead (listed from the harness spec). |

  - Plan and read-only sessions are never widened. The Node owner's ceiling still caps every level.
  - Questions, Steve tool permissions, vault secrets, personal sends and design decisions still wait for you.
  - Settings shows which discovered harnesses support Auto and Full access. Each session shows whether its level is applied, pending, unsupported or refused.
  - The word "YOLO" is gone from the interface, API, types and docs. Existing policies migrate automatically: the old switch off becomes Ask, on becomes Auto.
  - API: `/api/approval-policy` is now `/api/permission-policy` (and `/api/permission-policy/sessions/<id>`). Turning on Full access requires `confirmed: true`.
  - Metrics: `steve_permission_sessions`, `steve_permission_turns_total`, `steve_permission_full_access_confirmations_total`.

  Closes #622.
- **dispatch:** Steve chooses the Bot by reasoning over Bot and Node facts ([#630](https://github.com/Infranite/steve/pull/630))

  Steve now decides which Bot does a task by reading the request and the facts about Bots and Nodes. Keyword and specialty matching is gone.

  - **Two read-only tools for Steve.**
    - `steve_bots_list` shows, for each Bot: role, specialties, harness and model, permission mode, Teams, default project, bound Nodes, current load and recent results.
    - `steve_nodes_list` shows, for each Node: whether it is online, its ready harnesses and their permission levels, load, capacity and disk.
    - Both return only what the caller may see in this workspace.
  - **In a conversation**, Steve checks these before it offers to create an item, and the OFFER card shows the Bot it chose and one sentence on why. You can still pick another Bot on the card.
  - **For items created elsewhere** (channels, mail, flows, API), Steve makes the same choice in a short background job, and the item shows "Steve is arranging an executor" meanwhile.
    - With a single eligible Bot, or one you named, no model is called.
    - The dispatch model follows Steve's own conversation model and can be overridden on its own.
  - **Code keeps only hard constraints.** The Bot must be enabled and in the Team, its Node online, its harness and model ready, and the permission ceilings respected. A choice that breaks them is shown with the reason, and nothing silently switches to another Bot.
    - If dispatch fails (Node offline, model error), the item opens a card you can retry from. It is never left "arranging".
  - **Steve's own read-only tools work in every research run.** Before, research in shared or non-owner conversations ran in a mode where Claude Code's classifier blocked them, and Antigravity refused them. The harness spec now allow-lists exactly those tools (`steve_mcp_allow`); every other permission request is still refused.
  - **Removed:** the lexical scoring, the tie-break ranking, the old placement reasons and preview, and the duplicate OFFER parsers. Migration 148 adds `item_dispatch_jobs` and rewrites stored placement reasons.
  - Metrics: `steve_dispatch_job_duration_seconds`, `steve_dispatch_job_total`, `steve_dispatch_invalid_choice_total`, `steve_offer_bot_override_total`, `steve_permission_oneshot_allowed_total`.

  Closes #626.

## Fixes

- **updates:** retry transient GitHub errors and show the latest upgrade receipt ([#602](https://github.com/Infranite/steve/pull/602))

  - **Temporary GitHub errors no longer look like a failed update check.** HTTP 5xx responses, timeouts and connection failures are retried with bounded backoff. Settings → About then shows "GitHub is temporarily unreachable; retrying automatically" instead of a raw URL and error. Real failures, such as a manifest that fails verification, are still reported as failures, with the technical detail under "Details".
  - **The upgrade card shows the latest upgrade.** It now shows the most recent upgrade or deployment, whether it ran in the app or from the terminal. A failed attempt whose target version is now running moves to history. Failure titles name both versions: "Upgrade to X failed; restored Y".
  - New metric `steve_update_check_total{result}`.
- **acp:** carry Claude Code classifier settings into isolated sessions and surface auto-mode failures ([#608](https://github.com/Infranite/steve/pull/608))

  Fixes Claude Code sessions in auto mode failing every tool call with "Classifier unavailable" after a handoff.

  - **Root cause.** Each principal's session runs Claude Code with its own isolated config directory, which did not carry the Node's Claude Code classifier, network and proxy settings. Behind a custom gateway with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, recent Claude Code releases then have no usable auto-mode classifier unless `CLAUDE_CODE_AUTO_MODE_SERVER=0` is also set. Every tool call was denied, and after ten denials in a row the turn stopped.
  - **Fix.** When a session opens, Steve copies an allow-list of the Node's own Claude Code `settings.json` entries into the isolated directory: auto-mode and classifier settings, gateway base URL, proxy and TLS. The allow-list is declared in the harness spec. Nothing outside the allow-list is copied (personal tokens and other environment entries stay out), and sign-in is shared exactly as before.
  - **Visibility.** `permission_check_status` frames and repeated classifier denials are recognised as typed diagnostics with metrics (`steve_acp_permission_check_status_total`, `steve_acp_classifier_unavailable_total`, `steve_session_auto_mode_unavailable_total`). The session shows a warning with what to do, instead of tools silently failing.

  Closes #612.
- **runtime:** stop cutting off long tools, MCP calls and async subtasks as 15-minute stalls ([#609](https://github.com/Infranite/steve/pull/609))

  Fixes long-running work being cut off as "no progress for 15 minutes". This was why Antigravity (agy) sessions seemed to stop on their own.

  - **Progress is recognised.** Deduplicated tool advances (read, search, exec, Steve MCP), plan updates and subtask changes now count as progress. Running tools and non-daemon subtasks extend the limit to 60 minutes (`ACTIVE_WORK_NO_PROGRESS_MS`). Subtasks waiting on you pause the timer. Real silence, loops and hangs are still stopped.
  - **Antigravity subagents are tracked correctly.** An async `invoke_subagent` is no longer marked done the moment it starts, so running background work is tracked.
  - **Workspace changes are detected** through a deterministic fingerprint.
  - **Correct attribution.** A stall cancel is a typed reason, shown as a stall with what was blocking. It is no longer shown as "you interrupted this turn".

  The Node protocol stays at 17: only existing events are reused, and the new prompt fields have defaults.

  Taken over from Steve item ST-228 at the owner's request.

  Closes #613.
- **node:** stop Antigravity approval prompts in Auto mode ([#610](https://github.com/Infranite/steve/pull/610))

  Fixes Antigravity (agy) repeatedly asking for tool approval in Auto mode.

  - **Steve's MCP tools are allowed.** The isolated agy settings allow `mcp(steve/*)`. The rule is declared in the harness spec (`state_settings`), and the user's own allow, ask and deny rules are kept.
  - **agy stays inside Steve's OS sandbox.** It shares the workspace boundaries, toolchain and cache locations, login environment and control-plane protection with every other harness. Its own terminal sandbox cannot start inside Steve's: macOS does not nest sandboxes.
  - **What that means per mode** (agy 1.5.18, tested on a real agy inside Steve's sandbox):
    - **Auto** uses agy's native `auto`. Workspace reads and edits and Steve's tools run without prompts. agy's own classifier lets safe shell commands through outside its sandbox and still asks before risky ones.
    - **Full access** runs agy with `--dangerously-skip-permissions`, so agy no longer reviews commands. Steve's sandbox still keeps Steve's own files (keys, `steve.env`) out of reach, but agy can change anything the sandbox lets it write and use the network. The deployment guide states this risk.

  Taken over from Steve item ST-224 at the owner's request.

  Closes #614.
- **harness:** tell a missing ACP adapter apart from a missing service PATH ([#603](https://github.com/Infranite/steve/pull/603))

  A Node's Harnesses tab now says what is actually missing.
  - **Four distinct causes.** The CLI is not on the service PATH (fix: `refresh-env`); the CLI is there but its ACP adapter package is not installed (fix: one-click install); both are missing; or the adapter is installed but fails to start.
  - **Deterministic diagnosis.** The cause is derived from the harness spec's command kind (npm entry or binary) and its detection binaries.
  - **Execution policy explained.** "This Node's execution policy forbids component upgrades" now says which Node setting causes it, what it blocks, and where to change it.

  Before, a missing adapter such as Pi's `@openma/pi-acp` was reported as a missing service PATH, even when the PATH shown contained the CLI.

  Closes #619.

  No upgrade steps: the Node protocol stays at 17 (the new diagnosis field has a default).
- **hub:** bound subprocess waits and avoid macOS fork hangs in the supervisor and backup ([#600](https://github.com/Infranite/steve/pull/600))

  Fixes occasional hangs of the upgrade supervisor and the backup engine on macOS.

  - **One bounded subprocess runner.** `steve-runtime::process` provides a single runner, sync and async, that every caller now uses: installer, upgrade supervisor, backup engine, vault key helper, adapter probes, npm lookups, Git push and the core's deadline runs.
    - Every wait on an external process and every pipe read has a named upper bound and an output cap.
    - On timeout, the process group is killed before the child is reaped, so a recycled pid is never hit.
    - The caller gets a typed error, and the runner reports `steve_process_*` metrics.
    - This replaces six separate implementations, plus the hand-written waits that #606, #609 and older Node code had added (git probes, `lsof`, adapter and harness version checks, history import, the system check).
    - Waits that stream progress, hold a long-lived tunnel or follow their own start protocol keep their own handling.
  - **No `fork()` from the multi-threaded Hub on macOS.**
    - The backup engine, which inherits a lock descriptor, and detached sessions (`setsid`) start through `posix_spawn`.
    - Elsewhere, a bare program name is resolved against the child's `PATH` before spawning. Without that, `std` falls back to `fork()` whenever `PATH` is changed.
  - **Rollback keeps a full restore budget.** Restoring the database after a failed upgrade has its own one-hour budget, separate from the two-minute pre-upgrade backup budget.
  - The backup password is written without growing its zeroizing buffer. A key-helper timeout is reported as unavailable (503), not as an internal error.
  - Tests find `restic` through `STEVE_BACKUP_ENGINE` only. The build no longer scans `PATH` or Homebrew for it.

  Closes #623.

  Other call sites that set `PATH` with a bare program name are tracked in #621.
- **process:** resolve programs before spawning and start detached sessions without fork ([#629](https://github.com/Infranite/steve/pull/629))

  On macOS, the Hub and Node no longer start child processes through `fork()` when they set the child's `PATH` or start a detached session. `fork()` from a multi-threaded process can deadlock the child.

  - **Programs are resolved before spawning.** A bare program name is resolved to an absolute path against the `PATH` the child will get, using the single resolver in `steve-runtime::process`. Without this, Rust's standard library falls back to `fork()`. If a program cannot be found, the error names the program and the `PATH` that was searched. This covers:
    - MCP capability servers the Hub starts (`npx`, `node`, `uvx`, …);
    - harness adapters launched outside `sandbox-exec`;
    - the login-shell environment probe, where `$SHELL` must be absolute;
    - plugins.
  - **Detached sessions start without `fork()`.** The Hub's local service Node and the Node CLI's self-upgrade helper now start through `DetachedCommand` (`posix_spawn` with `POSIX_SPAWN_SETSID` on macOS), replacing `setsid` in `pre_exec`.
  - **Guard.** A new `spawn_path_guard` test fails when production code spawns a `Command` that clears the environment or sets `PATH` without a resolved or absolute program. The 7 existing sites that are safe for other reasons are listed with their rationale, and the list can only shrink.
  - Metric: `steve_process_program_resolve_failures_total{reason}`.

  Closes #621.
- **harness:** run Codex inside Steve's OS sandbox and keep its command output ([#631](https://github.com/Infranite/steve/pull/631))

  Codex now runs inside Steve's OS sandbox like every other wrapped harness (`nested_sandbox = true`). Workspace boundaries, toolchain and cache locations, the login environment, read-only research and control-plane protection now apply to it too. It is no longer listed as running outside Steve's sandbox in the **Full access** risk confirmation.

  Codex's own sandbox cannot start inside Steve's: macOS does not nest sandboxes, and `codex-acp` offers no switch that turns off only the inner sandbox. The permission levels therefore work like this (tested with codex-cli 0.171 and `@agentclientprotocol/codex-acp` 2.12.1):

  - **Ask**: Codex retries each shell command outside its own sandbox and asks you first. Approved commands run inside Steve's sandbox.
  - **Auto**: Codex's built-in reviewer approves safe workspace commands without asking.
  - **Full access**: no prompts. Steve's sandbox still keeps Steve's own files out of reach, but Codex can change anything the sandbox lets it write and can use the network.

  Research on Codex is now kept read-only by Steve's sandbox (`self_read_only = false`).

  Also fixed: Codex's command output was dropped on the way into Steve, so its tool calls showed no output. Streaming terminal output is now gathered into the tool view, within the existing length limits, and failed commands carry their exit code and error.

  Closes #620.
- close four races behind intermittent test failures ([#632](https://github.com/Infranite/steve/pull/632))

  Fixes four races that made tests fail intermittently on CI. Three of them were in the product.

  - **Store reader pool opened every connection up front.** `Store::open` built its SQLite reader pool with r2d2's default `min_idle`, which equals `max_size`. Every store immediately held 10 to 16 read connections, 23 to 35 descriptors, and never released them. Readers now open on demand and close when idle. Under macOS's default limit of 256 open files, restarting the Hub and Node repeatedly in tests ran out of descriptors ("Too many open files"). The `restart_matrix` tests now also wait for their runtimes to shut down.
  - **The adapter install lock could outlive its holder.** `PrefixLock` relied on `close()` to release its `flock`. A child forked concurrently on another thread kept the descriptor until it ran `exec`, so the lock could look busy right after it was dropped. A lease not handed to a child now unlocks explicitly. A Node's upgrade hold releases the lock before it clears its active flag.
  - **A forced harness update check could be dropped.** A fresh check requested while another check was running returned the old result. Concurrent fresh checks are now coalesced into a follow-up pass. The re-probe after an upgrade reads the refreshed cache and no longer schedules a redundant fresh check.
  - **Orphaned upgrade probes on Linux.** The updater could not read a process's start time on Linux, and an unreaped zombie counted as still alive. Recovery therefore skipped the orphaned probe it should stop. The start time now comes from `/proc`, and zombies count as gone.
  - `send_one` re-checks readiness inside its commit lock, and a retried turn waits until it has actually started.

  Closes #625.
- **install:** create the Hub database before setup issues the owner token ([#634](https://github.com/Infranite/steve/pull/634))

  A fresh `steve setup hub` completes again. Before, it stopped after the configuration check with "exit status: 2" on an empty data directory, so a first install could not finish.

  - **The database is created first.** Setup now runs a new `steve-hub --admin init-db` step before it issues the owner's first token. The step uses the Hub's own store opening and migrations. Old databases, half-finished installs and resumed runs are handled.
  - **A resumed setup always ends with a usable owner token.** If the receipt lists a token whose file is missing, setup issues a new one. Setup no longer prints "安装完成" with an empty user name or token.
  - **Failures say why.** When a setup or reconfigure step's subprocess fails, its own error output is shown instead of a bare exit status.
  - **Private directories are created with mode 0700.** This covers the Hub's `secrets/`, `data/`, `worktrees/`, `scratch/`, `workspaces/` and `updates/`, and the Node's `node/`. Symlinks and directories owned by another user are refused.

  Closes #633.

## Other changes

- **chore(ops):** run Steve from Rust only and remove the shell/Python runtime scripts ([#593](https://github.com/Infranite/steve/pull/593))

  - **Runtime operations are Rust only.** The shell and Python runtime scripts are gone from the repository, the release bundles and the Homebrew installer. `steve-hub` reads `<STEVE_HOME>/steve.env` itself, and launchd or systemd start it directly.
  - **One-time macOS upgrade command.** On macOS, `steve-hub --local-release upgrade-macos` moves an existing install to the new service shape. It validates the bundle, switches `current`, rewrites the plist, starts the service and probes `/healthz`, and rolls back automatically if any step fails. `rollback-macos` goes back by hand. Settings → About recognises the old service shape and shows this command.
  - **Linux upgrades in place.** The new Hub rewrites the systemd unit after the upgrade commits.
  - **Hardening.** CI, release and migration-lock guards are stricter. Startup no longer opens an empty SQLite write transaction. The public architecture and deployment docs match the code.


  Closes #581.
- **ci:** allow Node protocol bumps only for breaking changes, with a reason ([#607](https://github.com/Infranite/steve/pull/607))

  The Node protocol number now changes only when the wire format breaks, and CI enforces this in both directions.

  - **The rule is documented in code.** `steve-node-api`'s `PROTOCOL` comment and CONTRIBUTING spell it out:
    - Narrowing a type, removing a field, or changing semantics or a security boundary requires a bump.
    - Adding a `#[serde(default)]` field to a non-strict payload must not bump.
  - **No bump without a reason.** If a PR changes `PROTOCOL`, the PR lint requires that the change is exactly +1. The description must also contain both `Protocol-Bump: <category> — <reason>` (from an allow-list of categories) and `Upgrade:`.
  - **No silent incompatibility.** New baseline JSON fixtures in `steve-node-api/tests/ordinary_compat.rs` cover the main ordinary payloads. They must deserialize into the current types, including with unknown fields injected. The baselines can only change together with a protocol bump.

  Background: the protocol went from 14 to 18 in two days, and only one of those bumps was needed. Each bump forces every Node to upgrade.

  Closes #611.
- **refactor(hub):** move all agent work out of the Hub into Node processes ([#606](https://github.com/Infranite/steve/pull/606))

  The Hub no longer runs agent work in its own process. All coding sessions, model and research jobs, project directory operations, Git and stdio MCP servers now run in Nodes: the Hub's own local Node is a separate `steve-node --local-node` process, plus any paired remote Nodes. Differences between harnesses are handled in the adapter layer and the declarative harness spec, not in the Hub.

  - The in-process local Node mode (`STEVE_NODE_MODE=local`) is gone.
  - Hub restarts and upgrades no longer interrupt work running on the local Node.
  - Paths that are reported or compared are canonicalised (for example macOS `/var` → `/private/var`).
  - Background loops (outbox, daily backup, price sync, digest intake, calendar sync, …) use the single `steve-runtime` due loop.


  Closes #583.

  Library stdio MCP servers now run only where an OS sandbox backend is available (macOS Seatbelt, or bubblewrap on Linux).

  While an older local Node from before this release is still finishing its turns, Steve shows "local Node updating" and routes no new model, research or host work to it; the Node is replaced as soon as its last turn ends.
- **ci:** check PR descriptions in their own workflow ([#628](https://github.com/Infranite/steve/pull/628))

  Editing a pull request's title or description now re-runs only the new `PR description` check, a few seconds of `ops/cut-release.py lint`. Before, it re-ran the whole CI workflow and cancelled the run in progress. The CI workflow no longer listens to `edited`. Main's branch rules will require `PR description` next to `CI gate` once this is merged. A merge queue run passes it without checking, since it has no description.

  Closes #627.
- **docs(deploy):** macOS owners on v0.13.0 also upgrade once from the terminal ([#636](https://github.com/Infranite/steve/pull/636))

  macOS owners on v0.13.0 or earlier: upgrade once from Terminal with `steve-hub --local-release upgrade-macos`. Do not use Settings → About for this upgrade. Those versions' About page cannot detect the old launch setup. The deployment guide used to say only v0.12.0 and earlier needed this.

  Closes #635.
