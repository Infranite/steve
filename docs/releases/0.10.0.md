# Steve v0.10.0

Needs a minor release: existing macOS Nodes need a one-time administrator-approved service migration; the Hub cannot manage macOS Node deployment or removal remotely.

- After finishing the Node's sessions, run `steve node enable-boot` as its existing macOS user and approve the one-time sudo prompt. This retires the login LaunchAgent and registers one system LaunchDaemon that runs as that user before desktop login. Migration corrects stale receipts from the running release or the newest verified installed bundle. The pairing, identity and data stay in place.
- Devices now shows why the Hub considers a Node offline and for how long, including when it has no evidence beyond the missing connection.
- Once the Node is running a signed boot release, upgrade it from **Devices** even when nobody is signed in. The supervisor switches release directories without sudo and the helper rolls back if the replacement fails to link. `steve node update --release <bundle>` also remains available locally. Devices distinguishes harness authentication failures from an offline Node.

Needs a minor release: drain active Node work and upgrade Nodes with the Hub because ordinary Node requests and journal receipts use a new error format.

Node requests and tool results now carry the same structured errors and retry advice as the Hub. After a lost response, query the original operation before retrying. The Node upgrade connection still works across ordinary protocol versions.

Session and worktree commands keep their operation identity and acceptance window during retries. The Hub reconciles commands whose effects are uncertain and stops automatic sends when their budget is exhausted.

A Flow command whose process outlived the Hub keeps its unknown result after its deadline. An explicit rerun first tries to retire the original command before starting a new one.

Steve holds a running turn when the same observed tool action fails five times or when fifteen minutes of observable work pass without verified progress. Approval waits and disconnected Nodes pause that clock. Steve requests a stop once and keeps the same decision card across restarts. Continuing requires the Node to confirm that the attempt ended.

Retrying a work unit preserves downstream work while it waits for replacement evidence. Verified equivalent immutable deliveries can keep downstream results valid. Failed independent reviews can name the affected units and criteria, and stale or unverified findings leave existing results in place.

Needs a minor release: Upgrade the Hub and Nodes together for the new gateway phase and capability reports. Gateway calls now use only the first configured model; reorder the list if you want a different default.

Short model calls now report queue, first-response, and execution timeouts separately, or report an unknown phase when there is no reliable evidence. A call that needs attached-file tools is refused before it starts if the selected adapter does not advertise them or the files are not authorized. Tool refusals use the existing controlled handoff where allowed. Reported token usage still counts on failure and can be reconciled after a timeout.

Needs a minor release: the Node protocol carries file-access observations. Update the Hub and its Nodes to the same release before resuming work.

- On a macOS Node, the first interactive `steve node enable-boot` checks access to configured protected locations. If it finds a denial, it opens Full Disk Access settings with your approval and shows the exact supervisor executable to enable. Run `steve node file-access` on the Node to repeat the check after changing its folders or permissions.
- Devices shows the Node's file-access status and lets you recheck after granting access. The macOS service keeps its signed supervisor in place as you switch release bundles.

Needs a minor release: Update the Web client with the Hub. Item and session views now carry Bot selection explanations and replace the item detail's previous dispatch placement field.

Steve checks workspace and Team access, the project, and available execution Nodes before ranking Bots by specialties and description. Items and sessions show the recorded reason for the choice alongside the session's recorded harness and model. Workspace owners can review and confirm an editable Bot proposal when an automatic request exposes a gap.

Needs a minor release: Back up the Hub database before upgrading; the former YOLO settings, action history and API are removed. Reinstalling the previous binary does not restore them.

The workspace owner can turn on **More → Native approval (YOLO)** to use a supported harness's native approval mode. It starts off. Pending mode changes take effect at an idle boundary; session views show the mode the Node actually applied. YOLO no longer answers Steve decision cards, including questions, acceptances and personal sends. Existing decisions and observed external results are retained; old unsent automatic approvals do not send anything after the upgrade. Statistics show auto-mode use, permission requests and agent question cards.

Turning a conversation into an item no longer requires the main Steve Bot to belong to the workspace’s default Team. If placement finds no eligible Bot, the item is still saved, without starting a session. Its details explain the blocker and let you choose an eligible Bot.

The Hub queues new work for its local service Node during startup and dispatches it after reconciliation.

Bot 页的「新建 Bot」按钮移到 Bot 列表上方，与「新建 Team」的布局和样式一致。Bot 卡片展示当前工作空间内已加入的全部 Team，未加入时显示「未加入 Team」；编辑 Team 后，卡片上的归属信息同步更新。

Main chat batches live reply text so typing and scrolling can take priority. Offscreen draft text skips layout and paint, and code fences show plain text immediately before syntax coloring runs in the background. History keeps its reading position as rows are measured, and opening a process reveals its card headers before formatting arguments and results.

The Hub's queued-turn tests now wait for the Node's start event and receipt to be committed before finishing a fake attempt, so CI reliably checks that a queued message starts a new turn and the item hears one completion.

Returning to a chat reading position now keeps the same message and offset while older pages load. Jumping to the latest reply also cancels any history scroll still in progress.
