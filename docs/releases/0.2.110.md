# Steve v0.2.110

新增当前 Hub 管理入口：实例所有者可保存共享名称与用途备注，成员读取相同信息；稳定身份和地址只读，权限撤销与并发版本冲突不会静默覆盖。浏览器与 Apple 客户端支持独立个人别名编辑及清空，旧服务或旧桥不支持时明确提示，离线快照注明读取时间。

设备页优先显示需处理请求，再展示其他当前工作，最近会话折叠收纳；保留会话、队列消息与原始状态身份。监控区分读取失败、无样本、过旧和断采，负载不冒充 CPU 利用率，容量使用 GiB，无历史的磁盘不画趋势。设备关联仅使用可信稳定标识，缺失事实显示未知。

本地设备配置由实例所有者按 revision 保存，统一支持整数并发上限 1–256，已有 32 在暂停或恢复时保持不变。暂停接活或调低并发仅限制新回合，不中断已接受执行及重试、不丢队列或自动迁移。旧客户端缺 revision 时返回刷新或升级说明。新增设备配置 revision 的数据库迁移，公共操作与兼容合同见部署文档。

Repository work now starts with a GitHub issue and is handled through a dedicated pull request linked to that issue, including documentation and maintenance changes. Unrelated work belongs in separate issues and pull requests.

- **Items hierarchy**: Workflow subtasks now group directly beneath their parent item with visual tree connectors and collapsible settled/historical attempts, keeping the top-level list, board, and running counts focused on main items.
- **Workflow convergence & budgets**: Bots can no longer raise `max_attempts` or loop replans endlessly; global concurrent workflow units are bounded per Hub (`STEVE_WORKFLOW_MAX_PARALLEL`, default 4) with automatic slot wakeup.
- **Scoped checks & safer auto-acceptance**: `steve_deliver` checks accept `scope` (`unit`, `baseline`, `external`) so unrelated baseline failures can be reported without blocking unit handoff, while parent `auto` acceptance holds deliveries with failed non-baseline checks or `unfinished` steps for user confirmation.
- **Harness ingress & output guards**: The stdio ACP frame limit is raised to 16 MiB and `outputs/` rejects embedded checkouts, `node_modules`, `.git`, and build directories.

Device configuration now checks the current owner's permission, configuration revision and write in one transaction, so a request waiting behind a committed revocation is rejected without changing the device. The concurrency editor, API and Store accept integers from 1 through 256 and preserve existing values such as 32 when pausing or resuming. Older clients without a configuration revision receive a 400 response and must refresh or upgrade; stale revisions still return 409. These settings affect new turns only, preserving queues, accepted attempts and retries.

统计页“现在”区域新增输出 TPS、输出会话数和近 60 秒趋势，每秒通过 `GET /api/stats/realtime` 更新，只跟随项目与 Bot 筛选，不受历史日期范围影响。TPS 为最近 10 秒输出 token 数除以 10；输出会话数为该窗口有输出的唯一会话数。页面支持中英文、窄屏、键盘查看和趋势明细。

实时数据区分实测、文本估算、无输出、不可用和部分覆盖。当前全部注册 harness（含 Pi）在未验证定时输出 token 契约前仅使用可见输出文本估算，不将累计 usage、结束账单或上下文 token 当作实时输出。趋势缺失点保留断线，覆盖不完整时 TPS 和会话总量均待确认，不用局部观察值替代未知总量。说明分别区分 3 秒采集新鲜度与 5 秒接口响应陈旧；接口缺失、网络异常、响应不兼容或陈旧数据不显示为实时零值。

采集记录持久保存并可回读，重放去重、迟到事件和异常停止时间不会制造输出尖峰或抹去近期输出。升级时依据已持久的 Node 停止事件及匹配终止回执恢复有界未知区间，已确认停止及未发出的取消不永久污染当前统计；缺乏可信停止证据时仍保守保留未知。滑窗查询使用带索引的时间边界，采样与文本偏移按会话及执行保留策略保存。

Bot 创建、修改和配置卡片应用会按所属 harness 成功报告的模型与思考强度清单校验，拒绝不支持的值；harness 新提供的强度也可直接保存。只换 harness 时会检查保留的旧值，不兼容时需同时选择支持的值或显式恢复默认（`null`），不会静默改写其他字段。

未取得清单或探测失败时保留未知语义，仍检查输入格式，但不宣称模型已可用；成功返回的空清单不会再混入内置备用值。已有旧配置不妨碍单独修改职责、工作规范等无关字段。会话启动仍核对模型和思考强度实际生效情况。

Add an isolated, bounded Codex MCP diagnostic for maintainers, with separate startup, text and tool round-trip results, partial timeout evidence and optional Responses tool-protocol observation. Tool success requires matching MCP responses, the corresponding ACP completion and the model's final consumption of the returned marker. Document reversible model substitution, exact adapter-reported model ids, existing-session limits, the Bot API's lack of atomic revision preconditions and the difference between diagnostic evidence and production recovery. Runtime model compatibility and Bot configuration are unchanged.

The maintainer's isolated MCP diagnostic now tracks observed adapter descendants by PID and process birth identity, waits for each tracked process, and forcibly stops verified survivors after a bounded grace period. Cleanup also covers tracked descendants after their adapter exits; remaining or unverifiable processes make the diagnostic fail and are recorded per PID. Offline regressions cover these cases without calling a model service.

Git worktree projects now default to completing on PR merge (`done_when: "merge"`) when created in the UI, always expose the **Done when** setting even before a custom release script exists, and accept both `release` and `done_when` updates in `PATCH /api/projects/:id`.
