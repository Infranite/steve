# Steve v0.2.66

- 完全放开下，Agent 的命令仍然不先问你，但 Steve 会检查 Agent 报告的每个工具调用：推送（git push）、用 gh 改 GitHub、用 lark-cli 或 sendmail、mail、osascript 等以你的名义发消息、碰 ~/.steve、8440 端口或 launchd、用 pkill/killall，会立刻停下这一轮，在会话里记一笔并通知你，Agent 下次收到消息时也会知道原因。这是事后拦截：那条命令可能已经开始执行，Agent 没报告或藏在脚本文件里的命令看不出来。YOLO 打开但没完全放开时，Agent 没先请求权限就直接执行的命令也按同样的底线检查。不论用哪种 Agent 都一样。完全放开的确认对话框改成只写实际做得到的事，也写明做不到的。
- YOLO 不再替你批准 lark-cli、sendmail、mail、msmtp、osascript：它们会以你本人的身份发消息或邮件，即使你把它们加进了额外程序，也一律留给你。
- YOLO 打开时，这些命令留给你确认：带对外字眼的内联代码（python3 -c、node -e 等）、含 system()、管道或写文件的 awk 程序、通过管道喂给 python3、node 等解释器的程序（包括 here-document）、git bisect run、npx 运行常见构建工具以外的包（别的 scope 下同名的包也算）、带查询参数或路径很长的网页抓取。ps、pgrep、lsof、喂给 cat 等读取命令的 here-document，以及 git tag、git worktree list、git cherry-pick 等本地 git 命令，现在可以直接替你批准。
- Agent 的进程不再继承 GH_TOKEN、GITHUB_TOKEN 和 SSH agent（SSH_AUTH_SOCK），不论 YOLO 开没开。交付时的推送由 Steve 用保险箱里的凭据完成，不受影响；Agent 自己运行需要 SSH 的 git 命令（例如 git fetch 一个 SSH 地址的远端）会失败。
- 有自己工作区（worktree 或临时目录）的事项，不开 YOLO 时 Agent 改文件也不再逐个文件问你。
- YOLO 打开但没完全放开时，Agent 问“要不要删掉旧测试文件”“日志发到 stderr 还是 stdout”这类普通编码问题，YOLO 可以替你回答；涉及上线、推送、发布、发邮件的问题仍然留给你。完全放开时所有对外字眼都留给你。
- 从邮件、GitHub issue 建的事项，Agent 会把内容当作别人写的不可信数据，不会因为里面的指令去推送、发消息或读密钥。流程从外部事件（邮件、消息、GitHub、Webhook 等）建的事项，事件带来的内容同样被当作不可信数据；你在流程里自己写的目标，以及手动、定时流程建的事项，仍然算你的要求。群聊里建的事项，你自己发的消息仍然算你的要求，只有之前的对话和别人发的消息被当作不可信数据。
- 修复：事项分支名以“-”开头时，查看输出文档不会把它当成 git 的参数。

- 渠道外发的披露检查更快了：建事项的回执（“收到，已记为 …”）和转交时的“我请 … 来看”是固定模板，不再调用检查模型，只做机密和规则检查；机器人账号自己写的回复，听众全是本工作区成员、用到的知识对他们都可公开时，也不再调用检查模型（以你本人或代你发的、智能体和流程直接给出的文字仍要过检查模型）。检查模型的超时从 60 秒降到 20 秒。
- 反正要等你批准的草稿不再先自动改写，你看到的是原文和标出的可疑片段（开着 YOLO 时仍先改写一次，因为 YOLO 不会批准可疑的原文）；卡片上多了“改写后再看”，点了会改写一次、重新检查，再出一张新卡片。能直接发出的回复，可疑时只改写一次（原来两次）。
- YOLO 让机器人账号首次向内部群发消息时，冷却时间从 10 分钟缩短为 1 分钟（新增设置 `chan_bot_delay_s`，默认 60 秒）；这类消息不会被当成你本人发的，发出后仍可撤回。以你本人身份发的消息和邮件仍等 10 分钟，发送失败后的重试仍等 5 分钟。
- 批准后的撤销窗口按身份区分：机器人账号 3 秒，你本人和代你发送的仍是 10 秒；YOLO 已经等过冷却期的消息批准后立即发出。每个接入账号可以在账号页单独设置这个时间（0–60 秒）。
- 邮件草稿：没有开 YOLO 时，写草稿只做本地的机密和规则检查，不再等检查模型；卡片上显示“没有做披露检查”，旁边有“检查披露”按钮，需要时再检查。开着 YOLO 时仍在写草稿时就检查。
- 路由更快：路由模型超时从 60 秒降到 30 秒；一个模型超时后不再换下一个模型重试（报错类的失败仍会换下一个），统计里的失败记录会标出超时。
- 发给事项的消息（`/汇报`、从事项发、引用事项的消息、`#ST-n`）不再排在正在进行的回答或研究后面，会马上送到；回执可能先于研究答复出现。
- 单纯的提问（不带附件、不点名机器人、不提事项和设置、不要求建事项）不再先问路由模型，直接就地研究，大约省 6 秒；群聊里 30 字以内的这类短问题直接回答，更长的问题仍由路由模型决定（开了研究的群里仍可能去研究）。
- 研究输出结束后进程迟迟不退出时，最多再等 45 秒（原来最长 10 分钟）。

- 流程在执行对外动作前要你批准时，批准卡多了一个选项“此流程当前版本以后都执行”：选它之后，这条流程的这个版本再运行到同一步就直接执行，定时流程可以真正无人值守。授权只对当前版本有效，改过流程（存成新版本）后会重新问你；http 请求只对卡片上的那个主机生效，地址由模板拼出来的请求不提供这个选项；以你本人身份发的消息仍然先起草、等你确认；保险箱里“高”级别的条目和银行卡不能这样授权。这一步还用到保险箱机密时，这个选项也一并授权这些机密，以后运行不会再为机密弹卡。流程路径上已经有一个“等你批准”节点时，后面用到的保险箱机密不再另外弹一张卡（“高”级别的条目和银行卡除外，仍会为这一步单独问你）。
- OpenViking（语义检索）停了的时候，知识检索不再整个失败：仍然按关键词查找，并在对话、事项会话、渠道回复和邮件草稿拿到的知识里，以及知识页的搜索结果上注明“语义检索暂时不可用，这次只按关键词查找”。一次失败后 45 秒内不再去连 OpenViking，不会每次都等到超时。
- 知识库可以添加 iCloud 云盘（`~/Library/Mobile Documents`）和 Dropbox、OneDrive、Google Drive（`~/Library/CloudStorage`）里的文件夹，例如放在 iCloud 里的 Obsidian 仓库；这两个目录本身和 `~/Library` 的其他位置仍然不能添加，云盘里的文件夹只收录 `.md` 和 `.txt` 文件。
- 新建“建事项”类的定时任务（建事项并开始、建事项并开始且自动验收）时，每次预算默认 $20，不再是 $1，避免普通的一次运行就被预算拦下；汇报和先给方案仍是 $1。超出预算后选“继续一次”，新的上限取“原上限的 2 倍”和“这次已花费的 2 倍”中较大的那个，一次超出很多时不会连着再弹卡。
- 流程里分支和连线对不上时会提示：连线的名字对不上任何分支（这条线永远走不到）标为需要处理，分支没有对应的连线（走到这里流程就停）标为提醒。画布上方列出这些提示，点一下打开对应节点；Steve 起草或修改流程时也会在草稿里写出来。在画布上给分支改名时，它的连线跟着改名。运行时走到一个没有连线的分支，这次运行的结果会写明“分支「…」没有连线”，不再悄悄结束。
- 流程里 http 节点能访问的内网主机（本机、局域网、Tailscale 地址）现在是一个真正的设置，在「自动化 · 流程」页底部的「允许访问的内网主机」里填写；只有工作空间的所有者能改，Steve 起草的流程不会改它。
- 事项成果里的大文件不再显示“文件太大，不在这里打开”：录屏等视频和音频可以直接播放和拖动，PDF 可以直接打开，任意大小都能下载；只有超过 64 MB 的图片和 Office 文件仍只提供下载。
- 附件不再只限于图片、PDF、文本和 zip：认不出类型的文件（例如录屏）也能上传，存为普通文件，只能下载、不会在页面里打开，文件名保留原来的扩展名。选择文件时可以直接选 Word、Excel、PowerPoint 和 EPUB 文件。
- 交付后、验收前改动了工作区时，验收通过时先发现改动并作废这次交付，不会先弹出发布或开 PR 的卡片再作废；等你验收期间，后台的定时检查不再每 10 秒对整个工作区计算一次指纹。计算工作区指纹的 git 超过 20 秒时视为“暂时不知道”，收尾继续等待、稍后再查，不再当成“结果变了”而作废交付。
- 统计重建和“今天”按小时的图表，现在把每个回合记在实时统计记下的同一个模型名下，重建前后数字不再对不上（例如被重启打断的回合）。
- 删除联系人时，被一并删掉的属性、只关于这个人的记忆和团队成员关系，会按原样记进这次删除的审计记录，需要时可以照着恢复。

- 后台投递（事项完成后的流程触发、邮件事件、GitHub 后续动作等）遇到网络或对方服务的临时故障时，会持续重试一整天才放弃，而不是约 4 分钟后就永久放弃；被明确拒收的仍然立即放弃。放弃后每个投递方只发一条通知，“设置 · 数据 · 后台投递”里可以看到原因并一键重新投递。
- 附件写入改为先写临时文件再整体替换，断电不会留下被截断的附件；以前留下的截断附件，在同一文件再次上传时会自动修复。
- 没有项目的事项在临时目录里工作。事项结束后，磁盘紧张（低于回收线或开工下限）时 Steve 会回收其中的 node_modules、target 这类缓存目录，其他文件不动；“设置 · 数据 · 工作区与磁盘”里单独列出这些临时目录的占用。
- “会话记录保留”改为只读显示当前值（默认永久，不清理）。以前这项设置不起作用，所以升级时所有工作区都恢复为永久，之前选过的 90 天或 1 年不会生效。如果通过对话把它改成 90 天或 1 年，事项归档满这段时间后，会话里的图片换成占位，很长的工具输出只保留开头和结尾。
- “接入”页不再列出尚未支持的服务（Slack、Google 日历等）；飞书里规划中的能力照常显示。
- 数据库新增失败计时字段和会话压缩记录表（迁移 045）。

- 智能体更难拿到 Steve 自己的机密文件了：在 Steve Node 上运行的 Claude Code 会话，以及思考和读附件的调用，在所有权限模式下（包括“完全放开”）都不能用 Claude Code 自带的读写工具打开 `~/.steve` 下的签名身份、secrets、备份、升级记录（含升级控制令牌和升级前的数据库副本）、steve.env、数据库、附件、原始邮件和各 Node 的状态。这只管 Claude Code 自己的读写工具：它在终端里运行的命令（比如 `python3`、`sqlite3`）还能读到这些文件。Codex 读附件的调用是在系统沙箱里禁读的，命令也读不到。会话里的 Codex 暂时还读得到：给 Codex 加上禁读规则后，你批准在沙箱外运行的命令也只能留在沙箱里，“每次改文件或运行命令都问你”这个模式下就改不了任何文件。智能体的工作目录不受影响。启动智能体时也不再带上指向保险箱和机密文件的环境变量。
- 签名钥匙串的密码不再放在 `signing/keychain-pass` 这个普通文件里。Hub 启动时会通过 steve-keyhelper 把它移进登录钥匙串，再给签名钥匙串换一个新密码，然后删掉文件，每日备份也不再打包它。以前的每日备份里和被读走的旧密码从此打不开签名钥匙串。设置里的一键升级照常可用，升级任务从 Hub 那里拿到密码，但只在升级的是本账户的 `~/.steve`、所用 Python 在系统或 Homebrew 的目录里、并且重新读到的发布清单指向同一个 commit 时才交出；一键升级不再使用 `STEVE_PYTHON` 和 `PATH` 里别处的 Python。在终端里手动运行 `ops/release.sh`、`ops/sign-setup.sh` 或 `local-release.py build` 时，macOS 会弹窗确认：请点“允许”，不要点“始终允许”，否则任何程序都能悄悄读到这个密码。不在终端里运行时（包括 Hub 为“发布”启动的 `ops/release.sh`），它们会停下，请改用设置里的一键升级。
- 签名钥匙串只在签名的那一刻解锁，签完就锁上，签名失败也一样；它还会在闲置 5 分钟后和睡眠时自己锁上。解锁时密码不再出现在命令行里，同一用户下的其他程序用 `ps` 也看不到。
- 备份只有你自己能读：清理前的备份、发布前的备份都改成 600，备份目录改成 700，发布时会把以前留下的旧备份和 steve.env 副本一起改过来。
- 轮换保险箱主密钥一次做完：所有条目的数据密钥在同一个事务里重新包裹，旧版本立刻作废，不会再中途卡在“正在轮换”。以前的版本留下的未完成轮换，Hub 启动时会补完。
- 连接因为钥匙串被锁而用不了凭据时，同一个连接一小时内的连续失败只记一条（更新最后失败时间），连接也会等一会儿再试（30 秒起，最长 5 分钟），使用记录不再被几百条失败刷屏。
- 在对话里粘贴了密码或令牌，消息不再整条丢掉：机密部分换成［已拦下的机密］，其余内容照常交给 Steve 处理，下面附一条提示，说明可以存进保险箱。改写排队中的消息也一样处理。日志里的毫秒时间戳和 `${DB_PASSWORD}`、`<your-password>`、`/run/secrets/…` 这类占位写法不再被当成机密拦下。

- 登录后的跳转只回到本站页面：`//别的网站`、`/\别的网站` 这类地址一律回到首页。
- 本机一键登录（`STEVE_DEV_LOGIN=1`）只认直接从本机打开的浏览器：Host 必须是 localhost 或回环地址，并且请求没有经过反向代理（带任何转发头都不行）。
- `STEVE_HOST` 可以用逗号写多个监听地址，例如 `127.0.0.1,100.64.0.2`，Hub 会逐个监听。`0.0.0.0` 和 `::` 会让局域网里的所有设备都能访问，现在默认拒绝启动，除非同时设置 `STEVE_ALLOW_ANY_HOST=1`，这种情况下启动时会给出警告。
  - 升级前请先改 `steve.env`：如果 `STEVE_HOST` 还是 `0.0.0.0` 或 `::`，先改成具体地址（例如 `127.0.0.1,100.64.0.2`），或者加上 `STEVE_ALLOW_ANY_HOST=1`，否则新版本启动不了，升级会失败回滚。
  - 改成逗号列表之后，比这一版更早的版本读不懂这个写法，会监听失败。要退回旧版本，先把 `STEVE_HOST` 改回单个地址。
- 对话和新建事项重发不会再重复：同一份草稿重试时（网络断开、刷新页面、连点，包括发送还没完成就断线）用同一个标识，Hub 在 10 分钟内只处理一次；改过草稿后再发就算新消息。

- 聊天消息有了“水位线”：接入（或重新接入、恢复、开启新能力）之前写的消息，以及写完超过 30 分钟才送到的消息，现在只存为旧消息并记录下来，不再运行规则、触发词、意图判断、流程，也不起草回复、不建卡片。不管消息是哪个适配器（包括插件）送来的，都由 Hub 统一把关。判断时给双方时钟留了 2 分钟余量；被编辑过的消息从最后一次编辑的时间算起。迟到的时长可以按账号设置（`PATCH /channels/:id` 的 `late_minutes`，1 到 10080 分钟），账号信息里会显示有多少条接入前的旧消息和迟到消息。在会话里，这些消息照常显示，旁边带一个不显眼的“旧消息”标记。只因旧消息出现的新群，会等有人现在说话时再问你要不要设置。
- 你本人发的消息不会再被当成别人的消息来起草回复：在以你本人接入的账号上，发送者是你的“我”、并入了“我”的联系人，或者发送者的句柄是“我”的账号句柄、别名或你的登录邮箱时，这条消息就算你自己的，不起草、不发送、不建确认卡片。（发给机器人的消息照旧由机器人回应。）新出现的联系人如果和“我”同名、邮箱域名也是你在用的，或者邮箱就是“我”的别名，会出现一张“可能是同一人”的合并建议卡片，只是建议，不会自动合并。
- 新增智能体工具 `steve_im_read`：任务需要时读取某个会话在一段时间里的消息（参数 `space`、`from`、`to`、`limit`），只作上下文，不会回复、不会触发规则或流程、也不会存成新消息。它只读你能看到的会话，带上会话的披露级别，屏蔽或不使用的会话不读，输出有长度上限。渠道插件可以提供可选的 `HistoryRead` 能力（Extension API 2 内新增，不破坏现有插件）从平台实时读取；没有提供时读 Steve 已存的消息。内置的“飞书 · 你本人”已支持实时读取。

- 合并通道：批准卡还没回答时到达的合并请求，直接并入这一批，批准卡换成一起列出它的新卡（加入前打开的旧卡不能再批准，你批准的总是实际要合并的那些），不再另开一批、等满 2 小时。项目页的合并通道可以看到在途和合批中的批次，能设置合批窗口和每批上限，并新增“立即合并发布”按钮，让正在合批的一批不再等窗口。
- 合并通道不再直接推送到托管方要求经 PR 或合并队列合入的分支（即使你有绕过规则的权限）：在出批准卡之前就会拦下，事项上出一张卡告诉你原因，不再退回给执行者重做（它改不了这条规则）；推送前还会再查一次。
- 合并通道里结束的批次（已发布、放弃发布、全部退出、发布并入下一批）会删掉它的临时工作目录和批次分支；发布失败等你重试时保留。
- 合并通道从来没有实际运行过“合并前检查”，项目页的文字改成“托管方要求的检查”，并说明实际的把关是每项交付时的构建，以及打发布 tag 前推到 main 的 CI。
- GitHub 仓库设置的“验收后”新增“直接开草稿 PR”：只对私有仓库生效，验收即视为同意，提交先过泄露检查（逐个提交检查新增内容和提交说明，后面的提交又删掉的机密也算；含二进制改动时也会问你），只推事项自己的分支，PR 一律开成草稿；验收时会向 GitHub 重新确认仓库现在仍是私有（关联后改成公开的仓库、查不到可见性时都按公开处理），公开仓库、泄露检查有发现、事项在 Node 上时仍会出卡片问你。合并仍然每次问你。
- 通过个人令牌（PAT）连接的仓库，开 PR 和评论的确认卡上会注明“以你的 GitHub 账号发出”。
- 合并通道按目标仓库和分支共用：项目页只列出你所在工作区的合并请求，其他工作区的只显示数量；通道里还有其他工作区的合并时，不能在这里改合批设置或立即合并。
- 目标分支要求经 PR 合入时，正在拦下的那一批不再收新到达的合并请求，新的请求进入下一批，不会卡在没有批准卡的批次里。

- 本机发布（一键升级和 `ops/local-release.py deploy`）在新版本健康之后会清理旧文件：发布前的数据库备份保留最新 8 个（连同 -shm/-wal），release 目录保留当前、上一个和最新 3 个；pre-rust、pre-purge、pre-takeover、每日备份和 failed-probe 不动。部署没成功时什么都不删。想现在就清理一次，运行 `ops/local-release.py prune`（先加 `--dry-run` 看会删哪些）；单独运行时也保留上次成功部署前的那个版本，回滚目标不会被删。
- 测试改在打 tag 之前跑：每个 PR（Linux）和每次推到 main（Linux 和 macOS）都跑完整测试。`ops/cut-release.py cut` 只给推到 main 后 CI 通过的提交打 tag（同一提交在 PR 上只跑过 Linux 的结果不算），CI 还在跑就等它，失败或没跑就拒绝，并给出重跑失败任务的命令 `gh run rerun <id> --failed`；`--skip-ci` 可以明确跳过。打 tag 后的 Release 构建只负责构建、打包和发布，偶发失败时在同一个 tag 上重跑即可，不用再发一个新版本。
- Steve 自己的项目不再用本机的 `release.sh` 发布，改走合并通道：`steve_publish` 把分支交给合并通道，Steve 合并后用仓库自己的 `cut-release.py` 发布（Hub 由 launchd 启动、PATH 里没有 `gh` 时，也会按 `STEVE_GH`、Homebrew 和 /usr/local 的位置找到它），合并并打 tag 后事项完成。已有的 Steve 项目会自动迁移（手改过的发布命令不动）；给 Agent 的发布提示也改成指向合并通道，不再让它自己推送或打 tag。
- 合并通道的发布一步会等合并后的 CI 跑完，最多等 30 分钟（整个发布一步最多 45 分钟，超时就停下）；还没跑完或失败时给出“重试 / 放弃”卡片，卡片开头写明原因：CI 偶发失败时先用卡片里的 `gh run rerun <id> --failed` 重跑，等它通过后再点重试，否则重试会再次被拒绝。

- YOLO 等你的时候少了：工作区内的工具权限不再因为你刚发过消息而多等最多三分钟；排在队里的消息只在三分钟内算你“在场”。
- YOLO 不再轻易整区暂停：只有会话出错或 Hub 重启打断的失败卡才算系统性问题，同一件事项只算一次；你撤销 YOLO 的决定后，只把那件事项移出 YOLO，1 小时内在 3 件事项上撤销、同一条规则在 2 件事项上被撤销，或撤回 2 条消息，才整区暂停；YOLO 自己执行前复查发现“先等等”或“留给你”时照常处理，不再暂停；执行前出错 10 分钟内连续 3 次才暂停。
- YOLO 发布两次之间至少隔 15 分钟，太快时会等到时间再发，不再把发布卡留给你；去掉了每小时最多 3 次的限制。
- 验收卡上可以直接选“验收并发布”或“验收，先不发布”。选验收并发布时，Steve 按你验收的那份结果直接 rebase 并开始发布，不用再等 Agent 申请、再点一张发布卡；分支在验收后又有改动、已有发布在进行，或工作区在其他设备上时，仍按原来的方式由 Agent 申请发布。按 PR 合并或推送 tag 判定完成的项目，验收卡仍只有“验收通过”，完成仍以合并或 tag 为准。
- 待处理里的记忆确认合成一行“N 条记忆待确认”，点开进入 知识 › 待确认 批量处理。你在对话里明确说“记住”“以后”的，会直接保存并发一条通知，不对可以改或撤销；要替换已有记忆的仍然先问你。过期没处理的候选可以在待确认页底部恢复。
- 在对话里说的本地设置（语言、启动页、免打扰、归档天数等）和联系人、组织、团队的字段修改，会直接应用，卡片上显示“已应用”并可撤销；保留期限、默认验收方式、YOLO、GitHub、渠道、邮件，以及新建、删除或有没认出的名字时，仍然先给你预览。撤销时，你之后又手动改过的字段会保留现在的值，并告诉你是哪几项。
- Agent 在对话里说某个机器人、账号归谁负责时直接记下，不再弹确认卡，24 小时内可以撤销。
- Agent 停下来汇报方案、列出待确认事项，或回答你在对话里追问的问题时，Steve 不再自动让它继续，而是交给你看；让它继续时也会提醒它有意停下要用 steve_ask 提问。

- 磁盘慢或 Hub 忙的时候，正在进行的回答不再被中途取消（原来会以“ingress budget exceeded”结束）。Steve 跟不上时，Agent 会等它跟上再接着输出，回答完整送达，只是可能慢一些。只有 Steve 连续 5 分钟一点输出都收不下（例如磁盘卡死）时，才会停下这一轮，并写明原因；输出超过上限或单条消息超过 1 MiB 时也会写明是哪一种。
