# Steve v0.2.98

- 只改发版说明的推送（每次发版自动推上来的那一个提交）不再重跑 Rust 测试：它等前一个提交的 CI 通过后直接放行，省下一整轮两个平台的编译和测试。前一个提交没通过、改了别的文件、或者查不清楚时，照常全跑；PR 永远全跑。
- CI 的依赖缓存只在依赖或编译配置真的变了时才保存一份，不再每次推送都存 0.6 GB（之前缓存总量超过 GitHub 的 10 GB 上限，一直在被淘汰）。改了依赖的 PR 现在从 main 最近的缓存起步，不再从零编译。
- 发版构建不再保存缓存。每个版本都存一份 0.5 GB，但 GitHub 不允许下一个版本读上一个版本的缓存，所以从来没被用上过，只是每次多花半分钟、多占空间。
- CI 和发版的每个任务都有了时限（Rust 测试 45 分钟，发版构建 40 分钟，其余 5 到 15 分钟）。卡住的任务到时会被终止并报失败，不再占着机器等 GitHub 默认的 6 小时。
- CI 每次运行附带一份编译耗时报告（cargo-timing.html），能看到编译时间花在哪些 crate 和测试程序上。

- 多表业务写入（配置变更应用与撤回、事项工具提问/审批/计划更新、失败卡片生成、依赖变更、目标修订等）现通过可重入的 `Store::atomic` 在同一 SQLite 事务中提交或整体回滚；嵌套写作用域通过 `SAVEPOINT` 隔离，变更事件、诊断记录与 outbox 唤醒统一在外层提交后发出。
- 开启 `STEVE_PRINCIPAL_STATE=on` 后，Owner 可通过已认证的 `GET /api/sessions/{id}/principal-state` 直接查询会话的凭据主体状态，无需再使用开发态内部 Header。
- Hub 事件总线的内部监听通道改为有界队列加同键溢出合并，慢消费者不再无限堆积内存；`/api/state` 缓存改为按工作区统计变更代数，不再因其他工作区的写入被连带清空。
- 知识库同步到 OpenViking 时，先读出分块并归还 SQLite 读连接，再发起远端 HTTP 写入，避免慢网络响应占满读连接池拖慢普通请求。
- Hub 的 `wire::node_runtime` 按生命周期、规划、派发、收件、落库与对账拆分为独立子模块，保持原有行为与边界约束不变。

- 实例管理员在自己的主对话里让 Steve 查看、整理、安装或排查 Hub 所在机器上的东西时，Steve 直接动手：这类对话以该系统用户的完整权限运行（读写文件、执行命令、访问网络），工作目录是主目录，不再受“只读研究”的限制。Steve 自己的密钥、数据库和程序文件仍在它够不到的地方。只有一个用户的实例上，你和 Steve 在渠道里的私聊同样如此。其他成员的对话、渠道里多人可见的对话和远程 Node 上的研究照旧只读。删除、覆盖这类难以恢复的操作，Steve 会先说明要动什么并等你同意。
- 主对话里一次工具调用开始时就显示在进度行上（“正在执行 `du -sh …`”），旁边可以随时停；以前要等这次调用结束才显示，第一条命令跑得久时只有一个“正在查”。
- 新建项目的对话框可以选所在 Node 并浏览目录：点进子目录、返回上级，或直接输入路径（输入到一半时列出匹配的子目录）；git 仓库有标记，名称默认取目录名。项目目前只能建在 Hub 内置的 Node 上，其他 Node 会列出但不可选。目录浏览只对实例管理员开放。
- 主对话里判断不出一条消息该怎么处理时（路由超时或出错），Steve 直接带着工具去查、去做，不再退回成一个什么都动不了的回答。
- 主对话里的就地研究现在真的跟随 设置 · 模型：没有单独指定模型时用 harness 自己的默认模型，不再悄悄改用预设的 sonnet → opus（0.2.94 已说明取消这个预设，但研究这一处仍在用）。
- 追问接不上前一次会话时（会话过期，或 harness 没能恢复它），Steve 带着完整的说明重新开始：权限、规则、最近的对话都在，不再只凭“上一轮的回答”作答。

- `steve setup` 在终端里是一个向导：先把问题问完（角色、谁能连到这个 Hub、装哪些 ACP 适配器），再一步步执行并显示进度，结束时可以直接启动 Hub、等它就绪并打开浏览器。不在终端里（管道、`TERM=dumb`、`STEVE_PLAIN=1`）时仍是逐行输出，只注册服务、不启动。
- 安装时不再询问浏览器地址：它由监听地址推出，需要别的地址时用 `--public-url URL`，之后用 `steve setup --reconfigure` 改。
- 适配器可以选：向导里勾选，或 `--adapters claude-code,codex|all|none`；之后用 `steve adapters install <id>…` 补装。没选的适配器不会被自动安装或升级，启动检查也不再为它报缺失。
- 数据目录里已经有另一个版本的安装时，向导会问是否全新安装；`--fresh` 直接这样做：停掉并注销旧服务，把整个目录改名为 `<目录>.bak-<时间>` 保留，不删除任何数据。
- macOS 上登录钥匙串里留有上一次安装的签名密码时，Hub 启动时用当前安装的密码替换它，不再因为“密码不一致”卡住升级签名。
- `steve hub status` 和 `steve hub doctor` 在终端里显示正在运行的版本（来自 Hub 自己的 `/healthz`）；`--json` 输出不变。
- `steve` 命令行的全部文字有中文和英文两套：`--lang zh-CN|en` 优先，其次是 `STEVE_LANG`、`LC_ALL`、`LC_MESSAGES`、`LANG`，macOS 上再看系统语言，都没有时用中文。

- 实例管理员第一次打开一个空的 Hub 时，首次引导的最后一步改为“互相认识”：同意后 Steve 在主对话里先打招呼，问怎么称呼你、平时用它做什么，然后逐项征求同意再动手：从这台机器上已有的信息（编码助手留在主目录下的会话记录和全局指令文件、git 全局配置、主目录下的项目）整理你的资料并写进“我”；按各 harness 实际提供的模型，为分诊、起标题挑快的，为研究、起草、编排挑最强的；按你做的事建两到四个 Bot（已有的 Bot 能承担的不再另建）。每一项都先问你，每次写入都进审计日志，可以在 我、设置 · 模型、Bot 页查看和改回。
- 认识期间，你在主对话里说的话直接由 Steve 带着工具处理，不再先过分诊（点名 Bot 或事项的消息除外），所以全新安装后的第一句话不用再等分诊超时。
- 不想认识可以在引导里选“以后再说”、对 Steve 说“跳过”，或点欢迎语下面的“跳过认识”；这个选择记在 Hub 上，换浏览器不会再问。超过十二条消息没有结束，认识会自己结束。之后想重来，到 设置 · 通用 重新开始首次引导。
- 其他成员只看到原来的引导，没有“互相认识”。
- 没有做“互相认识”也不再让分诊等最强的模型：Steve 所在的 harness 报出自己的模型后，Hub 会把分诊、起标题、披露检查、流程 Bot 节点这四个高频小判断一次性放到该 harness 的快模型上（例如 Claude Code 提供的最新一款 haiku），只在这些用途还没有单独设置时写入。它就是 设置 · 模型 里的普通单独设置，改掉或改回“跟随 Steve”后不会再被写回。harness 没有报出快模型时一切照旧。设置了 `STEVE_MODELS_FAST` 的安装不受影响。

- 单次 ACP 调用在收到适配器报错返回前先排干已到达的通知并封口统计：模型因过载等错误回退时，失败尝试已上报的 token 与费用不再偶发漏记；会话加载阶段末尾重放的历史片段也不会串入后续提问。
- 同一 Git 仓库上的 `git worktree` 变更子命令（`add` / `remove` / `prune` / `move` / `repair` / `lock` / `unlock`）现按公共 `.git` 目录串行化（`fetch` / `push` / `rebase` / `commit` 等非 worktree 命令不加此锁，保持 Git 自身锁行为），后台磁盘回收中的 `git worktree prune` 移出核心状态锁外执行，避免与新建或清理 worktree 并发修改 `.git/worktrees` 导致偶发报错。

- 多 Hub 切换与设备配对现在是网页端自己的功能，任何浏览器里都有：侧边栏顶部的 Hub 切换器（手机上在「我的」页），登录页与「无法连接」页的 Hub 列表，「设置 · 访问与客户端」里的完整列表，以及命令面板（`⌘K`）。
- 添加 Hub 时填地址或粘贴配对链接都可以。同一主机不同端口、或 HTTPS 的 Hub 在当前页面内直接切换；其他主机上的 HTTP Hub 会跳转到那个 Hub 自己的页面，已保存的 Hub 列表随地址一起带过去，经你确认后才加入。
- 配对二维码现在是一个任何浏览器都能打开的链接：手机用系统相机扫码即可在浏览器里完成登录，不需要安装 App，链接还能复制到另一台设备的「添加 Hub」里。二维码 5 分钟内有效、只能用一次；Hub 有多个地址时可以选择设备够得着的那个。
- 同一台主机上的多个 Hub 现在可以同时保持登录：Hub 的 Cookie 名带上了自己的端口。升级后，已登录的浏览器需要重新登录一次。
- 开启了独立网页端口（`STEVE_WEB_PORT`）时，用浏览器打开 Hub 的 API 端口会自动转到网页端口。
- 未设置 `STEVE_PUBLIC_URL` 时，默认地址跟随 `STEVE_PORT`，不再固定为 8440。
- 浏览器重新登录同一个 Hub 时，被替换掉的旧登录会随之失效，不再在客户端列表里越积越多。
- 页面开着时与 Hub 的连接断开，页面顶部会说明并继续重连，旁边可直接换到其他 Hub；连不上的地址与「不是 Steve Hub」的地址现在是两句不同的提示。
- 添加 Hub 时填的是它的网页地址（地址栏里看到的那个，网页端口与 API 端口分开时两者不同）也可以，页面会找到背后的 Hub。
- 页面只为自己所在主机上的 Hub、或当前正在使用的 Hub 领取配对码；指向其他 Hub 的配对链接会先提示，再转到那个 Hub 自己的页面完成。用 `#/hub/pair` 链接打开配对窗口时，点一下才会生成二维码。
- 浏览器不保留其他站点上 Hub 的登录状态时（Safari、隐私窗口），登录页会直接说明并提供前往那个 Hub 自己页面的入口，不再悄悄回到登录页。
- macOS / iOS 客户端（`apple/`，需自行从源码构建）尚未跟进这次调整：客户端里原有的 Hub 列表与配对窗口还是旧实现，扫码只认 `steve://pair` 码，客户端自己的配对窗口与本版本的 Hub 不兼容。客户端改用网页端同一套界面的改动随后发布。
