# Steve v0.4.1

Ordinary Agent replies now open supported local file links and images from signed-in Hub previews without a delivery tool call. Markdown reports keep their local images with the preview. Saved copies still work after the source Node goes offline; old or unsafe local references show why Steve cannot open them instead of trying to read a device path.

Needs a minor release: newly paired Nodes no longer receive automatically spread Bot work before an explicit binding; upgrade Nodes before using strict Bot/Team routing. Older Hubs do not enforce the new policies.

- See which execution Nodes can run a Bot’s saved configuration before explicitly binding them. The check opens a scratch session, without a model prompt; it does not prove subscription entitlement or quota.
- Reuse Bots in workspace Team presets with narrower Node lists. Switch the workspace default or pick a Team for one new item. Item details explain the actual Node choice or what blocked dispatch; existing sessions stay on their original Node.
- On macOS, an owner session using Pi can take the lock beside the Node’s linked sign-in without granting write access to the provider directory.

本人代回的批准、发送失败、重试与接手卡现在和会话列表使用相同的名称：私聊显示实际对方，自聊显示“你自己”，群聊保留群名。修复渠道服务把私聊命名为本人时，卡片无法区分收件人的问题；发送目标、授权和批准流程不变。

修复自己的账号没有代发授权时，触发词转到网页主会话答复后，来源消息一直保留“处理中”表情的问题。网页答复成功后改为完成，出错或研究未完成时改为失败，在路由、排队或答复时停止则清除；重复处理不会重复添加表情，也不会向原渠道发送答复文本。

重新验收交付或补充报告时，同一仓库、PR 和完整提交 SHA 的有效人工合并批准会保留，Hub 重启后也不再重复弹出批准卡。批准卡会显示准确的合并目标；新提交（包括 rebase）、其他 PR、仓库或事项周期不能沿用批准，已撤回、过期或缺少准确目标的旧记录也不复用。

重新交付仍需验收，CI 及合并前的批准和 SHA 核验继续生效；无法核验 PR 或验收版本时不会合并。

Needs a minor release: an older installed runner keeps its fixed timeout for the first upgrade. Large pending migrations need an updated runner first; macOS local-release installations can use the verified, prepared target bundle's explicit maintenance deploy. A newer CLI alone still delegates to the installed runner. See the first-upgrade instructions in `docs/deployment.md`.

Upgrade probes now distinguish ongoing SQLite migration work from an unhealthy candidate. Forward migration/VM progress permits backfills longer than 60 seconds, with a 60-second idle timeout and a 15-minute total limit. Crashes, stalled migrations and unhealthy startup still fail within bounds and restore the pre-upgrade backup before commit. Managed probes also reject unsuccessful HTTP health responses even when their identity metadata matches. Native, managed and compatibility Python probes use the same policy; released migration 076 and the database schema are unchanged.

Fixed personal external channels bypassing the account's Hub write switch for recalls and reactions. Sends, replies, recalls, adding/removing reactions and connector writes now check the current Hub permission at the adapter boundary, including after pacing or retry backoff.

Accounts and Connections display Hub permission and the service's last reported write policy separately, with the reason and recovery path for each restriction. Enabling the existing Hub switch does not override upstream policy, replay denied operations or act on historical messages. Existing approvals and identity checks still apply; no service configuration is changed automatically.

重新交付或提问成功后，Steve 会保留当前事项周期和逻辑轮的持久回执，避免晚到、乱序或重放的回合结束通知再次显示“Agent 没有交付也没有提问”。重启后的停滞检查会清理与有效回执矛盾的旧兜底卡，保持真实的验收或 PR 收尾状态。

正文自述、被拒绝的交付和旧周期或旧轮的记录不算成功回执；真正没有交付、没有提问时仍显示失败卡，执行错误和发布状态未知卡保留。

修复 IM 来信已被起草器判定无需回复、未生成草稿，却仍在聊天记录中显示“处理中”的问题。此类消息现在显示“已跳过”及原因；真正处理中的消息和待确认草稿保留原有状态。仅调整状态展示，不改变回复或发送规则。

Needs a minor release: offline Hubs upgraded through legacy runtime archives must provide the matching verified installer via `STEVE_NODE_INSTALLERS` before upgrading Nodes.

Node upgrades from the Hub now include the matching `steve` maintenance CLI alongside `steve-node`, so adapter maintenance and manual removal remain available after upgrading. New packages verify both binaries before staging; they switch and roll back together. Legacy Node-only packages remain supported.

`steve adapters --home <node-home>` now recognizes Nodes installed remotely or with the service installer and uses their registered release, even without a `current` link. Hub homes continue to use their current release. Missing, retired or inconsistent installation records are rejected without running adapter commands.

运行环境面板优先展示可用环境，只保留名称、版本、简短状态和主要操作。未安装或不可用的环境默认收起为带数量的一行，可展开安装或查看；路径、组件、能力和原始错误放入各环境的详情。安装中、安装失败和待重启提示保持可见，中文和英文界面均支持。

Email now checks the final To/Cc/Bcc audience, subject and body against disclosure rules and a second model immediately before sending, with YOLO on or off. This applies to quick compose, agent drafts, edited approvals, direct Send and retries. A preview or approval cannot skip the final check.

Timeouts, unavailable or unreadable model results, missing knowledge and changes during checking keep the draft unsent with a visible reason. Retrying checks again; repeated or concurrent approvals cannot submit the same draft twice. Existing approvals, connection permissions, undo delays and reconciliation for unknown provider outcomes remain in force.

Main-conversation messages now treat item numbers, including `#ST-n`, as context. New requests create new work; only clear supplements go to unfinished items, and uncertain routing asks once. References no longer silently focus subsequent messages on an item. If a proposed supplement targets an item that has ended, Steve offers to create separate work or discuss it in the conversation instead of failing and losing the request.

The Devices page now shows each Node's own harness availability, known CLI and ACP adapter versions, and reported models, including remote Nodes. Empty, unavailable, older unsupported Nodes, probe failures and offline cached reports have distinct messages. Open a Node to inspect its report or probe that Node again; provider settings and logins remain managed on that Node.

模型服务中途断流（包括输出末尾的 `upstream stream interrupted`、适配器错误或中断 stop reason）现在按执行错误处理，在同一逻辑轮内等待 20 秒、60 秒自动重试，并提醒 Agent 核对已完成的操作再继续；不占用“未交付，让它继续”的次数。连续三次失败后才显示明确的“模型服务中断”卡片，重放不会重复重试或建卡，Hub 重启保留退避和重试次数。已经交付、提问或被用户停止的回合不会因此重新开工。

Simple channel questions can use the configured outward identity without being escalated solely for mentioning the owner's name. Private questions and answers with missing classification or disclosure evidence stay with the owner.

Reply approval cards show the original message, destination, sending identity and final draft, with actions to approve, edit, leave unanswered or convert the source into an item without sending. Refreshed drafts cannot silently overwrite edits, and queued approvals are distinguished from actual send outcomes. Cold delivery replays retain the existing single-outbound-operation guarantee, including failed personal trigger commands.

父事项完成或放弃后，尚未完成的子事项会停止执行并归档，注明“随父事项结束”和父事项结束原因；旧失败记录保留原来的失败结论。升级后的生命周期检查也会清理同类遗留子事项，覆盖嵌套和已被替换的工作尝试，不依赖动态工作流开关。已经完成、单独取消或手动归档的历史记录保留；仍在执行或有外部操作结果未知的子事项会等待停止、核实后再归档。

Choosing “It's actually done” on an agent failure card now records your acceptance directly, instead of asking automatic acceptance to judge an empty check list and send the item back to the agent. Your choice and any note are retained in history. Required PR merges, release approvals and other closeout gates still apply.

模型服务返回 503「无可用上游账号」等容量故障时，Steve 会按错误中的预计恢复时间或 Retry-After（秒数或 HTTP 日期）自动重试，并为各会话加入独立的 1–5 秒抖动；恢复时间已过则从现在加抖动后重试，未提供有效时间时按 20、60、120 秒退避。工具已经运行过的回合也会先提示核对结果再恢复，不消耗“继续”次数。重试最多 3 次、等待最多 15 分钟，重启保留等待时间；超过上限后显示一张说明服务容量问题和预计恢复时间的失败卡。

Needs a minor release: personal trigger settings are now scoped to the receiving connection; check each personal account’s trigger settings after upgrading instead of relying on another account’s latest configuration. Unsent historical requests without a live receipt require review rather than automatic sending.

Personal chat triggers now check the actual receiving account and verified author, including thread follow-ups and bot-first copies. Configure extra automation prefixes in the account’s trigger settings; built-in AI markers remain ignored. Historical messages are not replayed.

Conversation records and stored reply notes show the persistent outbound result: sent, draft only, blocked, failed or unconfirmed, with discarded, recalled and Steve-only replies distinguished. Policy refusals are distinguished from transport failures when writing the note as well as when reading it back. Generation and reaction completion no longer count as proof of sending. Existing approval, disclosure and Bot boundaries remain in force.

Devices now checks CLI and ACP component versions on each selected local or remote Node and offers one-click upgrades for installed components in that Node’s managed prefix. Checks show latest versions, times, failures and unsupported or external installations. Upgrade results come from durable Node receipts and verified installed versions, with progress, failure and unknown outcomes retained across refreshes and reconnects.

This optional capability requires an updated Node; older Nodes keep working and show the upgrade steps. The instance owner’s authorization and the Node’s execution ceiling both apply. Active work and other installers block component changes; package failures require an explicit retry. Provider, model and sign-in configuration stays on the Node and is not changed.

新建事项的 HTTP API 和 `steve_item_create` 支持 `deps` 前置事项编号数组。事项与依赖在同一次事务中保存；前置尚未成功完成时不会创建执行会话、工作目录或失败提问卡。重启后继续等待，前置都完成后按工作空间策略自动启动或提醒开始；启动上下文带有 Hub 核对的前置摘要，无需为了核对进度请求扩大读取范围。无效或跨工作空间的依赖会拒绝整次创建。

给已有事项补设依赖时，执行中的旧回合也会转为等待，过时的提问或停滞卡失效；等待期间旧回合不能再创建提问或授权卡。暂停状态及仍需核实的外部操作、有效授权保留。

The Hub no longer retries cleaning up a worktree after its Node reported the cleanup as not retryable (for example, a worktree with uncommitted changes); the worktree is kept and a later preparation starts a fresh cleanup. A command whose outcome is unknown and that the Node marked as not retryable is no longer sent again; reconciliation with the Node settles it.

Nodes now prune fully acknowledged, finished command history after 24 hours in the background and keep stream heads in memory, reducing journal growth and acknowledgement delays during long runs. Session streams and records still needed for recovery remain available; pruning failures do not prevent Node startup or roll back acknowledgements.
