## Features

- **backup:** keep every backup purpose in one encrypted restic repository (#497) ([#507](https://github.com/Infranite/steve/pull/507))

  Steve now uses one encrypted, deduplicated backup repository under `backups/restic` for daily, manual, upgrade, destructive-operation and diagnostic copies. The Data and privacy page shows total repository use, and Health warns when its destination is low on space. Automatic backups retain the latest copy of each purpose and use time and count limits. Manual snapshots stay until you remove them.

  Keep the repository password and Vault recovery keys separately from off-machine backups. Existing backup directories stay in place. To recover an earlier copy, stage the database named in its `manifest.json` and the contents of its `files/` or `files.tar` in a private directory. Check the recorded database SHA-256 and run SQLite `quick_check` before restoring. The Backups section of `docs/deployment.md` covers offline recovery. Retire earlier copies manually after verifying the new repository.

  Benchmarks (isolated 1.5 GB database, restic 0.19.1): unchanged daily backup 9.9 s / 46 KB written (v1 copied ~1.51 GB every time); +10 MB change 9.8 s / 12.3 MB; five snapshots 1.52 GB total (v1 ~7.54 GB); full restore 5.7 s.
- **dispatch:** make Steve the coordinator and ask the owner when no Bot can take the work ([#544](https://github.com/Infranite/steve/pull/544))

  Steve now acts only as the coordinator: automatic placement picks from ordinary Bots (the selected Team's members, or all Bots without a Team) and never from Steve itself, and Steve cannot be added to a Team. When no Bot can take an item, Steve asks you once per workspace, listing why each Bot was ruled out: assign a Bot, confirm a proposed Bot, or choose *Later*, after which Steve does such work itself (Settings → *When no Bot can take work*). Items Steve does itself say why.


  Checks (local, focused): steve-core 571/571, steve-types+store 354/354, steve-hub guards, thread_routing_api 2/2 (chat → item, #524), web 357/357, browser smoke 17/17 incl. new no-executor. Full suite in CI.

- **identity:** make the avatar part of the person and show who did what everywhere ([#545](https://github.com/Infranite/steve/pull/545))

  Your avatar and name now come from your contact profile everywhere: the account menu, item timelines, settled decisions, conversations and member lists all show the same person, and every timeline row shows who acted — a person, a Bot, or Steve's system — with a distinct avatar for each.


  Checks (local, focused): steve-store 73/73 (incl. migration), steve-types 24/24, web check + 361/361, browser smoke incl. new person-avatar. Full suite in CI. Screenshots reviewed (contacts, item timeline, settled decisions; light/dark).

  Migration number is taken at merge time.
- **thread:** cut the conversation layer over to durable reply tasks, receipts and origin idempotency (W3.4) ([#546](https://github.com/Infranite/steve/pull/546))

  Conversation replies now run as durable tasks: one at a time per conversation, resumed after a restart only when they had not started, and never sent twice — a reply whose delivery is uncertain is shown as unknown instead of being resent. Explicit commands and @-mentions no longer go through the routing model, and turning a message into an item twice at once creates it once.


  Local focused checks: steve-core 598/598, steve-store (schema incl. migration), steve-channels reply/outbound, steve-knowledge 53/53, steve-hub research/bus/outbox, web 357/357, guards. Full suite in CI. **Production copy (schema v119 → current) passes the migration check** (#549, extended to this migration): every table count accounted for; reply links `reply_message_id` 99 → 209 of 209 (110 recovered from the route log); `dispatch_ref_id` 0 → 42, one per historical dispatch (the other 167 replies created or appended nothing). Runtime receipts now always carry a typed dispatch reference, including appends to existing items.
- **knowledge:** keep knowledge about the owner's world and move engineering notes to project proposals ([#550](https://github.com/Infranite/steve/pull/550))

  Knowledge now means what Steve should know about your world: people, organisations, projects and commitments, your preferences and rules, and the material you connect. Items and conversations are kept as records — still searchable — instead of being indexed as knowledge. Engineering lessons about a code repository are offered as a proposal to that project's AGENTS.md instead of being saved as your memory, and the knowledge steward only runs when there is something to tidy.


  Local focused checks: steve-knowledge lib 54/54, k3 12/12, redefine 3/3, steve-mail e6_knowledge 6/6, guards, web 357/357 + knowledge browser test. Full suite in CI. Migration number is taken at merge time.
- **handoff:** hand work to another execution surface mid-task on owner request, exhausted quota or provider failure ([#553](https://github.com/Infranite/steve/pull/553))

  Work can now be handed off mid-task to another harness or model — when you ask for it, when a model runs out of quota, or when a provider keeps failing. By default the same Bot continues with its next configured harness/model for that item only, starting from a handoff summary, and the timeline says why. If none of a Bot's options is available, Steve asks you.


  Local focused checks: handoff 3/3, handoff errors zh/en, assembly, guards, steve-core/steve-node related, web check + tests. Full suite in CI. Migration number is taken at merge time.
- **waits:** give every wait an owner, a clock and a deadline ([#560](https://github.com/Infranite/steve/pull/560))

  Every wait now has an owner and a deadline: decisions, prerequisite waits, item operations, GitHub actions, mail drafts and flow steps can no longer hang forever. When a wait runs out, Steve closes it or, where that would hide something, asks you to check.


  Local focused checks: steve-core lib, steve-store, steve-flow due, steve-channels owner decisions, steve-github, steve-mail, steve-hub decision expiry and guards. Loopback/HTTP tests and web in CI. Migration number is taken at merge time.
- **knowledge:** deliver personal memory context across sessions and harnesses ([#573](https://github.com/Infranite/steve/pull/573))

  Your confirmed personal memories now reach coding sessions, research runs and the main chat. Before this change, agent sessions did not include memories about you at all, and the main chat kept only the first five rules and preferences.

  - **Priority and budget.** Memories are packed in priority order (pinned, rule, preference, summary, fact, event, then recency) within named budgets: 1,500 characters for the main chat, and 1,200 tokens per session.
  - **Delivered through the harness, your files untouched.** Claude Code, Codex and Antigravity receive the context through their own system-prompt append option. Your `CLAUDE.md` and `AGENTS.md` are never modified. Other harnesses get a `## User Context` section in the opening prompt.
  - **Shared workspaces.** In workspaces with several members, only memories visible to the workspace are used. Memories marked "never disclose" are excluded everywhere.
  - **Metric.** New `steve_memory_uses_total{consumer, stage}`, where `stage` is `injected` or `cited`.

## Fixes

- **observability:** cover storage, background jobs, plugins and integrations with bounded metrics (review batch B5) ([#565](https://github.com/Infranite/steve/pull/565))

  Health and Stats now see more of Steve: database queries and transactions, every background job (a job that crashes is restarted and shown as down instead of silently stopping), plugin processes and their upstream connections, mail/calendar/Feishu syncs and sends, live connections, and errors and reconnects in the web app.
- **acp:** keep buffered reply text when a turn is cancelled ([#568](https://github.com/Infranite/steve/pull/568))

  When a turn is stopped — for example because a Node shuts down — the text the agent had already written is kept instead of being cut off.
- **release:** resolve PRs landed through integration branches and dedupe upgrade notices ([#570](https://github.com/Infranite/steve/pull/570))

  Release notes now include every pull request that landed through an integration pull request. Each PR's upgrade notice appears once. The PR description takes precedence over its commit trailers, and identical notices are merged.

  Pull-request lint rejects `Checks:` paragraphs and signature lines inside `## Release note`. Put them under a separate heading such as `## Checks`.
- **nodes:** recover Nodes left behind by the Hub and fix headless macOS service setup ([#571](https://github.com/Infranite/steve/pull/571))

  Fixes Nodes that fall behind the Hub, and the harness checks that broke because of it.

  - **Hub-local Node replaced automatically.** The Node that runs on the Hub's own machine is now restarted on the Hub's build once it is idle. Before, a protocol mismatch left it on its old build indefinitely.
  - **Out-of-date Nodes reported clearly.** A Node whose protocol is older than the Hub's no longer retries ordinary work every few seconds. It is logged once, and the Node page reports its version and the Hub's, with a single "Upgrade Node" action. The page no longer shows "harness probe failed / 0 available".
  - **Remote upgrade of old Nodes.** Nodes on older builds report their build, so the Hub can upgrade them remotely. Stale upgrade records are reconciled once the target version connects.
  - **macOS boot service without a desktop login.** `steve node enable-boot` now works when nobody is logged in to the Mac, for example when starting a fresh install over SSH. If a Node process still holds the runtime lock, the error names its PID and binary path.
  - **`steve node update --release PATH`** copies the release into `<home>/releases/<version>-<commit>` and verifies it before switching. A service that was running before the update is started again afterwards.
  - **Service PATH from the login shell.** The macOS launchd and Linux systemd service definitions now take `PATH` from the owner's login shell, so CLIs installed by the user (for example `~/.local/bin/agy`) are found.
    - `steve node refresh-env` and `steve hub refresh-env` re-capture it after installing new tools; re-running `enable-boot` also refreshes it.
    - `steve node doctor` and the Node's Harnesses tab explain when a command is missing from the service PATH.
- **release:** list pull requests landed through integration PRs ([#575](https://github.com/Infranite/steve/pull/575))

  Release notes now list every pull request that landed through an integration pull request.
  - Merged pull requests are found by their merge commit in the release range, using GitHub GraphQL. Before this change, the commit-to-PR lookup returned only the carrying PR.
  - A carrying chore PR is listed once, under Other changes, with the PRs it carried.
  - For PRs, upgrade and breaking notices are read only from the PR description; stale commit trailers are ignored.
  - PR lint fails when a PR's commits carry an `Upgrade:` trailer that the PR description does not.

## Performance

- **web:** remove main-thread jank from streaming, cards and long lists ([#562](https://github.com/Infranite/steve/pull/562))

  Chat streaming, cards and long lists are smoother: live replies update only what changed, long histories and activity feeds render only what is on screen, and finished messages no longer re-render as new tokens arrive.
