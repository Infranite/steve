# Steve v0.2.113

- Releases no longer push to `main`. `ops/cut-release.py cut` now brings the release notes in through a release pull request (`release/vX.Y.Z`): it waits for that pull request's CI, rebase-merges it, and pushes only the tag. This lets `main` require pull requests and the `CI gate` check. A release whose pull request merged but whose tag never landed is finished by the next `cut`.
- CI skips the Rust and Apple jobs for a pull request that changes only `docs/releases/` and stands on a commit whose CI passed, as it already did for such a push. The CI workflow also runs for GitHub's merge queue (`merge_group`).
- CONTRIBUTING.md and AGENTS.md describe the flow: branch from the latest `main`, open an issue first, then a pull request that closes it. Nothing is pushed to `main` directly.

Retrying a work unit no longer creates a new item. Every attempt of a unit runs in the child item its first attempt created: the same number, branch and worktree, in a new cycle with its own session. The item list shows the attempt number on that one item, and the collaboration view lists the earlier attempts before the unit. A retry continues from the commits the earlier attempt left on the branch. While a unit can still run again, its child keeps its worktree and build caches for the retry, unless disk space is low. Attempts retired before this change keep their own items and are still shown.

A closed item now gives back its toolchains' build outputs in `.steve/build` (Rust's `target` among them, often tens of GB) along with its other caches, also when its worktree stays because the branch is not merged yet. Before, only caches with a known name or a `CACHEDIR.TAG` were found, so a moved Cargo `target` stayed on disk after the item ended. Worktrees already closed are cleared by the next workspace pass; sources, commits and branches stay.

- Agents now load the Node owner's personal harness configuration, as the harness does on its own: the user-level `CLAUDE.md` / `AGENTS.md`, skills, subagents, commands and prompts of Claude Code, Codex, Pi, Gemini CLI and Qwen Code are linked into each owner session's harness directory, so edits are seen by the next session. Before, only the project's files and Steve's own skills were loaded because each session's harness keeps its state in a directory of its own. A bot skill with the same name as one of the owner's gives way to the owner's.
- New switch: Settings → Items → "Load the device owner's personal agent config" (on by default), with a per-device override on the Devices page. Turn it off to make every Node behave the same; the project's own files and what Steve adds are always loaded. Changes apply to new sessions.

A Node that sends a request right after it links (catching up, a receipt) is no longer refused with "this connection no longer speaks for the node": requests that arrive before the Hub has installed the link wait for that, then are handled like any other. If the link is refused at that point (revoked, or replaced by a newer one), they are refused as before.

A channel service connection (其他聊天工具, or a channel plugin) now takes the account name the service gives whenever it reconnects. Before, the name was read only when the connection was made, and a service that gave none then left the account named by its numeric handle for good. A name you gave the account yourself is kept.

- The Hub can upgrade its separate Nodes to its own release. Devices shows each Node's build next to the Hub's, its upgrade policy (follow the Hub automatically, only show it, or off; a Hub-wide default plus a per-Node choice), the last upgrade and an **Upgrade to the Hub's version** button for the instance owner.
- The Node downloads the release over its own link and checks size, SHA256 and build identity; new work waits while running turns finish; a helper switches the service to the new release and goes back to the previous one if the Node does not reconnect in time. Nodes installed as a service from a release bundle take part from this release on; others keep the manual `steve node update` procedure.

- Git projects finished when merged (or merged and tagged) now land every change through its own pull request. An item's branch starts from the remote's latest default branch, fetched when its worktree is made. The agent pushes it and opens the pull request before delivering (an issue first for a bug), and never pushes the default branch or merges itself.
- After you accept, Steve turns on the host's auto-merge for the pull request (or merges it once every check passed where auto-merge is not allowed) and follows it: a failed check, a conflict or a branch that has to catch up goes back to the agent, a pull request closed without merging is a card for you, and the item closes once the change is on the default branch.
- `steve_publish` is no longer used in these projects, and accepted items no longer go through the merge lane.

- The merge lane and the merge queue are removed: their project-page sections, the `steve_lane_status` tool, the `/projects/:id/lane` and `/projects/:id/queue` API, the `STEVE_MQ` setting and the Node's merge-queue staging. Changes of git projects land through their own pull requests. The upgrade drops their tables, and lane or queue cards still open are closed.

- Pull requests run the Linux CI jobs only, and build the Apple apps only when they touch them, the web client or the CI workflow; macOS runners were the queue every pull request waited in. The push to `main` still runs Linux and macOS, and `ops/cut-release.py` now releases only a head whose own push run passed, so nothing is released untested on macOS.

- A conversation, a chat message and a card about a chat message from Feishu or Lark now have 在飞书中打开 (Open in Feishu). It is in the conversation's header, in the actions under each message of the conversation, on the group's page and on 待处理 cards about a chat message. It opens the chat in the Feishu client on a computer and in the Feishu app on a phone, through Feishu's AppLink (`applink.feishu.cn`, or `applink.larksuite.com` for a Lark connection, by the connection's domain setting). Feishu has no link to a single message, so a message opens its chat.
- It works for chats seen through the Feishu bot, your own Feishu account and a channel service that says it reaches Feishu. A chat whose id is not a Feishu chat id gets no link. The Hub gives the link as `open_url` on spaces, conversations, chat messages and `chan_message` decisions, so other platforms can add their own links later.

- In a project finished when merged (or merged and tagged), an item whose branch has no commit of its own is no longer reported as merged just because the remote's default branch contains its starting point. Unless a merged pull request of its branch says otherwise, the acceptance alone completes it; an agent that stops without a commit of its own is continued instead of being closed as merged.

- Preview links for any file or folder. `steve login` then `steve publish <file|folder> [--title] [--entry] [--interactive]` uploads a file (a folder is packed as a ZIP) and prints its delivery page, which opens from a phone through the Hub's public address. Publications without an item are listed, newest first, in **我的发布** (More, the command menu, `#/publications`), with sharing and revoking.
- Bots can call `steve_deliver_file` in any session with a working directory — chats, conversations and scheduled runs, not only items — within the same directory and Node read rules.
- Interactive HTML prototypes, opt in per delivery: the owner switches it on the delivery page (or the publisher with `--interactive` / `interactive: true`). The page then runs the package's scripts in an isolated sandbox (an opaque origin with no access to Steve, its cookies or storage, and no network beyond the package's own files). Static stays the default, and public shares follow the same switch.
- The delivery page is fully in your language, says plainly when a link only opens on the Hub's computer, and explains when a static HTML page needs scripts instead of showing an empty frame. It now also plays audio and video, renders Markdown with the package's own images (`.md` files are recognised by extension), opens a package at its README when it has no HTML, and highlights code by file type.
- A design delivered as an openable file with `steve_deliver_file` and listed in `steve_deliver` outputs now satisfies the design-confirmation step, whatever kind it was listed as.

- In YOLO mode an item's agent can now push its own branch to `origin`, create, edit or comment on that branch's pull request, and open an issue without stopping on an approval card. The branch is the one Steve recorded for the item, never one taken from the command, and only plain forms count (`git push`, `git push -u origin <branch>`, `git push origin HEAD` while the checkout is on that branch, `gh pr create`/`edit`/`comment` for it, `gh issue create`).
- Force pushes, other branches, refspecs such as `HEAD:main`, tags, deleting, other remotes, `gh pr merge`, repository settings, releases and `gh api` writes still wait for you. When a pull request conflicts or falls behind, the agent is now told to merge the default branch in and push again; a force push after a rebase still asks first.

A channel service (其他聊天工具, or a channel plugin) can now say which platform it reaches. Its connection is then listed under that platform on the 接入 page instead of under 其他聊天工具. A plugin that proxies your own Feishu account appears under 飞书 / Lark as its own 代你处理, with no bot needed and nothing said to be missing. It is independent of any Feishu bot you connect. The connection is regrouped the next time it connects; nothing has to be connected again.
