# ST-40 去掉顶部横栏，重整统计页

结论：页面顶部那条 YOLO 横栏去掉了，里面的状态和入口都搬进了统计页最上面的“运行状态”。统计页改成先看重点、再看图、最后看明细，四个核心数字和每张图都能点进去看具体是哪些事项。

## 横栏去了哪里

| 横栏原来的内容 | 现在在哪 |
| --- | --- |
| 模式（YOLO 替你审批 / 完全放开）和说明 | 统计页“运行状态”一行；侧栏的 YOLO 圆点照旧；手机“我的”里的 YOLO 行照旧 |
| 代办 N | “这次替你做了 N”，点开 YOLO 记录的“替你做的” |
| 留给你 N | “留给你 N”，点开 YOLO 记录的“留给你的” |
| 冷静期 N | 有冷静期时显示，点开 YOLO 记录 |
| “记录”入口 | “YOLO 记录”链接（#/yolo） |
| “调整”入口 | “调整”，打开原来的 YOLO 设置 |
| 熔断暂停（红点、原因、恢复） | 统计页“运行状态”（role=alert，带“恢复”）；待处理页顶上也有同样一条，因为暂停后卡片都等你处理 |
| Hub 不允许 YOLO | 统计页“运行状态”，灰色 |

手机上待处理页的工具栏也显示 YOLO 圆点（以前手机上只有横栏能看到）。

## 统计页层级

1. 运行状态：上面这一行。
2. 核心指标，四个，每个都能点开明细：
   - 进行中（现在）
   - 待你处理（现在，和待处理页同一批卡片）
   - 已完成（所选时间范围，和上一段比）
   - 失败或受阻（现在：有异常卡，或在等前置事项）
3. 事项：新建与完成（按天并列柱，件/天），没结束的事项按状态（横向条形，现在）。点某一天看那天完成或新建的事项；点某个状态看那批事项。
4. 耗时：完成耗时趋势（中位数折线，浅色带到 p85），时间花在哪（Agent 工作 / 等你 / 其他），各段耗时（中位数，下面灰字是 p85）。
5. 用量与费用：估算费用、总 tokens、缓存命中率，用量趋势（tokens / 费用 / 命中率，可按 token 类型、模型、Bot、项目、来源分组），用量明细表。
6. 质量与介入：首次通过率、返工、回合出错率、回滚，失败卡按原因，需要你决定的事按种类（数字下面是响应中位时间）。
7. Agent：回合、工具调用等明细数字，工具调用按种类。
8. 事项明细：区间内完成或有活动的事项表，点一行进单件统计。

## 统一的口径

- **时间范围**：只在页头选一次（今天 / 7 天 / 30 天 / 自定义），页头副标题写出具体日期，例如“近 7 天 · 10月30日 – 11月5日”。每个图的副标题都写“单位 · 日期范围”。标着“现在”的数字不随时间范围变。
- **颜色**：状态色全页一致，和事项列表里的状态点同色：进行中蓝、等你橙、完成绿、失败红，等前置、暂停、其他是灰，新建是中性灰。模型、Bot、项目这类“是谁”的分组用另一组低饱和色（`--series-1…5`），按顺序分配，第 6 组起合并成“其他”。这组颜色在浅色和深色下都跑过 dataviz 校验：亮度范围、色度下限、相邻色在色盲模拟下的区分度（ΔE ≥ 8）都通过。
- **图例**：两条以上的线或柱就显示图例，并在图例里写合计（如“完成 6 件”）。分布图每根条都直接写标签和数值，不靠颜色区分。
- **单位**：数量用件、张、个、次，时长的坐标轴按最大值统一换成分钟、小时或天，费用都标“估”。
- **空态**：没有数据时，每张图都写明“这段时间没有……”。
- **悬停、键盘和表格**：图上悬停或用左右键可以看当天所有数值，提示框里有“点击看这一天的明细”；每张趋势图都能切换成表格。

## 今天按小时（ST-43）

时间范围是一天时（“今天”，或自定义里起止是同一天），新建与完成、完成耗时、用量趋势（tokens / 费用 / 命中率）都改成按小时：

- **时区**：按统计设置里的时区（`stats.tz`，没设就用 Hub 所在时区）切成当天本地的 00:00–23:00 二十四个整点小时。图的副标题写明，例如“件 / 小时 · 11月5日 00:00–24:00 · 北京时间”；页头写“今天 · 11月5日 · 按小时，北京时间”。夏令时那几天，跳过的小时为空，重复的小时算两个真实小时；时间戳落在哪个本地小时，就算在哪一格。
- **当前小时**：垫一层浅底，柱子变浅，标“未结束”；提示框写“未结束，截至 HH:MM”。数字是到现在为止的。
- **未来小时**：Hub 返回 `null`，图上留空，不画 0；提示框写“还没到这个小时”，表格写“未到”，也不能点。页面每 15 分钟自动刷新一次，当前小时会自己往后走，过了零点也会切到新的一天。
- **口径**：数量按小时汇总，同一件事项在一个小时里只算一次。完成耗时是该小时内完成事项的中位数和 p85，命中率是该小时的缓存读 ÷ 可算命中率的输入。顶部四个核心数字和图例里的合计仍是当天累计。
- **下钻**：点某个小时，下钻列表取的是那一个小时（`hour=0..23`）里完成或新建的事项，标题写“11月5日 09:00–10:00 的事项”；用量趋势点某个小时，用量明细只看那个小时。
- **为什么一致**：按天的汇总表（`stat_daily`）分不出小时，所以小时数由同一批明细（`usage_records`、`agent_turns`）按小时切出来，规则和汇总表重建时一致。因此 24 个小时加起来就等于当天的汇总；每个小时的下钻列表和柱子用的也是同一个时间区间。

## 数据一致性

- “现在”的三个数字（进行中、待你处理、失败或受阻）、状态分布和它们的下钻列表，用的是同一份事项数据和同一个项目、Bot 筛选，所以数字和列表条数对得上。
- “已完成”和图例里的新建、完成合计都来自统计汇总接口。下钻用新加的 `GET /api/stats/items?only=done|created`，取的是汇总里计数的同一批事项：done 是区间内有状态变成完成记录的事项，created 是区间内新建的事项。Rust 测试 `backfilled_metrics_match_the_hand_count` 断言：下钻列表的条数等于汇总里的 done 和 created，并且就是那几件事项。
- 按天的完成数是“同一件事项一天只算一次”。如果同一件事项在区间里完成两次（中间被重开过），每天的柱子加起来会比区间合计多 1。

## 验证

ST-43 增加的验证：

- `cargo test -p steve-stats`：`day::tests` 检查小时切分（上海、印度半小时时区、纽约夏令时进出）；`tests/hourly.rs` 在上海时区下验证：
  - tokens、费用、回合、新建、完成按小时加起来等于当天汇总，按小时的明细和当天汇总表逐项相同；
  - 每个小时的下钻列表和柱子条数相同，24 个小时的列表合起来就是全天的列表；
  - 当前小时以后为 `null`；
  - 前一天最后一毫秒和第二天第一毫秒不会算进今天。
- `cargo test -p steve-hub --test stats_api`：`bucket=hour` 和 `hour` 参数的校验，以及返回的 24 个小时、`spans`、`current`、`tz`。
- 浏览器 `web/test/stats.browser.mjs` 的“今天”场景：24 格、当前小时的标记、未来小时不画柱、表格每列合计等于图例合计、悬停提示、点小时下钻（事项和用量），桌面和手机都不超出右边缘。截图在 `.steve/qa/ST-43/stats-today-*.png`。

ST-40 的验证：

- `npm run check`、`npm test`、`npm run build`
- `cargo test -p steve-stats`（含新断言）、`cargo test -p steve-hub --test stats_api`（含 `only` 参数校验）、`cargo fmt --check`
- 浏览器：`web/test/stats.browser.mjs` 配合 `web/test/fixtures/stats.html`，所有接口都在测试里模拟。覆盖 1440px 和 390px、浅色和深色，检查以下几项：

  - 新建与完成的图例合计等于汇总；悬停某一天的提示框；点某一天下钻
  - 状态分布和概览一致
  - 每张图都标了单位和日期范围
  - 按模型分组时第 6 组起并为“其他”
