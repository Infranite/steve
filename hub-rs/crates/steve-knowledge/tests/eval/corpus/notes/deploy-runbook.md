# 部署手册

这是 Hub 和 web 的上线流程。任何人上线前都要读一遍。

## 发布前检查

1. 主分支 CI 全绿，e2e 测试通过。
2. 数据库迁移脚本在生产库的备份副本上跑过一遍，`PRAGMA integrity_check` 返回 ok。
3. 在变更日历上登记，写清楚影响范围和回滚方案。
4. 周五下午和节假日前一天不部署，除非是线上故障的修复。

## 部署脚本

部署脚本是仓库里的 `scripts/deploy.sh`，它会依次：构建 release 二进制、签名、停掉旧进程、替换二进制、启动并等待健康检查 `/api/health` 返回 200。整个过程大约 90 秒。

脚本支持 `--canary` 参数：先只切 10% 的流量到新版本，观察 15 分钟错误率和延迟，没有异常再全量。

## 回滚

如果健康检查失败或者错误率超过 1%，立刻回滚：

```
scripts/deploy.sh --rollback
```

回滚会把上一个版本的二进制换回来并重启。数据库迁移只向前兼容，所以回滚前要确认新版本没有写入旧版本读不懂的数据；拿不准时先停写再回滚。

## 上线后

在主线对话里发一条上线说明，附上版本号和变更列表。观察 30 分钟监控面板，确认没有新的告警再离开。
