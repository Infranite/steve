结论：Steve 的视觉方向是苹果自带应用（邮件、备忘录、提醒事项）加硅谷工具（Linear、Vercel）的克制风格，原则是“内容是主角，界面退后”。

- **颜色**：界面以黑白灰为底，颜色只用来表达状态。蓝色表示选中、进行中和链接；橙色只表示“需要你”；红色表示失败。
- **层级**：靠字号、字重和留白区分，不靠边框和底色。
- **动效**：只给正在发生的事，正在运行的东西才会动。

组件基于 shadcn/ui（Base UI 底层，Rhea 风格），agent 相关部件用 shadcn 官方的 AI 模式，关系图用 React Flow。本方案取代 [[30_项目/易人实验室/方案/Steve正式版视觉优化方案|Steve 正式版视觉优化方案]] 的深灰 Codex 方向，配套交互方案见 [[30_项目/易人实验室/方案/Steve助手化交互重构|Steve 助手化交互重构]]。

[打开原型 v12](https://wiki.example.com/reviews/steve-assistant-interaction-20261031-v12/)。侧栏底部（手机在“我的”里）有“视觉规范”页，集中展示本方案的颜色、实测对比度、字体、状态、组件和对照示例；侧栏最下方和设置里可以切换浅色、深色或跟随系统。

## 为什么改

v5 用了一套风格强烈的组件库，问题集中在“同时说话的东西太多”：

| 现象 | 问题 |
| --- | --- |
| 每个 Bot 头像一种颜色，状态标签橙、蓝、绿、紫同时出现 | 颜色失去含义，用户分不清哪个需要注意 |
| 点阵画布、流光文字、带底色的提示块随处可见 | 装饰和信息抢注意力 |
| 大部分区块都有卡片边框和底色 | 层级靠容器堆出来，页面显得拥挤 |
| 多处同时在动 | 用户分不清哪里真的在运行 |

## 原则

1. **内容优先**：标题、正文和 agent 的回复是页面主体；控件默认安静，悬停或需要时才出现。
2. **颜色只表达状态**：界面的主体是黑白灰。一个页面里同时出现的彩色不超过两种。
3. **一个区域一个主操作**：主按钮用实心深色，其余是描边或纯文字按钮。
4. **层级靠排版，少用框**：先用字号和字重区分，再用留白，最后才用分隔线。边框只给“需要你动手的东西”：决策卡、输入框、弹层，以及对话里引用的事项卡。列表、属性、进度、会话记录都不加框；一页里同时出现的框越少越好，框里不再套框。
5. **动效只表达变化**：展开、出现、切换有短暂过渡；循环动画只给正在运行的那一个东西。唯一的例外是对话页顶部 Steve 的大头像，它的动作就是对你操作的反馈。
6. **两种主题同等完成**：浅色为默认（跟随系统），深色不是浅色的反色，而是单独调过的一套。

## 颜色

颜色按角色定义，组件只引用角色，不写具体色值。

| 角色 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| background | `#FFFFFF` | `#1C1C1E` | 内容区 |
| sidebar | `#F5F5F7`（半透明） | `#232325`（半透明） | 侧栏、窗口底 |
| muted | `#F5F5F7` | `#2C2C2E` | 输入框、分段控件轨道、悬停底色、用户气泡 |
| card | `#FFFFFF` | `#232325` | 需要独立成块的内容 |
| foreground | `#1D1D1F` | `#F5F5F7` | 正文、标题 |
| muted-foreground | `#6E6E73` | `#98989D` | 次要文字、元信息 |
| tertiary | `#8E8E93` | `#7C7C80` | 占位符、禁用、装饰性文字，不用于需要阅读的内容 |
| border | `#E5E5EA` | `#38383A` | 分隔线、描边 |
| primary | `#1D1D1F` | `#F5F5F7` | 主按钮、发送按钮 |
| accent（系统蓝） | `#0071E3` | `#0A84FF` | 链接、选中、焦点环、运行中、开关打开 |
| attention（系统橙） | `#FF9500` | `#FF9F0A` | “需要你”的圆点和图标 |
| destructive（系统红） | `#E5352B` 图标 · `#C9251C` 文字 | `#FF453A` | 失败、危险操作 |
| success（系统绿） | `#28A745` | `#30D158` | 只用于“完成”的勾选图标 |

使用规则：

- 状态用“圆点 + 文字”表达，圆点带颜色，文字保持正文色。不使用实心彩色标签。
- 运行中：蓝色圆点，带缓慢的呼吸动画。需要你：橙色圆点。完成：灰色文字，可带绿色勾。暂停和放弃：灰色。
- 橙色和红色不作为文字颜色出现在正文里，危险操作按钮除外。
- 头像用 [agent-robot-avatar](https://github.com/CX-ArtLab/agent-robot-avatar) 生成的机器人头，外形由名字决定。颜色只有 8 种，都是低饱和色，和表示状态的蓝、橙、绿、红区分开：石墨、石板、雾蓝、鼠尾草、沙、陶土、薰衣草、玫瑰灰；深色主题下各自换成更亮的一档。Steve 默认雾蓝。
- 消息靠颜色区分，不挂头像：Steve 的消息用他的颜色调成浅底（浅色主题 11%，深色主题 22%），你的消息用中性浅灰。
- 正文与背景的对比度不低于 4.5:1，次要文字不低于 4.5:1。三级灰低于 4.5:1，只用于占位符和装饰。原型的视觉规范页实测并列出每一对颜色的对比度。

## 字体

字体使用系统字体：苹果设备上是 SF Pro 和苹方，其他平台回退到 Segoe UI 和微软雅黑，不打包网页字体。等宽字体用 SF Mono，回退 JetBrains Mono。

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 大标题 | 26 / 32 | 600 | 页面标题：待处理、事项、会话 |
| 标题 | 20 / 28 | 600 | 事项详情的标题 |
| 小标题 | 15 / 22 | 600 | 区块标题、卡片标题 |
| 正文 | 14 / 22 | 400 | 对话、回复、列表主文字 |
| 说明 | 13 / 20 | 400 | 列表副文字、描述 |
| 脚注 | 12 / 16 | 400 | 时间、元信息 |
| 分组标签 | 12 / 16 | 500 | 列表分组名 |
| 代码 | 12.5 / 20 | 400 | 命令、输出、Diff |

规则：

- 只用 400、500、600 三种字重。
- 大标题的字间距收紧到 -0.02em。
- 手机端正文放大到 15px。
- 不用彩色文字区分层级。
- 不用全大写。

## 间距、圆角与材质

| 项 | 规格 |
| --- | --- |
| 间距 | 4 的倍数：4、8、12、16、20、24、32、40、48 |
| 页面边距 | 桌面 24–32，手机 16 |
| 区块间距 | 32 |
| 列表行高 | 不小于 44，触控目标不小于 44×44 |
| 圆角 | 按钮和分段控件为胶囊形；文本输入 8；列表组与卡片 12；弹窗 16；输入框 20 |
| 阴影 | 卡片无阴影，只用 1px 描边；菜单和弹层用柔和投影；弹窗用较深投影 |
| 材质 | 侧栏半透明并模糊背景；页面大标题随滚动收进顶栏，顶栏这时才出现半透明底和分隔线 |

## 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 悬停、按下 | 120–150ms | ease-out |
| 展开、折叠、出现 | 200ms | cubic-bezier(0.2, 0.8, 0.2, 1) |
| 弹窗、侧滑面板 | 280ms | 同上 |
| 运行中的圆点 | 1.6s 循环 | ease-in-out |

规则：

- 循环动画只给正在运行的那一项；对话页顶部的大头像除外，它只在对话页出现，并且尊重“减弱动态效果”。
- 思考和工具调用运行时，标题文字带一次柔和流光；完成后静止。
- 新回复直接逐段出现，不做模糊、打字机等装饰。
- 尊重系统的“减弱动态效果”设置。

## 图标

图标使用 Lucide，线宽 1.5，尺寸 16（列表）和 18（导航），颜色默认为次要文字色，选中时为正文色。图标只用来帮助识别，不单独承担含义：关键操作必须有文字或悬停提示。

## 组件

界面统一用 [shadcn/ui](https://ui.shadcn.com/) 的组件（Base UI 底层），只在需要时改 token 和少量样式，不再手写同类部件。改动集中在组件源码里：卡片、命令菜单、列表行的圆角统一为 12。

| 部分 | shadcn 组件 | 规则 |
| --- | --- | --- |
| 整体框架 | Sidebar（可收起成图标栏，⌘B 切换）+ Sidebar Inset；手机用底部 4 个标签 | 侧栏半透明，选中行浅灰底；“待处理”的数字是唯一的橙色角标；收起后图标有提示 |
| 全局搜索 | Command Dialog（⌘K） | 搜页面、事项编号和标题、会话，也能直接新建事项、新建流程、切换深色 |
| 页面标题 | Breadcrumb + 大标题 + 工具栏 | 详情页顶栏显示面包屑，滚动后补上当前标题 |
| 列表 | Item Group / Item / Item Separator | 不加外框，行之间是细分隔线，悬停时整行浅灰底；组名是 12px 灰色标签 |
| 属性 | 描述列表（dl） | 左侧一列对齐的灰色标签，右侧是值；下拉框平时只显示文字，悬停才出现边框 |
| 视图切换 / 筛选 | Tabs / Toggle Group | 切换视图用 Tabs；筛选用 Toggle Group，不加描边，选中项浅灰底 |
| 下拉选择 | Select | 描边小号触发器，选项带勾 |
| 表单 | Field、Field Group、Field Label、Field Description | 标签在上，说明在下；单选用“选择卡片”（Radio Group + Field Label） |
| 状态 | 圆点 + 文字；标签用 Badge（outline） | 颜色只表达状态；“AI”“需审批”“内置”“只读”用灰色描边 Badge |
| 头像 | agent-robot-avatar（Web Component） | 对话页顶部是 136px 的动画头像，翻看历史时缩成一行；其他地方是静止的小头像 |
| 对话 | 气泡 | 不挂头像；Steve 的消息是他颜色的浅底气泡靠左，你的消息是浅灰气泡靠右 |
| agent 过程 | Trace、Code Block | 单色图标和次要文字；运行中一行带流光；输出放在可展开的代码块里 |
| 验收、审批、提议 | Card（Header / Content / Footer） | 说明在上，操作在右下；主按钮在最右，次要操作是描边或纯文字按钮 |
| 问题 | Questionnaire | 选项是无边框的单选行，选中后浅蓝底；点“回答”提交 |
| 输入框 | Input Group；`#` 引用菜单用 Command | 圆角 20，细描边；附件在左，模型选择和发送在右；桌面显示 Kbd 快捷键提示 |
| 空状态 | Empty | 一句标题、一句说明，不放插画 |
| 危险操作 | Alert Dialog | 放弃事项、卸载插件先确认 |
| 流程节点面板 | Popover + Command | 按分组列出节点，可以搜索 |
| 决策表 | Table | 输入列浅底、输出列略深，单元格直接编辑 |
| 离开期间汇报 | Card | 一句结论放在 Steve 的气泡里，摘要卡紧跟在气泡下方、不嵌进气泡；按“需要你、已完成、进行中”分组，每组最多 3 行 |
| 上下文占用 | Hover Card + Progress | 小号文字按钮，悬停显示进度 |
| 关系图、流程画布 | React Flow + dagre | 白色卡片、细描边；不用点阵背景；节点多时保持可读的最小缩放，可拖动 |
| 弹层 | Dialog、Popover、Dropdown Menu、Tooltip、Sonner | 只有弹层带投影 |

## 该做与不该做

| 该做 | 不该做 |
| --- | --- |
| 用圆点加文字表示状态 | 用彩色实心标签表示状态 |
| 头像颜色只从 8 种低饱和色里选 | 头像用和状态色接近的鲜艳颜色 |
| 用字号和留白区分层级 | 每个区块都套卡片和底色 |
| 一个区域一个深色主按钮 | 多个彩色按钮并列 |
| 只有运行中的那一项在动 | 多处同时流光、跳动 |
| 提示信息用一行次要文字 | 用彩色底块做提示 |
| 次要操作在悬停时出现 | 每行常驻一排图标按钮 |

## 实施

- Steve 2.0 前端已是 React 19 和 Tailwind v4，引入 shadcn/ui 不需要换技术栈；组件以源码形式复制进项目，主题变量集中在一份样式文件里。
- 先替换 token 和基础组件，再按视图迁移：对话、事项详情（工作记录）、会话模式优先。
- 验收：对比度检查；浅色和深色逐页截图；窄屏与触控；开启“减弱动态效果”后页面静止；包体增量记录。
